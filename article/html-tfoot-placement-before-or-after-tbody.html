HTML tfoot Placement: Before or After tbody

This article examines the structural role, parsing mechanics, and rendering behavior of the HTML <tfoot> element when placed before versus after the <tbody> tag. It covers the evolution of the HTML specification from HTML4 to the HTML Living Standard, how browser rendering engines process table layouts, and the implications for accessibility and Document Object Model (DOM) ordering.

Historical Context: HTML4 vs. HTML5

In HTML4 and XHTML, authors were required to place <tfoot> before <tbody> if a footer was used. The original intent was performance-oriented: tables were frequently used for large data sets, and streaming browsers could parse and render the header (<thead>) and footer (<tfoot>) before receiving and rendering potentially thousands of <tbody> rows. This allowed print engines and early browsers to determine pagination boundaries and render table summaries upfront.

HTML5 relaxed this restriction. The HTML specification was updated to permit <tfoot> to be placed either before or after <tbody>. In modern HTML (HTML Living Standard by WHATWG), placing <tfoot> after <tbody> is officially recommended to align with logical source order, though browsers continue to accept both placements for backward compatibility.

HTML Parser Behavior and DOM Construction

The HTML parser constructs the DOM tree sequentially based on tokens:

  • Placement Before <tbody>: When the parser encounters <tfoot> before <tbody>, the <tfoot> node becomes a child of <table> and precedes the <tbody> child node in the DOM tree.
  • Placement After <tbody>: When placed after, the <tfoot> node appears after <tbody> in the DOM tree.

The parser does not reorder the DOM nodes automatically. The node order directly reflects the order of the tags in the raw HTML markup.

Visual Rendering and Layout Processing

Regardless of whether <tfoot> appears before or after <tbody> in the markup or the DOM, CSS table formatting algorithms dictate its visual rendering:

  • Visual Order: The CSS Table Formatting Model specifies that elements with display: table-footer-group (the default user-agent style for <tfoot>) must be rendered visually at the bottom of the table, below any elements with display: table-row-group (<tbody>).
  • Print Rendering: In paged media (such as printing), browsers and print engines repeat headers and footers across page breaks. This behavior functions identically regardless of whether <tfoot> is placed before or after <tbody>.

Impact on Accessibility and User Experience

While visual rendering remains identical, the physical placement of <tfoot> significantly affects assistive technologies:

  • Linear Reading Order: Screen readers and accessibility APIs traverse tables primarily through the DOM tree. When <tfoot> is placed before <tbody>, screen readers operating in linear reading mode encounter summary or total values before the user has heard the data rows.
  • Semantic Confusion: Reading conclusions and totals before the data breaks cognitive expectations for non-visual users.

Placing <tfoot> after <tbody> ensures that the DOM tree matches the logical reading order, providing a cohesive experience across visual and non-visual user agents. Modern best practices dictate always placing <tfoot> after <tbody>.
