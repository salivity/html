Using the HTML Capture Attribute for Mobile Input

The HTML capture attribute enhances standard file upload controls on mobile devices by directly invoking native capture hardware—such as cameras and microphones—instead of forcing users to browse their existing media libraries. This article explains how the capture attribute works, how it interacts with the accept attribute, its supported values, and how mobile browsers interpret it to streamline mobile user experiences.

How the capture Attribute Works

In standard HTML forms, an <input type="file"> element typically opens a native file picker, prompting the user to select an existing file from storage or choose between several options (like taking a photo or selecting from a gallery).

When the capture attribute is added, compatible mobile operating systems (such as iOS and Android) bypass the default file-selection dialog. Instead, the browser immediately opens the device's native camera or audio recorder application. Once the user captures the photo, video, or audio clip, the data is automatically loaded into the form input, ready for submission or client-side processing.

Syntax and Device Targeting

The capture attribute must be paired with the accept attribute to inform the browser what type of media to request. The capture attribute itself accepts two main values to control which device sensor is engaged:

  • user: Specifies the front-facing camera or user-directed microphone (ideal for selfies or front-facing video).
  • environment: Specifies the outward-facing (rear) camera (ideal for photographing documents, barcodes, or scenery).

If the attribute is included without a specific value (e.g., just capture), the browser uses the operating system's default sensor for that media type.

Common Implementation Examples

1. Rear Camera Photo Capture

To immediately launch the rear-facing camera to capture a still photo:

<input type="file" accept="image/*" capture="environment">

2. Front Camera (Selfie) Capture

To launch the front-facing camera directly:

<input type="file" accept="image/*" capture="user">

3. Direct Video Recording

To launch the default video recording interface using the outward-facing camera:

<input type="file" accept="video/*" capture="environment">

4. Voice and Audio Recording

To open the system's native voice recorder:

<input type="file" accept="audio/*" capture>

Browser Support and Fallback Behavior

  • Mobile Browsers: Mobile Safari on iOS and Chrome/WebKit on Android provide widespread support for capture. If a device lacks the specified sensor (such as a device without a front-facing camera), the browser typically falls back to an available sensor or the default file selection dialog.
  • Desktop Browsers: Most desktop browsers ignore the capture attribute entirely. When encountered, the browser falls back gracefully to a standard file selection dialog, honoring only the accept attribute.

Key Considerations

  • User Choice: Using capture eliminates the option for the user to upload a pre-existing image from their gallery. It should only be used when real-time input is strictly required (such as ID verification, real-time damage reporting, or live document scanning).
  • Permissions: Unlike the WebRTC MediaDevices API (navigator.mediaDevices.getUserMedia), which requires complex JavaScript permission handling and canvas manipulation, the capture attribute relies entirely on the OS-level file picker permissions. This makes it a lightweight, privacy-friendly alternative that requires no custom camera UI.
