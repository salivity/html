HTML Autocorrect Attribute for Mobile Inputs

The autocorrect attribute in HTML is a mobile-focused configuration used to control whether a device's virtual keyboard automatically corrects spelling errors as a user types. This article explores the purpose of the autocorrect attribute, how it operates across mobile browsers, and best practices for implementing it effectively to optimize form usability and prevent input errors.

Purpose of the Attribute

Mobile operating systems rely heavily on software keyboards equipped with predictive text and automatic spelling correction algorithms. While helpful in everyday communication, automatic correction can disrupt data entry when users input non-dictionary terms such as usernames, email addresses, coupon codes, URLs, or proper nouns.

The autocorrect attribute allows developers to instruct the browser whether to permit or suppress this automated text manipulation on specific <input> and <textarea> elements.

Syntax and Values

The attribute accepts two primary values:

  • autocorrect="on": Explicitly enables automated correction. This is generally the default behavior for text-based input fields.
  • autocorrect="off": Disables automated correction, ensuring that the text entered by the user remains exactly as typed.
<!-- Disabling autocorrect on a custom username field -->
<input type="text" name="username" autocorrect="off">

<!-- Enabling autocorrect on a feedback textarea -->
<textarea name="feedback" autocorrect="on"></textarea>

When to Disable Autocorrect

Setting autocorrect="off" is recommended in scenarios where standard dictionary corrections are counterproductive:

  • Usernames and Handles: Usernames rarely conform to standard dictionary words and are often altered by mistake.
  • Email Addresses and Domain Names: Specialized syntax can trigger incorrect word substitutions.
  • Verification Codes, One-Time Passwords (OTPs), and Captchas: These inputs rely on exact character strings that should never be altered.
  • Physical Addresses and Postal Codes: Street names, abbreviations, and alphanumeric postal codes can be erroneously "corrected."
  • Search Fields for Technical Data: Part numbers, serial numbers, and programming queries often contain non-standard terminology.

When to Enable Autocorrect

Retaining or explicitly setting autocorrect="on" improves the user experience in long-form writing contexts, such as:

  • Blog comments and reviews
  • Customer support messages and inquiries
  • Notes, descriptions, and free-form text areas

Browser Support and Standards

Originally introduced by Apple for Mobile Safari in iOS, autocorrect was a non-standard, vendor-specific attribute. Due to its utility, it was subsequently adopted by Chromium-based mobile browsers (such as Google Chrome for Android).

While modern standards encourage the use of related attributes like spellcheck (standardized by the WHATWG HTML specification) and autocapitalize, mobile rendering engines continue to support autocorrect="off" to ensure complete control over predictive keyboard behaviors. For maximum compatibility on mobile inputs requiring raw text, developers typically combine these attributes:

<input 
  type="text" 
  name="account-id" 
  autocorrect="off" 
  autocapitalize="off" 
  spellcheck="false" 
  autocomplete="off">
