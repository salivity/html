HTML Tabindex 0 vs -1 vs Positive Values Explained

The HTML tabindex attribute controls whether an element can receive keyboard focus and dictates its order in sequential keyboard navigation. The primary difference between its values lies in how the browser handles user interaction: tabindex="0" inserts an element into the natural, source-code tab order; tabindex="-1" makes an element focusable programmatically via script while excluding it from the keyboard tab sequence; and positive tabindex values force a rigid, custom focus order that overrides the default flow of the document.

tabindex="0": Natural Sequential Focus

Setting tabindex="0" makes a non-focusable element focusable and places it into the natural tab order of the page based on its position in the HTML document.

Native interactive elements—such as <button>, <a>, <input>, and <select>—have built-in keyboard focusability by default. However, generic structural elements like <div> or <span> do not. Applying tabindex="0" enables keyboard users to navigate to these custom elements using the Tab key in the exact order they appear in the DOM.

Common use cases:

  • Custom interactive widgets, such as a custom dropdown or a <div> styled as a button.
  • Scrollable containers that users need to focus on to scroll using arrow keys.

tabindex="-1": Programmatic Focus Only

Setting tabindex="-1" removes an element from the sequential keyboard navigation flow while still allowing it to receive focus via JavaScript using the .focus() method, or through mouse clicks. A user pressing the Tab key will skip past this element entirely.

This attribute value is essential for managing focus dynamically in single-page applications and complex user interfaces.

Common use cases:

  • Modal dialogs that need immediate focus directed to their header or container upon opening.
  • Error message summaries at the top of a form that need programmatic focus after a failed submission.
  • Hidden or off-canvas navigation menus.
  • Elements that were previously interactive but are temporarily disabled from keyboard navigation.

Positive tabindex Values (tabindex="1", tabindex="2", etc.)

Any integer greater than zero creates a custom, prioritized tab sequence. When a user presses Tab, the browser navigates through all elements with positive tabindex values in ascending numerical order (1, then 2, then 3), before navigating to elements with tabindex="0" or default interactive elements.

Using positive tabindex values is widely considered an accessibility anti-pattern. Because positive values override the visual and structural layout of the DOM, they often cause the focus indicator to jump erratically across the screen. This creates a disorienting experience for keyboard and screen-reader users. Furthermore, positive values are difficult to maintain, as adding new focusable components requires re-indexing existing attributes across the codebase.

Summary Rule of Thumb

  • Use tabindex="0" to make non-interactive elements reachable via the Tab key according to the document source order.
  • Use tabindex="-1" for elements that should only receive focus dynamically through JavaScript.
  • Avoid positive values entirely; instead, structure your HTML so that the DOM sequence matches the intended logical navigation flow.
