Autonomous vs Customized Built-in Elements in HTML

Web Components allow developers to create reusable, encapsulated HTML tags, which are categorized into two distinct types: autonomous custom elements and customized built-in elements. The primary difference lies in their inheritance and syntax. Autonomous elements are completely new, standalone HTML tags that extend the generic HTMLElement interface, requiring developers to build functionality and accessibility from scratch. In contrast, customized built-in elements extend existing standard HTML elements (such as <button> or <input>), inheriting their native semantics, keyboard interactions, and accessibility features while adding customized behaviors.

Autonomous Custom Elements

Autonomous custom elements are brand-new HTML tags defined from the ground up. They do not inherit behaviors, styles, or semantics from any existing HTML tag other than the base HTMLElement class.

  • Inheritance: They inherit directly from HTMLElement.
  • Naming Convention: Their tag names must contain a hyphen (e.g., <user-profile>, <media-player>) to prevent collisions with future standard HTML elements.
  • Registration: Defined using customElements.define('element-name', ElementClass).
  • HTML Usage: Used directly as custom tags: 
    <user-profile></user-profile>
  • JavaScript Definition: 
    class UserProfile extends HTMLElement {
  constructor() {
    super();
    // Implementation details
  }
}
customElements.define('user-profile', UserProfile);

Because autonomous elements start with a blank slate, they do not carry default browser styling, native form participation, or built-in keyboard navigation. Developers are responsible for implementing appropriate ARIA roles, tabindex values, and event listeners.

Customized Built-in Elements

Customized built-in elements extend existing standard HTML elements, such as HTMLButtonElement, HTMLTableElement, or HTMLParagraphElement. They enhance standard elements with custom JavaScript functionality without losing the benefits of the underlying tag.

  • Inheritance: They inherit from specific HTML element interfaces (e.g., HTMLButtonElement).
  • Registration: Defined using customElements.define('element-name', ElementClass, { extends: 'base-tag' }). The extends option specifies which standard element is being customized.
  • HTML Usage: Written using the standard HTML tag combined with the is attribute: 
    <button is="expanding-button">Click Me</button>
  • JavaScript Definition: 
    class ExpandingButton extends HTMLButtonElement {
  constructor() {
    super();
    // Enhanced button behavior
  }
}
customElements.define('expanding-button', ExpandingButton, { extends: 'button' });

By extending native elements, customized built-in elements automatically retain native accessibility features, keyboard behaviors (such as pressing Enter or Space to trigger a button), and standard form-handling capabilities.

Key Differences Summary

  • Inherited Foundation: Autonomous elements extend HTMLElement; customized built-in elements extend specialized subclasses like HTMLAnchorElement or HTMLInputElement.
  • Syntax: Autonomous elements use new tags (<my-element>); customized built-in elements use native tags with the is attribute (<p is="my-paragraph">).
  • Accessibility and Semantics: Autonomous elements require manual accessibility setup via ARIA; customized built-in elements inherit all native accessibility features, screen-reader support, and focus management automatically.
  • Browser Compatibility: Autonomous custom elements are supported uniformly across all modern browsers. Customized built-in elements are supported in Chromium-based browsers and Firefox, but Apple's WebKit (Safari) has historically declined to implement them, often requiring a polyfill for cross-browser reliability.
