HTML Form Target Attribute Explained

The target attribute on an HTML <form> element defines where to display the server's response after the form is submitted. By controlling the browsing context—such as the current tab, a new tab, a parent window, or an embedded <iframe>—the target attribute dictates the navigation behavior triggered by form submission. Understanding this attribute helps developers deliver a smoother user experience, whether directing users to a fresh confirmation page or handling background file generations without redirecting the current page.

How the target Attribute Works

When a user submits a <form>, the browser sends data to the URL designated in the action attribute. By default, the browser replaces the current page with whatever the server returns. The target attribute overrides this behavior by instructing the browser to direct that response into a specific window, tab, or frame.

Standard Values

The target attribute accepts five primary values:

  • _self (Default): Loads the response in the same browsing context (current tab or window). If no target attribute is specified, the form automatically behaves as _self.
  • _blank: Loads the response in a new, unnamed browsing context, which is almost always a new browser tab (or window, depending on user settings).
  • _parent: Loads the response into the parent frame of the current context. If the form is not inside a nested frame, this acts the same as _self.
  • _top: Loads the response into the top-level browsing context, breaking out of any nested <iframe> elements to occupy the entire window.
  • [framename] (Custom Name): Loads the response into a specifically named browsing context, such as a window opened with a specific name or an <iframe> that has a matching name attribute.

Practical Use Cases

  1. Generating and Downloading Documents: When submitting a form to generate a file (such as an invoice or PDF report), setting target="_blank" prevents the user's current workflow from being interrupted, keeping the original form view intact.
  2. Submissions via Iframes: Forms can target a hidden or visible <iframe> by matching the frame's name attribute (e.g., <form action="/upload" target="upload-frame">). This pattern allows responses to process inside the frame without refreshing the main page.
  3. Leaving Nested Views: If a form is displayed inside an embedded frame or widget, setting target="_top" ensures that post-submission navigation takes over the full browser window rather than trapping the destination page inside the frame.

Overriding the Form Target

HTML5 allows developers to override the <form> element's target attribute on a per-button basis using the formtarget attribute on an <input type="submit"> or <button type="submit">. This allows a single form to have multiple submission pathways—such as a "Save Draft" button that uses the default target and a "Preview" button that uses formtarget="_blank".
