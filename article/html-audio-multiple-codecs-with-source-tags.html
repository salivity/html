HTML Audio Multiple Codecs with Source Tags

The HTML <audio> element achieves broad cross-browser compatibility by nesting multiple <source> tags, allowing developers to serve the same audio track in different formats such as MP3, OGG, and AAC. Because web browsers vary in their native support for specific audio codecs due to licensing or technical preferences, this nested approach allows the browser to evaluate a list of file alternatives sequentially and automatically play the first format it natively supports.

How Nested <source> Resolution Works

When an <audio> tag is rendered without a single src attribute in the primary tag, the browser scans its child elements. Inside, developers place multiple <source> tags, each pointing to a distinct file via the src attribute and defining the audio format via the type attribute.

The browser parses these child <source> tags from top to bottom:

  1. It checks the MIME type and codec specified in the type attribute of the first <source> element.
  2. If the browser determines it can decode and play that format, it downloads that file and immediately stops evaluating subsequent <source> elements.
  3. If the browser cannot decode the format, it skips that tag and tests the next <source> tag in the sequence.
  4. If none of the provided sources are supported, the browser displays any fallback text or HTML placed before the closing </audio> tag.

Implementation Example

The standard implementation lists modern, highly compressed formats first, followed by widely compatible legacy fallbacks:

<audio controls>
  <source src="sound.opus" type="audio/ogg; codecs=opus">
  <source src="sound.ogg" type="audio/ogg; codecs=vorbis">
  <source src="sound.mp3" type="audio/mpeg">
  <p>Your browser does not support the audio element.</p>
</audio>

In this scenario, a modern browser that supports Opus will play sound.opus. An older browser lacking Opus support will skip to the Vorbis-encoded OGG file, or ultimately fall back to the universally supported MP3 format.

The Role of the type Attribute

Specifying the type attribute is essential for optimal network performance. If the type attribute is omitted, the browser cannot determine whether it supports the audio stream based on HTML alone. As a result, it must send an HTTP request to fetch the file's headers or initial data chunks from the server to inspect the container and codec information. Explicitly declaring the MIME type and codec parameters allows the browser to reject unsupported formats instantly without initiating unnecessary network requests.
