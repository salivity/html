What Is the formnovalidate Attribute in HTML?

The formnovalidate attribute is a boolean attribute applied to submit buttons to bypass standard HTML5 form validation. This article explains the exact purpose of the formnovalidate attribute, demonstrates how it works with practical code examples, highlights common use cases such as saving drafts, and outlines the key differences between formnovalidate and the form-level novalidate attribute.

Purpose of formnovalidate

When an HTML form contains input fields with validation constraints—such as required, type="email", pattern, or minlength—the browser automatically checks these rules before submitting the data. If any field fails validation, the browser blocks submission and displays an error message.

Adding the formnovalidate attribute to a <button type="submit"> or <input type="submit"> instructs the browser to skip these built-in validation checks when that specific button is clicked. The form submits immediately, even if required fields are empty or formatted incorrectly.

Common Use Cases

The most frequent scenarios for using formnovalidate include:

  • Save as Draft: Allowing users to save incomplete forms to finish later without being blocked by required field validations.
  • Multi-Step Forms: Navigating backward to previous steps using a submit action without triggering validation on uncompleted fields on the current step.
  • Cancel Actions: Submitting a form specifically to process an exit or cancellation request on the server.

Example Implementation

Here is how formnovalidate is implemented in standard HTML:

<form action="/submit-survey" method="post">
  <label for="username">Name (Required):</label>
  <input type="text" id="username" name="username" required>

  <label for="email">Email (Required):</label>
  <input type="email" id="email" name="email" required>

  <!-- Standard submission: triggers browser validation -->
  <button type="submit">Submit Final Survey</button>

  <!-- Draft submission: bypasses browser validation -->
  <button type="submit" name="action" value="draft" formnovalidate>Save Draft</button>
</form>

In this example, clicking "Submit Final Survey" will trigger browser validation, prompting the user if either input is invalid. Clicking "Save Draft" bypasses validation entirely, sending whatever data currently exists to /submit-survey.

formnovalidate vs. novalidate

While both attributes disable HTML5 client-side validation, their scope differs:

  • novalidate is placed on the <form> element. It permanently disables validation for all submission triggers inside that form.
  • formnovalidate is placed on individual submit elements (<button> or <input>). It provides granular control, enabling validation for standard submissions while disabling it only when specific alternate buttons are pressed.

Security Note

Client-side attributes like formnovalidate only control browser UI behavior. They do not eliminate the necessity of server-side data validation, as malicious users or alternative HTTP clients can bypass client constraints at any time.
