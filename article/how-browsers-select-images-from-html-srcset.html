How Browsers Select Images from HTML srcset

The HTML srcset attribute enables responsive image loading by providing browsers with a list of image candidates rather than a single source file. Instead of forcing a static asset on every device, the browser dynamically evaluates device pixel ratio, layout dimensions, network speed, and user preferences to pick the most efficient image file. This process relies on two distinct mechanisms: pixel density descriptors and width descriptors paired with the sizes attribute.

Pixel Density Descriptors (x)

When using pixel density descriptors, image sources are defined using an x value (e.g., 1x, 2x, 3x). This method is typically used for fixed-width images that only need to adapt to different screen resolutions.

The browser determines which image to load through a direct calculation:

  1. It queries the device's Device Pixel Ratio (DPR), which indicates how many physical pixels make up a single CSS pixel.
  2. It matches the device DPR to the closest corresponding x value in the srcset list.
  3. If a device has a DPR of 2 (such as Apple's Retina displays), the browser selects the image marked with 2x. If no exact match exists, the browser selects the closest higher resolution candidate to maintain visual sharpness.

Width Descriptors (w) and the sizes Attribute

For responsive layouts where image display sizes change depending on screen width, width descriptors (w) are used. Unlike pixel density descriptors, width descriptors indicate the actual pixel width of each image file (e.g., image-800.jpg 800w).

To determine the correct source, the browser follows a four-step evaluation:

  1. Evaluates Media Conditions in sizes: The browser reads the sizes attribute from left to right to find the first matching media query, identifying the target display slot width in CSS pixels (or viewport width units). If omitted, sizes defaults to 100vw.
  2. Calculates Required Physical Pixels: The browser multiplies the resolved display slot width by the device's DPR. For instance, an image displayed at 400 CSS pixels on a device with a 2x DPR requires an 800-pixel-wide image.
  3. Compares Candidates: The browser scans the w descriptors in the srcset list against the calculated physical pixel requirement.
  4. Selects the Optimal File: The browser chooses the smallest image whose width is equal to or greater than the required physical pixel count, preventing unnecessary bandwidth consumption while avoiding blurry scaling.

Browser Heuristics and Overrides

While the mathematical formula acts as the baseline, the HTML specification deliberately gives browsers flexibility to apply performance heuristics:

  • Caching: If a browser has already downloaded a high-resolution version of an image (e.g., on a desktop monitor before resizing the window), it may continue using the cached larger version rather than making a new network request for a smaller file.
  • Network Conditions and Data Preferences: If the user has enabled "Data Saver" mode or is on a slow, metered cellular connection, the browser may deliberately choose a lower-resolution file to improve load times and conserve data.
