CDATA Sections in XHTML vs HTML5 Explained

This article explores the concept of CDATA (Character Data) sections, explaining their technical purpose in markup languages and examining the stark differences in how they are parsed and utilized in XHTML versus modern HTML5. By understanding how parsers treat CDATA blocks, developers can avoid common syntax pitfalls when handling inline scripts, styles, and embedded foreign content.

What is a CDATA Section?

A CDATA section is a block of text in markup languages—primarily XML—that instructs the parser to interpret all enclosed characters strictly as character data, not as markup. Defined with the syntax <![CDATA[ ... ]]>, it eliminates the need to manually escape reserved characters such as the ampersand (&), less-than sign (<), and greater-than sign (>). This makes CDATA particularly useful for embedding code snippets, mathematical formulas, or scripts directly within a document.

CDATA in XHTML

XHTML is an application of XML. Because it adheres to strict XML parsing rules, an XHTML processor treats elements like <script> and <style> as containing regular markup unless explicitly instructed otherwise. If a script contains operators like < or &&, an XML parser will encounter a fatal syntax error.

To prevent these parsing failures, developers in XHTML wrap the contents of script and style blocks inside CDATA sections:

<script type="text/javascript">
/* <![CDATA[ */
    if (x < 10 && y > 20) {
        // Code executes without XML parser errors
    }
/* ]]> */
</script>

In this context, the CDATA block informs the XML parser to ignore markup syntax inside the element. JavaScript comments (/* ... */ or //) are typically used to wrap the CDATA tags so that the JavaScript engine does not interpret the XML delimiter itself as invalid JavaScript syntax.

CDATA in HTML5

HTML5 departs from XML parsing rules and uses its own dedicated parsing algorithm. The handling of CDATA in HTML5 depends entirely on the context of the document:

1. Standard HTML Elements

In standard HTML5 elements (such as <div>, <p>, or inline <script> and <style>), CDATA sections are not recognized as XML character blocks. Instead, the HTML5 parser treats the <![CDATA[ syntax as a "bogus comment." It converts the block into an HTML comment or raw text, effectively breaking script execution or rendering unexpected text on the screen. Because HTML5 natively treats <script> and <style> as raw text elements, characters like < and & do not need CDATA encapsulation.

2. Foreign Content (SVG and MathML)

HTML5 allows inline SVG and MathML, which are classified as "foreign content." Within <svg> or <math> namespaces, the HTML5 parser temporarily adopts XML-like rules. Here, CDATA sections are fully supported and recognized, allowing unescaped text or scripts to be embedded safely inside vector graphics or mathematical markup.

3. XHTML5 (HTML5 Served as XML)

If an HTML5 document is served with an XML MIME type (such as application/xhtml+xml), the browser invokes a true XML parser rather than the HTML5 parser. In this scenario, CDATA sections function precisely as they do in traditional XML and XHTML.
