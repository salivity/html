Restrict Microphone Access in HTML Iframes

Modern web browsers enforce strict security boundaries to prevent unauthorized audio recording, requiring embedded documents to receive explicit permission before accessing device microphones. This access is governed by the Permissions Policy HTTP header and the iframe allow attribute. Together, these mechanisms create an inheritance-based permission model where top-level parent pages define access ceilings, and embedded iframes receive only the specific capabilities granted to them.

Default Browser Behavior

Web browsers treat same-origin and cross-origin iframes differently by default:

  • Same-origin iframes inherit the parent frame's permission policy. If the top-level document has access to the microphone, an embedded page from the same origin can request microphone access without explicit delegation, provided the parent document has not explicitly blocked it.
  • Cross-origin iframes are blocked from using the microphone by default. Even if a user manually approves a prompt, the browser rejects API calls like navigator.mediaDevices.getUserMedia({ audio: true }) inside a third-party iframe unless the parent document explicitly grants permission.

Restricting Access Using the allow Attribute

The allow attribute is applied directly to an <iframe> tag in HTML. It acts as an inline policy defining allowed features for that specific frame.

To completely prevent an iframe from accessing the microphone, omit the microphone token from the allow attribute:

<!-- Cross-origin iframe: microphone access is blocked by default -->
<iframe src="https://example.com/embed"></iframe>

To explicitly allow or restrict access to specific origins, define the feature along with an allowlist:

<!-- Explicitly allows microphone only for a trusted cross-origin domain -->
<iframe src="https://trusted.com" allow="microphone https://trusted.com"></iframe>

<!-- Explicitly disables microphone access, even for same-origin frames -->
<iframe src="/internal-page.html" allow="microphone 'none'"></iframe>

Restricting Access Using the Permissions-Policy Header

The Permissions-Policy HTTP response header allows server administrators to enforce sitewide rules for top-level pages and all nested content.

To disable microphone access entirely across the parent page and all embedded iframes, set the feature directive to an empty list:

Permissions-Policy: microphone=()

To restrict microphone access exclusively to the top-level origin, use self:

Permissions-Policy: microphone=(self)

To grant permission to the top-level origin and a specific external origin while blocking all others:

Permissions-Policy: microphone=(self "https://trusted.com")

Inheritance and Policy Precedence

Permissions Policy directives operate under a strict downward inheritance hierarchy:

  1. The Header Sets the Upper Bound: An iframe can never have more permissions than the parent page allows via its HTTP headers. If the parent page serves Permissions-Policy: microphone=(), adding allow="microphone" to an iframe will have no effect; access remains blocked.
  2. The allow Attribute Delegates Access: If the parent document allows the feature via HTTP headers, it must still use the allow attribute to pass that permission down to a cross-origin iframe.
  3. Nested Hierarchy: If an iframe embeds a secondary iframe (nested frames), the permission must be explicitly delegated at every level of the embed chain. If any intermediary iframe omits permission, all child iframes underneath it lose access.
