How the HTML bdi Tag Isolates Bidirectional Text

The HTML <bdi> (Bidirectional Isolate) tag is an inline element designed to handle user-generated text when the directional flow—left-to-right (LTR) or right-to-left (RTL)—is unpredictable. By instructing the browser to isolate the enclosed content, <bdi> determines the reading direction based strictly on the text inside the tag, preventing directional spillover that could otherwise scramble adjacent punctuation, numbers, or surrounding layout.

The Problem with Dynamic Text Flow

Web browsers rely on the Unicode Bidirectional Algorithm (UBA) to determine how characters are displayed on a screen. Languages like English and Spanish are written LTR, while languages such as Arabic and Hebrew are written RTL.

When dynamic text is injected into an HTML document—such as a username, a product title, or a comment—the application often cannot anticipate the language being used. If an RTL string contains numbers, neutral punctuation (like exclamation points or brackets), or sits next to LTR text, the UBA attempts to resolve the directional context across boundary lines. This often results in misplaced punctuation, reversed numbering, or fragmented sentences.

How <bdi> Isolates Content

The <bdi> element acts as a directional boundary. Under the hood, it applies the CSS property unicode-bidi: isolate; by default.

When a browser encounters a <bdi> tag, it executes two critical behaviors:

  1. Internal Direction Resolution: The browser evaluates the contents of the <bdi> tag independently. It inspects the first strongly typed character inside the element (either LTR or RTL) to establish the internal direction. If the first strong character is Arabic, the interior text renders RTL; if it is Latin, it renders LTR.
  2. External Isolation: The browser prevents the directional properties of the enclosed content from affecting the surrounding text. To the text outside the element, the <bdi> block is treated as an independent, neutral object. Trailing punctuation, numbers, or adjacent text outside the tag will not be pulled into the internal directional context of the dynamic content.

<bdi> vs. <bdo> and dir="auto"

Understanding <bdi> requires distinguishing it from other bidirectional controls in HTML:

  • <bdo> (Bidirectional Override): Forces all enclosed text into a explicitly stated direction via the dir attribute (e.g., <bdo dir="rtl">), ignoring the natural directionality of the characters. It is used when text must be displayed backward or in an unnatural order, whereas <bdi> respects natural language rules while isolating them.
  • dir="auto": An attribute that inspects the first strong character to set the direction of a container. While effective on block-level containers, using dir="auto" on inline spans does not always provide the complete directional isolation that the <bdi> tag guarantees against adjacent inline tokens.

Common Implementation

A classic failure occurs in ranked lists or activity feeds. Consider a layout displaying a user's name followed by a count:

<ul>
  <li>User <bdi>Sarah</bdi>: 5 points</li>
  <li>User <bdi>إكرام</bdi>: 3 points</li>
</ul>

Without <bdi>, the RTL characters in the second username would cause the colon and number 3 to flip to the opposite side of the name, rendering as 3 :User إكرام points. By wrapping the user-generated string in <bdi>, the browser treats the Arabic name as an isolated component, ensuring that the surrounding English structure (User [name]: X points) maintains its correct LTR visual flow regardless of the script inside the tag.
