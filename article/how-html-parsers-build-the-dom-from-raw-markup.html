How HTML Parsers Build the DOM from Raw Markup

When a browser receives an HTML document over the network, it cannot directly render the raw bytes of text. Instead, an HTML parser processes the markup through a multi-stage pipeline—converting raw bytes into characters, tokenizing those characters into distinct semantic units, and executing tree-construction algorithms to build the Document Object Model (DOM). This article explains the technical stages an HTML parser executes to transform a stream of text into a living, interactive node tree.

1. Byte Stream Decoding

The process begins with the network layer transferring raw bytes (typically via HTTP) to the browser engine. The parser's first task is character decoding. Using the character encoding specified in the HTTP Content-Type header (such as charset=utf-8), a <meta charset> tag, or heuristic detection, the parser translates the raw bytes into a stream of individual Unicode characters.

2. Tokenization (Lexical Analysis)

Once the characters are decoded, the parser passes them through a state-machine-driven tokenizer. The tokenizer breaks the character stream into meaningful tokens:

  • DOCTYPE tokens: Define the document standard.
  • Start tag tokens: Identify opening tags (e.g., <div>, <p>) and extract their attributes.
  • End tag tokens: Identify closing tags (e.g., </div>, </p>).
  • Character tokens: Represent text content found inside elements.
  • Comment tokens: Represent HTML comments.
  • End-of-File (EOF) tokens: Signal the end of the document.

The tokenizer operates as a state machine, transitioning between states such as "Data state," "Tag open state," "Tag name state," and "Attribute name state" based on each incoming character.

3. Tree Construction (Syntactic Analysis)

As tokens are emitted by the tokenizer, the tree construction stage processes them immediately. This process relies on a "stack of open elements" to maintain structural hierarchy:

  1. Node Creation: When a start tag token arrives, the parser instantiates a corresponding DOM Element node.
  2. Parent-Child Linking: The new node is attached as a child to the node currently at the top of the stack of open elements.
  3. Stack Management:
    • Non-void start tags push the new node onto the stack, making it the current insertion target for subsequent tokens.
    • Character tokens generate Text nodes that append directly to the current top of the stack.
    • Matching end tag tokens pop the corresponding element off the stack, returning context to the parent node.
    • Void elements (like <img>, <br>, or <input>) create a node, attach it to the tree, but are never pushed to the stack.

4. Handling Malformed HTML

Unlike XML parsers, which halt on syntax errors, HTML parsers follow strict error-recovery algorithms defined by the HTML5 specification. If an author forgets a closing tag (such as omitting </li> or </p>), the parser determines contextually where the tag should logically close, automatically pops the element from the stack, and continues constructing the tree without failing.

5. Script Execution and Parser Blocking

HTML parsing is inherently synchronous. When the tokenizer encounters a <script> tag without async or defer attributes, tree construction pauses. The browser must fetch, compile, and execute the JavaScript before resuming parsing, because scripts can call methods like document.write(), which inject new raw markup directly into the tokenizer's active input stream.

Once the tokenizer hits the EOF token, the parser pops any remaining nodes from the stack, marks the document as interactive, and fires the DOMContentLoaded event, signifying that the DOM tree is complete.
