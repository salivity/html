What FID and INP Measure in Web Applications

First Input Delay (FID) and Interaction to Next Paint (INP) are Core Web Vitals metrics designed to quantify the responsiveness of interactive HTML applications. While FID measures the delay between a user's very first interaction and the browser's ability to begin processing it, INP provides a comprehensive evaluation of user experience by tracking the total latency of all interactions throughout the entire page lifecycle until visual feedback appears on the screen.

First Input Delay (FID)

First Input Delay (FID) measures the time—in milliseconds—from when a user first interacts with an application (such as clicking a button, tapping a link, or using a key press) to the moment the browser's main thread becomes free enough to begin executing the associated event handlers.

FID focuses exclusively on the input delay phase of the first interaction. It does not measure the time it takes to execute JavaScript callbacks, nor does it track how long it takes to update the user interface. Because modern web applications often load large JavaScript bundles during initialization, the main thread can be blocked by heavy parsing and compilation tasks. FID specifically measures that initial unresponsiveness when a user attempts to interact with an ostensibly loaded page that cannot yet respond.

Interaction to Next Paint (INP)

Interaction to Next Paint (INP) is the successor to FID, measuring the overall responsiveness of a page by observing the latency of all qualifying interactions throughout a user’s entire session. The final INP score reflects the longest interaction observed, with allowances for outliers on highly interactive pages.

Unlike FID, which only measures the queue delay before processing begins, INP captures the complete interaction lifecycle, comprising three distinct phases:

  1. Input Delay: The time waiting for background tasks or previous events on the main thread to complete before the browser can start processing the input.
  2. Processing Duration: The total time required to execute the developer-written JavaScript event handlers triggered by the interaction.
  3. Presentation Delay: The time required for the browser to recalculate styles, recalculate layout, and paint the next frame to deliver visual feedback to the user.

An interaction is complete only when the browser renders a new visual frame confirming the action has occurred, such as opening a menu, showing an active state, or rendering updated data.

Key Differences in Interactive HTML Applications

The critical distinction between FID and INP lies in scope and depth:

  • Session Lifecycle: FID measures only the user's initial interaction, ignoring all subsequent actions. INP evaluates all user interactions across the entire session to ensure continued responsiveness.
  • Component of Interaction: FID measures only the waiting period before execution begins (input delay). INP measures the entire journey from physical input to visual confirmation (input delay, processing time, and paint delay).
  • Application Impact: In complex Single-Page Applications (SPAs) or rich HTML interfaces, interactions frequently occur long after initial page load. While an application might have a fast FID during initialization, unoptimized DOM updates or heavy runtime scripts can cause severe lag during ongoing usage. INP captures these runtime performance bottlenecks, making it a significantly more accurate metric for real-world interactive performance.
