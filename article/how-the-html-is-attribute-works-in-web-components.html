      How the HTML is Attribute Works in Web Components

      The is attribute enables standard HTML elements to transform into "customized built-in elements," bridging the gap between native browser tags and modern Web Components. By adding this attribute to standard elements like <button>, <input>, or <ul>, developers can inherit all the built-in accessibility, semantic behavior, and keyboard navigation of native elements while augmenting them with custom JavaScript logic, methods, and lifecycle callbacks.

      Autonomous vs. Customized Built-in Elements

      The Web Components specification defines two primary types of custom elements:

      1. Autonomous Custom Elements: Brand-new HTML tags (such as <my-card>) that inherit directly from HTMLElement. They start with no default styling, semantics, or behavior.
      2. Customized Built-in Elements: Standard HTML elements extended with custom behavior using the is attribute (such as <button is="fancy-button">). These retain the browser's default handling for the underlying native element.

      How the is Attribute Functions

      When you use the is attribute, the browser renders the host element as the native tag while attaching an extended JavaScript class to manage its behavior.

      Implementing a customized built-in element requires three main steps:

      1. Extending the Specific Native Interface

      Instead of extending the base HTMLElement, the custom class must extend the specific DOM interface of the element being customized. For example, extending a button requires HTMLButtonElement:

      class AutoSubmitButton extends HTMLButtonElement {
  connectedCallback() {
    this.addEventListener('click', () => {
      console.log('Custom button action executed.');
    });
  }
}

      2. Registering with the extends Option

      When registering the custom component via the customElements.define() method, pass a third parameter: an options object specifying which native tag the component extends.

      customElements.define('auto-submit-button', AutoSubmitButton, { extends: 'button' });

      The browser uses this registration mapping to know that any <button> with is="auto-submit-button" should be bound to the AutoSubmitButton class.

      3. Using the Attribute in Markup

      Once defined, apply the custom logic by assigning the registered name to the is attribute on the corresponding native element:

      <button is="auto-submit-button">Submit Order</button>

      You can also instantiate the element dynamically in JavaScript using document.createElement:

      const btn = document.createElement('button', { is: 'auto-submit-button' });

      Key Benefits

      • Built-in Accessibility: Native tags come with complex ARIA roles, focus management, and screen-reader support that are difficult to replicate from scratch in autonomous elements.
      • Form Participation: Elements like <input> and <button> naturally interact with parent <form> elements (handling validation, submission, and reset events) without requiring complex Form-Associated Custom Element APIs.
      • Progressive Enhancement: If JavaScript fails to load or custom elements are disabled, the element still renders and functions as a standard native tag.

      Browser Compatibility Considerations

      While Chromium-based browsers (Chrome, Edge) and Firefox fully support the is attribute and customized built-in elements, Apple's WebKit team (Safari) has declined to implement the feature. When targeting environments that include Safari, a polyfill is required to ensure the is attribute consistently attaches custom element behavior across all platforms.
