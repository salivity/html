Understanding the iframe credentialless Attribute

The credentialless attribute on HTML <iframe> elements provides a secure mechanism for embedding third-party content inside cross-origin isolated web pages. By instructing the browser to fetch the embedded document and its subresources without ambient credentials—such as cookies, HTTP authentication, and client certificates—it allows developers to embed external content without requiring the external server to explicitly configure Cross-Origin Resource Policy (CORP) headers. This article covers the purpose of the credentialless attribute, the cross-origin isolation issues it solves, and how it behaves in modern browsers.

The Problem: Cross-Origin Embedder Policy (COEP)

To mitigate side-channel attacks like Spectre and gain access to high-performance browser APIs like SharedArrayBuffer or performance.measureUserAgentSpecificMemory(), websites must enable cross-origin isolation. This state is activated using two HTTP response headers:

Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

Historically, require-corp meant that every external resource, including iframes, had to serve a Cross-Origin-Resource-Policy (CORP) header explicitly authorizing the embedding site. This created a significant bottleneck: if a developer wanted to embed a third-party widget, advertisement, or payment gateway that did not deploy CORP headers, cross-origin isolation would fail or the iframe would be blocked entirely.

What credentialless Does

The credentialless attribute removes the CORP requirement by stripping standard authentication contexts from the embed.

When an <iframe> has the credentialless attribute applied:

  1. No Credentials Sent: The initial network request for the iframe's src is sent without cookies, client certificates, or HTTP authorization headers.
  2. Partitioned/Empty Storage: The embedded document is loaded inside a fresh, transient environment. It does not have access to the standard cookie jar, localStorage, or other persistent storage associated with its origin.
  3. Subresource Inheritance: All subresources fetched by the embedded iframe also inherit the credentialless constraint, preventing nested credential leaks.
  4. Bypasses CORP Validation: Because the document cannot leak sensitive, user-specific data through authenticated requests, the parent page's require-corp policy allows the resource to load without an explicit CORP response header.

Syntax and Implementation

Using the attribute requires adding the boolean credentialless attribute directly to the iframe element:

<iframe 
  src="https://example.com/embed" 
  credentialless 
  title="Third-party content">
</iframe>

You can also control or inspect it via JavaScript:

const iframe = document.createElement('iframe');
iframe.credentialless = true;
iframe.src = 'https://example.com/embed';
document.body.appendChild(iframe);

Key Use Cases

  • Ad Tech and Analytics: Serving third-party creative assets or tracking pixels without requiring ad networks to overhaul their HTTP response headers for COEP compliance.
  • User-Generated Content: Displaying untrusted or external documents within web-based IDEs, editors, or gaming platforms that require SharedArrayBuffer.
  • Embedded Media and Widgets: Integrating social media widgets, videos, or external tools on pages requiring advanced threading or high-resolution timers.

By decoupling the requirement for explicit CORP headers from cross-origin isolation, the credentialless attribute eliminates integration friction while preserving origin-based security boundaries.
