How Element.matches() Checks CSS Selectors

The Element.matches() method in JavaScript checks whether an HTML element satisfies a specified CSS selector string, returning true if it does and false if it does not. This article explains the internal mechanism of the matches() method, its syntax, how it processes complex selectors and combinators, and common error conditions.

Syntax and Basic Operation

The syntax for the method is straightforward:

const isMatch = element.matches(selectorString);

The method takes a single parameter: a string representing a valid CSS selector. Instead of querying the entire document like document.querySelector(), matches() only evaluates the specific element it is called on.

The Matching Mechanism

When element.matches() is invoked, the browser executes the following steps:

  1. Selector Parsing: The browser's CSS engine parses the provided selectorString. If the string contains an invalid CSS selector syntax, the engine aborts the operation and throws a SyntaxError (a DOMException).
  2. Element Context Testing: The browser tests the target element against the criteria defined by the selector. This includes checking:
    • Tag names (e.g., 'div', 'button')
    • Classes and IDs (e.g., '.card', '#main-nav')
    • Attributes and attribute values (e.g., '[type="checkbox"]', '[disabled]')
    • Pseudo-classes (e.g., ':hover', ':first-child', ':checked')
  3. Hierarchy and Combinator Evaluation: If the selector includes combinators (descendant, child >, adjacent sibling +, or general sibling ~), the browser checks the element's position relative to its neighboring and ancestor nodes in the DOM tree. For example, calling el.matches('.container > .item') verifies that el has the class .item and that its direct parent element has the class .container.
  4. Boolean Output: If the element meets all the criteria of the selector, the method returns true. If any criterion fails, it returns false.

Handling Contextual Combinators

matches() is not limited to simple classes or IDs. It can resolve complex relationships:

  • Ancestry: element.matches('body.dark-mode .card') checks if element has the class .card while being nested anywhere inside a <body class="dark-mode">.
  • State: element.matches(':disabled') determines if the form control is currently inactive.

The element does not need to be attached to the active document to be tested, provided the selector does not rely on parent nodes that are absent. However, selectors that require document context (like :root or certain structural pseudo-classes) will return false if the element is disconnected from the DOM.

Primary Use Cases

  • Event Delegation: Determining whether the event.target matches a specific target, avoiding the need to attach listeners to multiple individual elements: 
    document.addEventListener('click', (event) => {
  if (event.target.matches('.delete-btn, .delete-btn *')) {
    // Handle deletion
  }
});
  • Conditional Logic: Performing quick state or type checks before applying manipulations, without the performance overhead of traversing the DOM with query selectors.
