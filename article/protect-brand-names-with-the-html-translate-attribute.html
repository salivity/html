Protect Brand Names with the HTML Translate Attribute

This article explains the purpose and implementation of the HTML translate attribute, focusing on how it prevents automated translation tools from distorting proprietary brand names and trademarks. You will learn why automated translation poses a risk to brand integrity, how the attribute functions within the Document Object Model (DOM), and the best practices for implementing it in your web projects.

The Problem with Automated Translation

Modern web browsers and search engines offer built-in machine translation tools that automatically detect and translate page content into the user's preferred language. While this improves accessibility, automated translation algorithms cannot reliably distinguish between common vocabulary words and proper nouns, such as brand names, trademarks, or proprietary product lines.

Without explicit instructions, a brand name like "Apple" might be translated literally into the local word for the fruit, "Target" into a word for an aim or mark, or "Subway" into an underground railway. These literal translations dilute brand identity, confuse users, and can undermine trademark consistency across international markets.

The Purpose of the translate Attribute

The translate attribute is a standard HTML5 global attribute designed to control whether an element's text content and the values of its translatable attributes should be translated by automated localization tools.

When protecting brand names, its primary purpose is to establish explicit translation boundaries. Setting the attribute to no directs user-agent translation features, third-party translation widgets, and search engine crawlers to leave the specified text in its original language.

How to Implement translate="no"

The attribute accepts two keyword values: yes and no. To protect a brand name, apply translate="no" to the element containing the proprietary term.

<!-- Protecting an inline brand name -->
<p>Welcome to the official store for <span translate="no">Greenlight</span> software.</p>

<!-- Protecting a logo or header element -->
<h1 translate="no">SoundWave Audio</h1>

Because translate is an enumerated global attribute, its value is inherited by child elements. If an entire section—such as a navigation bar or product catalog containing model numbers and brand assets—needs to remain untranslated, you can apply the attribute to the parent container:

<nav translate="no">
  <ul>
    <li>CloudScale Engine</li>
    <li>DataForge Analytics</li>
    <li>NetShield Security</li>
  </ul>
</nav>

Any child element within that container will inherit translate="no" unless explicitly overridden with translate="yes".

Legacy Support and Fallbacks

Before the translate attribute became a standard part of the HTML specification, many translation engines relied on proprietary class names. Most notably, Google Translate used the class="notranslate" convention.

Modern translation engines support the standardized translate="no" attribute. However, for maximum compatibility with older enterprise translation tools or legacy translation scripts, developers frequently combine both approaches:

<span translate="no" class="notranslate">BrandName</span>

Best Practices

  • Apply surgically: Restrict translate="no" only to proper nouns, trademarks, model numbers, and phrases that lose legal or commercial meaning when translated. Avoid applying it to full sentences containing descriptive text.
  • Protect metadata: The attribute also prevents the translation of attributes within the element, such as title, alt, and placeholder. Ensure that necessary descriptive accessibility text, such as complex alt descriptions, is separated from untranslatable brand terms where possible.
  • Maintain semantic structure: Use inline semantic elements like <span> or <strong translate="no"> rather than generic <div> containers when isolating brand terms within body text to avoid breaking document flow.
