Multiple Base Tags in HTML Head: What Happens?

When multiple <base> elements are included in an HTML document's <head>, modern web browsers adhere to the standard HTML specification by utilizing only the first <base> element and ignoring all subsequent ones. Because the <base> tag establishes the document's base URL and default target for all relative links, introducing duplicates violates HTML standards, creates invalid markup, and can lead to unexpected path resolution errors across your site.

The HTML Specification Rule

According to the WHATWG HTML Living Standard and W3C specifications, an HTML document must contain no more than one <base> element. When a browser parses an HTML document containing more than one <base> element, it processes them using the following rules:

  • The href attribute: The browser sets the document's base URL using the href value of the first <base> element that contains an href attribute. Any later <base> elements with an href attribute are completely ignored.
  • The target attribute: The default browsing context (such as _blank or _self) is determined by the first <base> element in tree order that has a target attribute. Subsequent target attributes in later <base> tags are ignored.

If the first <base> tag contains only an href attribute and a second <base> tag contains a target attribute, the browser will use the href from the first and the target from the second. However, if both tags define an href, only the first takes effect.

Example Scenario

Consider the following <head> block:

<head>
  <base href="https://example.com/primary/" target="_self">
  <base href="https://example.com/secondary/" target="_blank">
</head>

In this case:

  1. The base URL becomes https://example.com/primary/.
  2. The default link target becomes _self.
  3. The second <base> tag is entirely disregarded by the browser.

Any relative link, such as <a href="about.html">, resolves to https://example.com/primary/about.html and opens in the current tab.

Risks and Side Effects

Including duplicate <base> tags introduces several practical problems:

  • HTML Validation Errors: The W3C markup validator will flag any document with more than one <base> element as invalid HTML.
  • Unexpected Link Resolution: If multiple scripts, plugins, or template partials dynamically inject their own <base> tags, developers may struggle to predict which tag loads first, leading to broken assets, failed API calls, or broken relative hyperlinks.
  • Script and Style Breakage: Elements that rely on relative URLs, such as <link rel="stylesheet">, <script src="...">, and <img> tags, depend directly on the base URL. If an unintended <base> tag is parsed first, critical page assets may fail to load.

Best Practices

To avoid path resolution bugs, ensure your application or CMS generates no more than one <base> element per document. Place it as early as possible inside the <head> section, ideally before any elements that rely on relative URLs, to guarantee that scripts, stylesheets, and links resolve consistently across all browsers.
