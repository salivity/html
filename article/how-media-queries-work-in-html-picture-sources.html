How Media Queries Work in HTML Picture Sources

The HTML <picture> element allows developers to deliver responsive images by pairing one or more <source> elements with a fallback <img> tag. Within each <source> tag, the media attribute accepts standard CSS media queries to conditionally serve different image files based on device characteristics, viewport dimensions, or user preferences. This article explains the evaluation order, syntax support, and browser behavior that govern how these embedded media queries operate.

First-Match-Wins Evaluation

Browsers parse <source> elements inside a <picture> element sequentially from top to bottom. The first <source> whose media query evaluates to true is selected, and all subsequent <source> elements are ignored.

Because of this "first-match-wins" logic, the order in which sources are declared is critical:

  • Mobile-first approach: When using min-width queries, order the sources from the largest breakpoint to the smallest breakpoint.
  • Desktop-first approach: When using max-width queries, order the sources from the smallest breakpoint to the largest breakpoint.

If the order is inverted (for example, placing a min-width: 320px query above a min-width: 1024px query), the smaller condition evaluates to true first on large screens, preventing the larger, more appropriate image from ever being loaded.

<picture>
  <!-- Evaluated first -->
  <source media="(min-width: 1024px)" srcset="large.jpg">
  <!-- Evaluated second -->
  <source media="(min-width: 640px)" srcset="medium.jpg">
  <!-- Fallback if no media queries match -->
  <img src="small.jpg" alt="Example responsive image">
</picture>

Supported Media Features

The media attribute accepts any valid CSS media query that can be used in a standard stylesheet. This includes:

  • Viewport Dimensions: Width and height conditions such as (min-width: 768px), (max-width: 1200px), or range syntax like (600px <= width <= 900px).
  • Device Orientation: Queries such as (orientation: landscape) and (orientation: portrait).
  • Display Density and Resolution: Queries such as (min-resolution: 2dppx) or (-webkit-min-device-pixel-ratio: 2).
  • User Preferences: Accessibility and system preference queries such as (prefers-color-scheme: dark) to switch between light and dark versions of an image, or (prefers-reduced-data: reduce) for compressed assets.

Media queries can also be combined using logical operators like and, not, and comma-separated lists (which act as an or condition).

<picture>
  <source media="(prefers-color-scheme: dark) and (min-width: 800px)" srcset="dark-large.jpg">
  <source media="(prefers-color-scheme: dark)" srcset="dark-small.jpg">
  <source media="(min-width: 800px)" srcset="light-large.jpg">
  <img src="light-small.jpg" alt="Theme-adaptive diagram">
</picture>

Preload Scanner Compatibility and Resource Loading

Browsers utilize a speculative pre-parser (often called the preload scanner) to discover and fetch critical resources before the full DOM and CSSOM are constructed.

Because the media attribute is baked directly into the HTML structure, the browser's preload scanner can evaluate these queries against the current viewport and device state immediately. The browser only requests the single image source that matches the active query, preventing wasted bandwidth and unnecessary network requests.

If the environment changes dynamically—such as when a user resizes the browser window or flips their device between portrait and landscape modes—the browser re-evaluates the queries in the <picture> element and fetches the newly matched source file if necessary.

The Role of the Fallback <img> Element

The <source> element does not render pixels on the page by itself; it merely supplies alternative URLs and configuration data. The mandatory <img> element at the end of the <picture> block is what actually renders the selected image.

When a media query on a <source> evaluates to true, the browser takes that source's srcset and applies it to the underlying <img> element. If none of the media queries match, or if the browser does not support the <picture> tag, the src attribute of the fallback <img> is displayed.
