How Custom Elements Hook Into HTML Parsing

This article explains how autonomous custom elements integrate with the browser's HTML parser during page load. It covers how the HTML parser recognizes custom tags during tree construction, the role of the custom element registry in triggering synchronous construction and upgrades, and the precise timing of lifecycle callbacks like connectedCallback relative to DOM tree insertion and child node parsing.

The HTML Parser and Tag Recognition

When the browser streams and parses HTML, the tokenizer emits start and end tags while the tree construction phase builds the Document Object Model (DOM). Standard HTML tags map directly to predefined interfaces (such as HTMLDivElement for <div>).

When the parser encounters a valid autonomous custom element name—identified by containing a hyphen (e.g., <user-profile>)—it checks the document's CustomElementRegistry for a matching definition registered via customElements.define().

Defined Elements: Synchronous Construction

If the autonomous custom element is registered before the parser encounters its tag, the parser treats element creation as an active step in tree construction:

  1. Instantiation: The parser creates the element by invoking its registered JavaScript constructor. At this moment, the element exists in memory, but it has not yet been appended to the document tree.
  2. Attribute Processing: The parser reads the attributes present on the opening tag and assigns them to the newly created instance. If the class defines an observedAttributes array, the attributeChangedCallback fires synchronously for each attribute.
  3. Tree Insertion: The parser attaches the element to its parent node within the ongoing DOM construction.
  4. Invocation of connectedCallback: As the element enters the DOM, the browser enqueues a reaction on the custom element reactions stack. The parser processes this stack immediately, firing connectedCallback synchronously before parsing the next token.

Because this sequence occurs during start-tag processing, the element's children have not yet been parsed. Attempting to access this.childNodes or this.innerHTML inside the constructor or connectedCallback during initial HTML parsing returns empty structures.

Undefined Elements and the Upgrade Process

If the parser encounters a custom tag that has not yet been defined in the CustomElementRegistry, the sequence shifts to a deferred model:

  1. Creation as HTMLElement: The parser instantiates the tag as an un-customized HTMLElement instance and marks it as an "upgrade candidate."
  2. Normal DOM Insertion: The element is placed in the DOM tree, its attributes are set, and its children are parsed as normal without executing custom lifecycle hooks.
  3. Upgrading: When the script eventually executes customElements.define() for that tag name, the browser initiates the upgrade process. It invokes the constructor, assigns any previously existing attributes to trigger attributeChangedCallback, and invokes connectedCallback because the node is already connected to the active document.

The Custom Element Reactions Stack

To prevent lifecycle callbacks from disrupting parser execution, the HTML specification utilizes the custom element reactions stack. Whenever the parser executes an operation that alters an element's connection state or attributes, it pushes a reaction to the current reaction queue.

The parser processes this queue at well-defined checkpoints, specifically before running subsequent scripts or processing further tree nodes. This ensures lifecycle callbacks execute in strict document order without breaking the deterministic, streaming nature of the HTML parser.
