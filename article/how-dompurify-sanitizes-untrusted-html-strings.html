How DOMPurify Sanitizes Untrusted HTML Strings

DOMPurify is a client-side library designed to eliminate Cross-Site Scripting (XSS) vulnerabilities by cleaning unsafe HTML before it is rendered by a browser. Rather than relying on simple pattern-matching regular expressions, DOMPurify leverages the browser’s native parsing engines to construct an inert Document Object Model (DOM) tree, walks through every node, strips out dangerous elements and attributes against strict allowlists, and neutralizes advanced vectors like Mutation XSS (mXSS) and DOM Clobbering. This article details the step-by-step mechanism DOMPurify uses to turn untrusted input into secure markup.

1. Inactive Parsing via the Browser's Native Parser

The sanitization process begins by feeding the raw, untrusted HTML string into the browser’s built-in parser instead of a custom string parser. DOMPurify uses implementations like DOMParser or the <template> element to convert the string into an inert DOM tree (a DocumentFragment or decoupled HTMLDocument).

Because this tree exists purely in memory and is detached from the active document, embedded scripts do not execute, inline styles do not apply, and external resources (such as <img> or <iframe> sources) are not fetched during this phase. This step guarantees that DOMPurify interprets the markup identically to how the host browser will interpret it, avoiding mismatches that attackers often exploit.

2. Node Traversal and Tree Walking

Once the inert DOM tree is constructed, DOMPurify traverses the structure node by node. It inspects every element, text node, and attribute sequentially. During this traversal, hooks can be executed if custom rules or plugins are configured, but the default behavior focuses on evaluating the structural safety of each component.

3. Element and Attribute Filtering (Allowlisting)

DOMPurify operates on a strict default allowlist rather than a blocklist:

  • Tags: It allows safe structural tags (like <div>, <p>, <b>, <table>) while actively stripping high-risk tags such as <script>, <object>, <embed>, <iframe>, and <base>.
  • Attributes: It validates attributes against an approved set. All inline JavaScript event handlers (such as onclick, onerror, onload, and onmouseover) are immediately removed.
  • Protocols and URIs: For attributes that accept URLs (such as href on <a> tags or src on <img> tags), DOMPurify checks the protocol. Safe protocols like http:, https:, mailto:, and tel: are permitted, while dangerous protocols like javascript: and data: (with exceptions for safe image types if explicitly allowed) are stripped.

4. Mitigation of DOM Clobbering

DOM Clobbering occurs when an attacker uses HTML elements with specific id or name attributes (like <form id="submit"> or <img name="body">) to overwrite existing properties on the global window or document objects. DOMPurify actively detects and neutralizes these patterns. It identifies elements that attempt to mask native DOM properties and sanitizes or isolates their attributes so they cannot interfere with application logic or other security controls.

5. Protection Against Mutation XSS (mXSS)

Mutation XSS arises when a browser alters or "mutates" an HTML fragment between the time it is read and the time it is re-inserted into the active DOM. These mutations can transform seemingly harmless markup into executable script injection.

DOMPurify combats mXSS by performing normalization checks and, when necessary, re-evaluating the serialized output. By sanitizing the tree, re-serializing it, and verifying that subsequent parsing does not cause hazardous mutations (such as malformed MathML or SVG namespaces breaking out into regular HTML), it prevents the browser from interpreting inert text as executable code.

6. Serialization and Output

After all disallowed elements, invalid attributes, and dangerous structures are pruned from the inert tree, DOMPurify converts the remaining safe DOM nodes back into an HTML string using native serialization (such as innerHTML or XML serializers for SVG/MathML). Alternatively, it can return the sanitized DocumentFragment or DOM node directly. The resulting output contains only safe, valid markup that can be inserted into the live DOM using methods like element.innerHTML without risking XSS execution.
