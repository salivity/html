Difference Between rel="prefetch" and rel="prerender"

Speculative loading allows web browsers to anticipate user actions and load content before it is explicitly requested, significantly reducing perceived latency. While both rel="prefetch" and rel="prerender" aim to accelerate future navigation, they operate at vastly different levels of resource commitment: prefetch merely downloads and stores resources in the browser cache without executing them, whereas prerender downloads, parses, and completely renders an entire web page in the background for near-instant transitions.

What is rel="prefetch"?

The rel="prefetch" directive is a resource hint used to fetch resources—such as images, scripts, stylesheets, or even next-page HTML documents—that a user is likely to need in the near future.

  • Behavior: The browser downloads the specified file and stores it in the local HTTP cache.
  • Execution: It does not parse HTML, execute JavaScript, or create a Document Object Model (DOM). The resource remains inert until the user navigates to the corresponding page or calls the resource directly.
  • Priority: Downloads are treated with a low priority so they do not compete with critical network requests required by the current active page.
  • Resource Impact: Consumes minimal memory and CPU, requiring only network bandwidth and storage space.

What is rel="prerender"?

The rel="prerender" directive takes speculative loading a step further by fetching the target HTML document along with all of its dependent subresources, rendering the page entirely off-screen.

  • Behavior: The browser loads the target URL into an invisible background tab or process.
  • Execution: The browser parses the HTML, executes associated JavaScript, constructs the DOM and CSSOM, and performs layout and painting operations. If the user clicks the link, the rendered page instantly replaces the current viewport.
  • Priority: Typically operates with higher resource priority than a simple prefetch, though modern implementations still throttle background work to avoid degrading current page performance.
  • Resource Impact: Highly resource-intensive, consuming significant CPU, GPU, memory, and bandwidth.

(Note: In modern web standards, traditional <link rel="prerender"> has largely been superseded by the Speculation Rules API, which provides browsers with a safer, more granular mechanism to achieve prerendering.)

Core Differences

Feature rel="prefetch" rel="prerender"
Action Taken Downloads file and saves it to cache Downloads, parses, and fully renders the page
JavaScript Execution No execution occurs Executes JavaScript in the background
Applicable Targets Individual assets (JS, CSS, images) or HTML Full HTML pages and all subresources
System Overhead Low (bandwidth only) High (bandwidth, memory, CPU, and GPU)
Side Effects None (no code runs) Can trigger analytics, API calls, or cookies
Navigation Speed Fast (eliminates download time) Instant (eliminates download, parse, and render time)

When to Use Each

Use rel="prefetch" when:

  • You want to prepare for likely future actions with minimal risk of wasting client hardware resources.
  • You need to cache specific high-value assets across multiple pages, such as a large JavaScript bundle or hero image.
  • The probability of the user visiting the destination is moderate rather than guaranteed.

Use rel="prerender" when:

  • There is a very high probability that the user will navigate to a specific page (such as the next step in a linear checkout funnel or multi-page form).
  • Near-zero latency navigation is critical to the user experience.
  • The destination page does not execute harmful side-effects or premature tracking scripts before user activation.
