How the HTML Base Tag Resolves Relative Image Paths

The HTML <base> element defines a default target URL and browsing context for all relative URLs within a document. By specifying an href attribute inside the <base> tag, any relative resource path—including image sources—resolves against this designated base URL instead of the current document's location. This article explains how the tag overrides default URL resolution, how it affects relative image paths, and key behaviors to keep in mind when implementing it.

Default URL Resolution vs. Base Tag Resolution

Under normal conditions, a web browser resolves relative image paths using the document’s current URL. For example, if a user visits https://example.com/blog/posts/article.html and the HTML contains <img src="photo.jpg">, the browser attempts to fetch the image from:

https://example.com/blog/posts/photo.jpg

When a <base> tag is introduced, the browser ignores the current page URL for relative path calculations and instead uses the URL provided in the <base> element.

How the <base> Tag Modifies Image Paths

The <base> tag must be placed inside the <head> section of the document, positioned before any elements with external attribute references.

Consider the following setup:

<head>
  <base href="https://cdn.example.com/assets/">
</head>
<body>
  <img src="images/logo.png">
</body>

Because the base URL is https://cdn.example.com/assets/, the relative image path images/logo.png is resolved against that base:

https://cdn.example.com/assets/images/logo.png

Even if the HTML file itself is hosted on a completely different domain or directory (e.g., https://mysite.org/index.html), the browser routes the image request directly to the base domain and path.

Resolution Rules for Different Path Formats

The <base> tag handles different types of image paths according to standard URL resolution algorithms:

  • Relative Paths (src="logo.png" or src="img/logo.png"): Appended directly to the directory path specified in the <base href="...">.
  • Directory-Relative Paths (src="../logo.png"): The browser moves up one directory level from the base URL's path, rather than from the current document's path.
  • Root-Relative Paths (src="/logo.png"): Resolved against the origin (protocol + host + port) of the <base> URL, ignoring any subdirectories declared in the base href.
  • Absolute URLs (src="https://othercdn.com/logo.png"): Fully qualified URLs ignore the <base> tag entirely and resolve as explicitly defined.

Document-Wide Scope and Precautions

The <base> tag has global scope and alters every relative URL across the entire document, not just image elements. This includes links (<a href>), script files (<script src>), and stylesheets (<link href>).

A document can contain only one <base> element; any subsequent <base> tags are ignored by the browser. Additionally, internal fragment identifiers (such as <a href="#section">) will resolve against the base URL rather than the current document, which can cause unexpected page reloads if the base URL differs from the current page address.
