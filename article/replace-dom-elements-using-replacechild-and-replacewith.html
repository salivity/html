Replace DOM Elements Using replaceChild and replaceWith

Updating elements inside an existing HTML Document Object Model (DOM) tree is a fundamental operation in web development, typically achieved using either Node.replaceChild() or the modern Element.replaceWith(). While both methods swap an existing node for a new one without altering the surrounding document hierarchy, they differ significantly in their syntax, flexibility, and parent-child requirements. This guide explores how both methods manipulate the DOM tree, how the browser processes the replacement, and which approach best suits specific use cases.

The replaceChild() Method

The replaceChild() method is a core method of the Node interface. It operates from the perspective of the parent element and requires an explicit reference to that parent to execute the replacement.

Syntax

parentNode.replaceChild(newChild, oldChild);

How It Works in the DOM Tree

  1. Targeting: The developer must select the parent container, the node to be inserted, and the node being removed.
  2. Atomic Swap: The browser locates oldChild within parentNode.childNodes. It detaches oldChild from the live DOM tree and places newChild in its exact index position.
  3. Return Value: It returns the removed node (oldChild). This reference remains stored in memory, allowing developers to reinsert it elsewhere or inspect it later.

Example

const parent = document.getElementById("list");
const oldItem = document.getElementById("item-to-replace");

const newItem = document.createElement("li");
newItem.textContent = "Updated Item";

const removedItem = parent.replaceChild(newItem, oldItem);

The replaceWith() Method

Introduced in modern DOM specifications, replaceWith() is a method on the ChildNode (and Element) interface. It operates directly on the node that needs to be replaced, eliminating the need to explicitly query or reference the parent element.

Syntax

node.replaceWith(...nodesOrStrings);

How It Works in the DOM Tree

  1. Targeting: Called directly on the target element itself (element.replaceWith(...)).
  2. Direct Replacement: The browser internally determines the parent element and swaps the target element with the provided argument(s).
  3. Multi-Node and Text Insertion: Unlike replaceChild(), replaceWith() can accept multiple nodes and plain text strings. Strings are automatically converted into equivalent Text nodes before insertion.
  4. Return Value: It returns undefined.

Example

const oldItem = document.getElementById("item-to-replace");

const newItem = document.createElement("li");
newItem.textContent = "Updated Item";

// Replaces the element directly
oldItem.replaceWith(newItem);

You can also replace an element with multiple nodes or strings simultaneously:

const target = document.querySelector(".placeholder");
target.replaceWith("Hello, ", document.createElement("strong"), " world!");

Key Differences and Behavioral Impact on the DOM

Feature replaceChild() replaceWith()
Caller Must be called on the parent node (parent.replaceChild(...)) Called directly on the target element (element.replaceWith(...))
Accepted Arguments Exactly one replacement Node One or more Node objects or strings
Return Value The replaced (removed) Node undefined
String Handling Throws a TypeError if passed a raw string Automatically converts strings to Text nodes
Browser Support Legacy and modern browsers (Deep historical support) Modern browsers (Requires polyfills for legacy Internet Explorer)

Memory and Event Listener Lifecycle

When either method updates an element in the HTML tree:

  • Reflow and Repaint: The browser recalculates the layout (reflow) and updates the screen (repaint) only for the affected portion of the tree, avoiding a full page reload.
  • Detached Nodes: The replaced element is detached from the live document. If no JavaScript variable references it, the garbage collector safely destroys it.
  • Event Listeners: Any event listeners attached via addEventListener to the original node remain bound to that detached node in memory. They do not transfer automatically to the new replacement node.
