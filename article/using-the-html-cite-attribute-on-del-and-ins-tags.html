Using the HTML cite Attribute on del and ins Tags

The cite attribute on HTML <del> and <ins> elements provides a machine-readable URL that points to an external resource explaining why a specific text edit or document revision occurred. This article explains the technical mechanics of the cite attribute, how to implement it correctly in semantic markup, its default browser behavior, and how developers can expose this metadata to end users.

The Purpose of <del> and <ins>

HTML includes dedicated elements to represent editorial changes within a document. The <del> tag indicates content that has been removed, typically styled by browsers with a strikethrough. The <ins> tag indicates content that has been added, typically rendered with an underline.

Together, these tags preserve the history of a document directly in the markup, making them valuable for legal documents, collaborative writing platforms, and dynamic content updates.

How the cite Attribute Works

The cite attribute accepts a valid, absolute or relative URL pointing to an explanation, ticket, commit, or policy document that justifies the modification. It acts as semantic metadata rather than a standard navigational link.

<p>
  The project deadline is 
  <del cite="https://example.com/change-log#update-42">October 15th</del>
  <ins cite="https://example.com/change-log#update-42">November 1st</ins>.
</p>

In this example, both the deletion and insertion reference the exact section of a change log documenting the schedule shift. The URL can point to:

  • An issue tracker or pull request (e.g., GitHub, Jira).
  • Meeting minutes or internal memos.
  • An editorial correction notice.
  • Legal addenda or regulatory updates.

Browser Handling and Accessibility

Web browsers do not automatically turn the cite attribute into a clickable hyperlink for users. Because it is purely structural metadata, the target URL remains hidden from standard visual interactions unless explicitly exposed.

Screen readers and assistive technologies can recognize the cite attribute, allowing users to query the source or rationale of an edit programmatically. However, support varies across different tools.

Exposing the Explanation URL to Users

To make the cite URL accessible to general website visitors, developers must use CSS or JavaScript.

Using CSS

You can display the presence of a citation using CSS pseudo-elements, though this approach cannot create an interactive link:

del[cite]::after,
ins[cite]::after {
  content: " [citation]";
  font-size: 0.8em;
  color: #555;
}

Using JavaScript

To make the attribute interactive, JavaScript can wrap the edited content in an anchor tag, generate an accessible tooltip, or dynamically open the source URL upon clicking:

document.querySelectorAll('del[cite], ins[cite]').forEach((element) => {
  element.addEventListener('click', () => {
    const url = element.getAttribute('cite');
    if (url) {
      window.open(url, '_blank', 'noopener,noreferrer');
    }
  });
});

Using the cite attribute ensures document edits remain traceable, semantically accurate, and directly linked to their authoritative explanations.
