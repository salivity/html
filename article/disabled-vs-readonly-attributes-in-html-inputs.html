Disabled vs Readonly Attributes in HTML Inputs

Both the disabled and readonly attributes prevent users from editing form fields, but they function fundamentally differently in HTML. While both restrict user modifications, they differ significantly in form submission behavior, focusability, element compatibility, and default styling. This guide explains the technical differences between the two attributes so you can apply them correctly in your web forms.

Form Submission

The most critical difference between disabled and readonly is how they handle data during form submission:

  • disabled: The element's value is completely omitted from the HTTP request payload. Browsers do not submit disabled form controls.
  • readonly: The element's value is included in the form submission and sent to the server as usual.

Focus and Navigation

User interaction and accessibility differ depending on the attribute used:

  • disabled: The input cannot receive focus. Users cannot click into the field, select or copy text inside it, or reach it using keyboard navigation (such as the Tab key). It is completely inert.
  • readonly: The input can still receive focus. Users can navigate to the field using the Tab key, click inside it, and highlight or copy its contents. However, they cannot type into it or alter the existing value.

Supported Elements

Not all HTML controls support both attributes:

  • disabled: Universally supported across virtually all form elements, including <input> (all types), <textarea>, <select>, <button>, and <fieldset>.
  • readonly: Only supported on form elements that take direct text input, such as <textarea> and text-based <input> types (text, password, search, url, tel, email, number, date). It has no effect on <select>, buttons, file inputs, checkboxes, or radio buttons.

Visual Styling and Pseudo-Classes

Browsers handle the default appearance of these attributes differently:

  • disabled: Browsers apply a default grayed-out styling to indicate inactivity. In CSS, it matches the :disabled pseudo-class.
  • readonly: Browsers typically render read-only fields with the same default visual style as normal inputs, requiring custom CSS to visually distinguish them. In CSS, it matches the :read-only pseudo-class.

When to Use Each Attribute

  • Use disabled when a form field is irrelevant, inactive, or conditionally unavailable based on other user choices, and its data should not be sent to the backend.
  • Use readonly when a user needs to view, copy, or submit a pre-filled value (such as an account ID or calculated total) that must remain unchanged.
