CSS :required and :optional Selectors Explained

The CSS :required and :optional pseudo-class selectors provide a direct mechanism for styling form controls based on whether user input is mandatory. These selectors evaluate the presence or absence of the boolean required attribute on HTML form elements, allowing developers to present clear visual cues and real-time validation states without relying on JavaScript.

The HTML required Attribute

In HTML, the required attribute is a boolean attribute applied to form controls. When present, the browser prevents form submission until the user supplies a valid value for that field:

<input type="text" name="username" required>
<input type="text" name="nickname">

How the Selectors Map to HTML

The relationship between the CSS selectors and the HTML markup is strictly binary for supported elements:

  • :required: Matches any form control that explicitly includes the required attribute (e.g., required, required="", or required="required").
  • :optional: Matches any form control that lacks the required attribute, as well as any form control for which the required attribute is not permitted or supported.

Supported Elements

The mapping applies to any standard form control capable of taking the required attribute:

  • <input> (most standard types such as text, email, password, checkbox, radio, file, number, url)
  • <select>
  • <textarea>

Unsupported Elements

Elements that cannot take user input or cannot enforce mandatory input—such as <input type="hidden">, <input type="submit">, <input type="button">, <input type="reset">, or <button>—do not evaluate to :required. These elements evaluate to :optional by default in most browser implementations, although styling them as optional is generally unnecessary.

Implementation Example

Because :required and :optional map directly to the attribute's state, styles update immediately if the attribute is toggled via JavaScript or loaded statically:

/* Style for mandatory fields */
input:required,
textarea:required,
select:required {
  border-left: 4px solid #d9534f;
  background-color: #fffaf0;
}

/* Style for non-mandatory fields */
input:optional,
textarea:optional,
select:optional {
  border-left: 4px solid #cccccc;
}
<form>
  <!-- Matches input:required -->
  <label for="email">Email (Mandatory):</label>
  <input type="email" id="email" name="email" required>

  <!-- Matches input:optional -->
  <label for="phone">Phone (Optional):</label>
  <input type="tel" id="phone" name="phone">
</form>

Key Considerations

  • Disabled Controls: An element with both disabled and required attributes will still match :required, even though the user cannot interact with it. Combine selectors like :required:not(:disabled) to avoid confusing UI states.
  • Accessibility: Visual styles generated by :required and :optional should supplement, not replace, native semantic indicators such as the <label> text or accessible labels (aria-label) indicating a required field.
