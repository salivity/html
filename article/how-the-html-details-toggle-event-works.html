How the HTML Details Toggle Event Works

This article provides a concise overview of how the native HTML <details> element dispatches the toggle event. You will learn the exact conditions under which the event fires, its timing and lifecycle characteristics, its event propagation behavior, and how to reliably detect whether the element is opening or closing via JavaScript.

When the Event Fires

The toggle event triggers whenever the open attribute of a <details> element changes. Because it represents a state change rather than a specific directional action, the exact same event fires in two scenarios:

  1. When a closed element expands to show its contents.
  2. When an open element collapses to hide its contents.

Users typically trigger this by clicking the <summary> element, pressing the Enter or Space keys while the summary is focused, or when a script programmatically adds or removes the open attribute.

Timing and Asynchronous Execution

The toggle event fires after the open attribute has already been updated in the DOM. The browser queues a task to dispatch the event immediately after the visual and structural state changes take place.

Because the event fires after the mutation occurs:

  • The event is not cancelable (event.cancelable is false). You cannot call event.preventDefault() inside a toggle listener to stop the element from opening or closing.
  • If you need to prevent the state change, you must intercept the user interaction on the <summary> element (such as listening for click or keydown) and cancel that interaction before the open attribute can change.

Propagation and Bubbling

Unlike many common user-interaction events like click or change, the toggle event does not bubble (event.bubbles is false).

Because it does not bubble:

  • Event delegation on parent containers (such as document or a parent <div>) will not catch the event during the bubble phase.
  • If you wish to use event delegation to monitor multiple <details> elements, you must set the event listener to the capture phase by passing { capture: true } as the third argument to addEventListener.

Detecting Open vs. Closed State

Since there are no separate "open" or "close" events, you must check the boolean open property on the target <details> element within the event handler to determine the current state.

const details = document.querySelector("details");

details.addEventListener("toggle", (event) => {
  if (details.open) {
    console.log("The element has expanded.");
  } else {
    console.log("The element has collapsed.");
  }
});

When this callback executes, details.open accurately reflects the new state because the attribute mutation has already been applied.
