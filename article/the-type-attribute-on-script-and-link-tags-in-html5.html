The Type Attribute on Script and Link Tags in HTML5

In modern HTML5, the type attribute on <script> and <link rel="stylesheet"> elements is no longer mandatory for standard web assets, as modern browsers default to JavaScript and CSS respectively. While omitting the attribute maintains standard execution, modern browsers still actively inspect type values to unlock modern JavaScript capabilities, configure browser behavior, or ignore non-executable content.

The type Attribute on <script> Tags

In modern HTML specifications, omitting the type attribute or setting it to type="text/javascript" tells the browser to execute the contents as a classic JavaScript script. Modern browsers utilize the type attribute on <script> tags in several distinct ways:

  • JavaScript Modules (type="module"): When set to "module", the browser parses the file as an ECMAScript (ES) module. This triggers strict mode automatically, supports native import and export statements, isolates top-level variables from the global scope, enforces Cross-Origin Resource Sharing (CORS) restrictions, and defaults execution to defer behavior.
  • Import Maps (type="importmap"): Browsers recognize this type to resolve bare module specifiers in ES modules. The content inside the tag must be a JSON object mapping module names to URLs, enabling clean imports without bundling tools.
  • Data Blocks and Templates: If the type attribute contains any value not recognized as a valid JavaScript MIME type (such as type="application/json" or type="text/template"), the browser deliberately avoids executing the contents. Instead, the script element remains in the DOM as a pure data block accessible via JavaScript.
  • Speculation Rules (type="speculationrules"): Modern Chromium-based browsers recognize this type to parse JSON-based predictive rules for prerendering and prefetching upcoming navigations in the background.

The type Attribute on <link rel="stylesheet"> Tags

For stylesheets loaded via <link rel="stylesheet">, the HTML5 specification defines text/css as the default. Consequently, including type="text/css" is purely redundant.

When present, modern browsers treat the type attribute on <link> elements strictly as an advisory hint:

  • Fetch Filtering: Before initiating a network request, a browser may check the type attribute. If it specifies a stylesheet format the browser does not support (for instance, an alternate format other than CSS), the browser can immediately abort fetching the resource, saving bandwidth.
  • HTTP Header Priority: Regardless of what is declared in the type attribute, browsers ultimately rely on the HTTP Content-Type header sent by the web server. If a <link> tag specifies type="text/css", but the server serves the file with an incompatible MIME type (like text/plain or application/octet-stream), modern browsers enforcing strict MIME-type checking will reject and fail to apply the stylesheet.
