How hidden="until-found" Enables In-Page Search

The hidden="until-found" attribute enables web browsers to index and search collapsed or hidden HTML content using native "Find in Page" (Ctrl+F or Cmd+F) features. Unlike standard hiding techniques that completely obscure text from the browser's search mechanism, this attribute keeps the DOM nodes accessible to the search index while keeping them visually hidden. When a user searches for text contained within an element marked with this attribute, the browser automatically reveals the section, scrolls it into view, and highlights the match.

The Problem with Traditional Hidden Content

Standard methods for hiding content—such as display: none, visibility: hidden, or the standard boolean hidden attribute—remove elements from the rendering pipeline and the browser’s active text search. Consequently, content inside accordions, tabs, or expandable menus becomes unsearchable until a user manually opens every section. This creates a degraded user experience, as users frequently rely on native in-page search to quickly locate specific information on text-heavy pages.

How hidden="until-found" Changes Rendering

The hidden="until-found" attribute leverages the browser's content-visibility model. Instead of detaching the element from layout calculations entirely like display: none does, the browser treats the element similarly to content-visibility: hidden.

Under this model:

  • The element is visually hidden from view and skipped during painting and layout to maintain rendering performance.
  • The element’s text content and structure remain present in the accessibility tree and searchable by the browser's native search algorithms.
  • Fragment navigation (URL anchor links) can also target and locate elements within the hidden block.

The Reveal Process and the beforematch Event

When a user initiates an in-page search and the browser matches a string located inside a hidden="until-found" container, a specific sequence of actions occurs:

  1. Detection: The browser identifies the match within the hidden subtree.
  2. Event Dispatch: Before showing the content, the browser fires a beforematch event on the hidden element. This event bubbles up through the DOM.
  3. Attribute Removal: The browser automatically removes the hidden="until-found" attribute from the element.
  4. UI Synchronization: Developers can listen to the beforematch event to synchronize custom UI states, such as expanding an accordion wrapper, changing ARIA attributes (aria-expanded="true"), or rotating toggle icons.
  5. Display and Scroll: The browser renders the element, scrolls the viewport to the target position, and highlights the matching phrase for the user.

Basic Implementation

To apply this behavior to a custom collapsible section, assign the attribute to the container holding the hidden content:

<button id="accordion-toggle" aria-expanded="false">Show Details</button>

<div id="accordion-content" hidden="until-found">
  <p>This text is hidden by default, but searching for it will automatically expand this block.</p>
</div>

<script>
  const toggle = document.getElementById('accordion-toggle');
  const content = document.getElementById('accordion-content');

  // Sync the UI if the browser automatically reveals the content
  content.addEventListener('beforematch', () => {
    toggle.setAttribute('aria-expanded', 'true');
  });

  // Standard toggle interaction
  toggle.addEventListener('click', () => {
    const isHidden = content.hasAttribute('hidden');
    if (isHidden) {
      content.removeAttribute('hidden');
      toggle.setAttribute('aria-expanded', 'true');
    } else {
      content.setAttribute('hidden', 'until-found');
      toggle.setAttribute('aria-expanded', 'false');
    }
  });
</script>

CSS Considerations

Browsers apply user-agent styles to [hidden="until-found"] using content-visibility: hidden. If an author stylesheet includes aggressive overrides such as [hidden] { display: none !important; }, it will override the native behavior and prevent the browser from searching the hidden content. To avoid breaking searchability, any custom styles applied to [hidden] selectors should target [hidden]:not([hidden="until-found"]) or respect the browser's native handling of the attribute.
