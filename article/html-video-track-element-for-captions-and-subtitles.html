HTML Video Track Element for Captions and Subtitles

The HTML <track> element specifies timed text tracks for <video> and <audio> elements, allowing developers to add subtitles, closed captions, audio descriptions, chapter markers, and metadata. By linking external WebVTT files to media players, it enhances web accessibility for deaf or hard-of-hearing users, provides translations for international audiences, and improves comprehension in sound-sensitive environments.

What is the <track> Element?

The <track> tag is an empty, self-closing child element placed inside an <audio> or <video> container. It points to an external file—formatted in Web Video Text Tracks (.vtt)—that contains timestamped text cues synchronized with media playback.

A standard implementation looks like this:

<video controls width="640" height="360" poster="thumbnail.jpg">
  <source src="presentation.mp4" type="video/mp4">
  <track 
    kind="captions" 
    src="captions-en.vtt" 
    srclang="en" 
    label="English Captions" 
    default>
  <track 
    kind="subtitles" 
    src="subtitles-es.vtt" 
    srclang="es" 
    label="Español">
</video>

Key Attributes of the <track> Element

To function properly, the <track> element relies on several core attributes:

  • src: The URL of the .vtt text file containing the timed cues.
  • kind: Defines how the text track is intended to be used.
  • srclang: Specifies the language of the track using standard BCP 47 language tags (e.g., en, es, fr). This is required if kind="subtitles".
  • label: A human-readable title displayed in the browser's video player settings (e.g., "English SDH" or "French Subtitles").
  • default: A boolean attribute that designates the track to be active by default if user preferences do not dictate otherwise. Only one track per media element can have this attribute.

Types of Tracks: The kind Attribute

The primary function of the <track> tag is dictated by its kind attribute, which accepts five specific values:

1. Subtitles (kind="subtitles")

Subtitles provide transcription or translation of dialogue for viewers who can hear the audio but may not understand the spoken language. They assume the viewer can hear sound effects, background music, and emotional tones, focusing strictly on translated or written speech.

2. Closed Captions (kind="captions")

Captions provide a complete textual representation of the audio for viewers who are deaf or hard of hearing. Unlike subtitles, captions include not only the dialogue but also critical non-speech information, such as sound effects (e.g., [door slams]), music cues, and speaker identification.

3. Descriptions (kind="descriptions")

Descriptions provide a text-based version of the visual action taking place on screen. These are intended for synthesis into speech via a screen reader to assist blind or visually impaired users who cannot see the video track.

4. Chapters (kind="chapters")

Chapter tracks define titles and time ranges to help users navigate the media. When supported by the browser or custom media player, chapter markers allow viewers to jump directly to specific sections of a long video.

5. Metadata (kind="metadata")

Metadata tracks contain timed data intended for consumption by JavaScript scripts rather than being directly displayed to the user. This data can trigger real-time actions on the webpage as the video progresses, such as synchronizing slide decks, loading interactive quizzes, or displaying contextual links.

Benefits of Using the <track> Element

Implementing the <track> element ensures compliance with accessibility standards like the Web Content Accessibility Guidelines (WCAG). It also improves user experience by allowing viewing in noisy spaces or places where sound must be muted, and aids search engine optimization (SEO) by making video content crawlable via text.
