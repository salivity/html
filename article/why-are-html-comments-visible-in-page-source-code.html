Why Are HTML Comments Visible in Page Source Code?

HTML comments remain visible in a browser's page source because HTML is a client-side markup language delivered as plain text directly to the user's device. Unlike server-side code, which is executed and stripped before transmission, standard HTML files are transferred intact. Browsers are responsible for parsing the entire document—including comments—meaning anything written into an HTML comment reaches the user's browser unless an automated build tool or server-side process explicitly removes it.

How HTML Delivery Works

When a user visits a website, the browser sends an HTTP request to the web server. The server responds by sending the HTML document as raw text. Web servers such as Apache, Nginx, or cloud storage buckets do not interpret or modify HTML files by default; they simply transmit the bytes stored on the disk or generated by an application.

Because the web server treats the entire HTML document as static data to be sent across the network, every character inside that document—including <!-- comment --> tags—is delivered to the client machine.

Comments Are Valid DOM Nodes

HTML comments are not discarded by the browser upon arrival because the Document Object Model (DOM) specification explicitly treats them as valid components of a web page.

When the browser's rendering engine constructs the DOM tree, it represents HTML comments as Comment nodes (which inherit from the generic Node interface). Because these nodes exist within the DOM hierarchy, they can be read, manipulated, or traversed using client-side JavaScript via standard DOM properties like nodeType === Node.COMMENT_NODE. The browser hides comments from the rendered visual output, but it preserves them in the page source and developer inspection tools.

Server-Side vs. Client-Side Comments

A common source of confusion is the distinction between server-side comments and client-side HTML comments.

  • Server-side languages (such as PHP, Python, Ruby, or templating engines like Twig and Blade) process code on the server. Comments written in these languages (for example, <?php // comment ?> or {# comment #}) are stripped during execution on the server and are never sent over the network.
  • HTML comments (<!-- comment -->) are part of the final payload. If a server-side script outputs an HTML comment, or if the comment is written directly into an .html file, it will be transmitted to the browser.

Security and Performance Considerations

Because HTML comments are readable by anyone who right-clicks and selects "View Page Source" or opens browser developer tools, they present specific concerns:

  • Information Disclosure: Developers sometimes mistakenly leave internal API endpoints, database structures, employee names, staging URLs, or outdated code snippets in HTML comments. Malicious actors frequently scan source code comments during reconnaissance.
  • Payload Size: Large blocks of commented-out code or extensive documentation unnecessarily inflate the file size of the HTML payload, increasing bandwidth usage and slowing down page load times.

Preventing Comments from Reaching the Client

To keep comments hidden from end-users, development workflows rely on minification and build tools. Modern build tools (such as Webpack, Vite, and PostHTML) and production minifiers (such as html-minifier) automatically strip HTML comments before deploying code to production. Additionally, Content Delivery Networks (CDNs) often provide automated HTML optimization features that remove comments on the fly before delivering files to visitors.
