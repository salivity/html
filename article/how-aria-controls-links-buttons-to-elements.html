How aria-controls Links Buttons to Elements

The aria-controls attribute establishes a programmatic relationship between an interactive controlling element, such as a toggle button, and the specific HTML element whose state or visibility it manipulates. By defining this link, developers enable assistive technologies—including screen readers—to understand exactly which part of the Document Object Model (DOM) changes when a user triggers the control. This article explains how the attribute functions under the hood, how it pairs with other accessibility attributes, and how to implement it correctly in web interfaces.

The ID-Based Association

The mechanism behind aria-controls relies entirely on matching strings using unique DOM identifiers. To create the relationship:

  1. The target element that expands, collapses, or updates must have a globally unique id attribute.
  2. The controlling <button> element must include the aria-controls attribute.
  3. The value assigned to aria-controls must match the id of the target element exactly.

When a browser renders this markup, it exposes the relationship to the browser's accessibility tree. This allows assistive technologies to announce to the user that the button controls an external component, often enabling shortcuts that jump directly from the button to the controlled content.

<!-- The button references the target container's id -->
<button type="button" aria-expanded="false" aria-controls="collapsible-section">
  Toggle Details
</button>

<!-- The controlled container matching the id -->
<div id="collapsible-section" hidden>
  <p>This content is dynamically shown or hidden by the button above.</p>
</div>

Pairing with aria-expanded

While aria-controls establishes which element is being operated on, it does not convey the current state of that element. To make expanding content accessible, aria-controls is almost always paired with aria-expanded.

  • aria-expanded="false": Indicates that the associated element is currently closed or collapsed.
  • aria-expanded="true": Indicates that the associated element is currently open or expanded.

When JavaScript toggles the visibility of the target content (by removing the hidden attribute or altering CSS display properties), it must simultaneously update the button's aria-expanded value.

Controlling Multiple Elements

The aria-controls attribute can associate a single button with more than one HTML element simultaneously. If an action toggles or updates several distinct sections of a page, multiple target id values can be passed to the attribute, separated by a space:

<button type="button" aria-controls="panel-one panel-two">
  Expand All
</button>

<div id="panel-one">Content 1</div>
<div id="panel-two">Content 2</div>

Screen Reader Support and Best Practices

When properly implemented, screen readers use the aria-controls mapping to offer commands that let users navigate straight to the altered content without needing to search through the page structure manually.

To ensure the association functions reliably:

  • Ensure the target element's id is unique across the entire document.
  • Always apply aria-controls directly to interactive elements, ideally native <button> tags rather than generic <div> or <span> elements.
  • Avoid applying aria-controls if the expanding element is already placed immediately after the button in the DOM source order, as sequential reading will naturally encounter the expanded content next. However, when controlling detached drawers, modals, or remote sections, aria-controls remains an essential accessibility link.
