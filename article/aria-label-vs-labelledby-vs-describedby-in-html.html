ARIA Label vs Labelledby vs Describedby in HTML

Web accessibility relies on providing clear context to assistive technologies like screen readers. This article explains the distinct purposes, syntax, and proper use cases of three essential Accessible Rich Internet Applications (ARIA) attributes: aria-label, aria-labelledby, and aria-describedby. Understanding the differences among these attributes ensures that web interfaces are accessible, predictable, and compliant with modern accessibility standards.

What Is aria-label?

The aria-label attribute directly provides an element with an accessible name using an invisible text string. It is applied directly to the HTML tag and does not alter the visual appearance of the element.

  • Primary Purpose: To give an accessible name to interactive elements that lack visible text on screen.
  • Value Type: A plain text string.
  • Common Use Case: Icon-only buttons (such as a search magnifying glass or a close "X" button).
<!-- The screen reader announces: "Close, button" -->
<button aria-label="Close">
  <svg aria-hidden="true"><!-- Icon SVG --></svg>
</button>

What Is aria-labelledby?

The aria-labelledby attribute establishes an accessible name by referencing the id of one or more existing visible elements in the DOM. Instead of providing a hardcoded string, it pulls text directly from the page content.

  • Primary Purpose: To label an element using visible text that already exists elsewhere on the page.
  • Value Type: One or more space-separated element id attributes.
  • Precedence: It takes precedence over all other naming methods, including native HTML elements (like <label>) and aria-label.
  • Common Use Case: Dialog boxes labeled by their visible heading, or complex form controls that rely on existing text blocks.
<!-- The screen reader announces: "Billing Address, section" -->
<section aria-labelledby="billing-header">
  <h2 id="billing-header">Billing Address</h2>
  <!-- Form fields -->
</section>

You can also concatenate multiple elements to form a complete label:

<span id="item-name">T-Shirt</span>
<span id="item-color">Blue</span>

<button aria-labelledby="item-name item-color">Delete</button>
<!-- Screen reader announces: "T-Shirt Blue, button" -->

What Is aria-describedby?

The aria-describedby attribute provides an accessible description rather than an accessible name. It references the id of an existing element in the DOM to supply supplementary or secondary information.

  • Primary Purpose: To provide contextual, instructional, or error details that accompany an element.
  • Value Type: One or more space-separated element id attributes.
  • Screen Reader Behavior: Screen readers typically read the accessible name and role first, pause, and then read the description provided by aria-describedby.
  • Common Use Case: Input field formatting instructions, password requirements, error messages, and tooltips.
<label for="password">Password</label>
<input 
  type="password" 
  id="password" 
  aria-describedby="password-rules"
/>
<p id="password-rules">Must be at least 8 characters long.</p>
<!-- Screen reader announces: "Password, edit text, Must be at least 8 characters long." -->

Key Differences at a Glance

Attribute What It Sets Value Expected Primary Role
aria-label Accessible Name Text string Names an element when no visible text is available.
aria-labelledby Accessible Name Element ID(s) Names an element using visible text from the DOM.
aria-describedby Accessible Description Element ID(s) Adds supplementary instructions, hints, or errors to an element.

When to Use Which

  1. Use aria-labelledby when the text you want to use as the label is already visible on the screen.
  2. Use aria-label only when an interactive element has no visible text label (e.g., icon buttons).
  3. Use aria-describedby when an element already has a name, but requires additional context, validation hints, or error messages.
