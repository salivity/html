Measuring Component Render Time with elementtiming

This article explores the HTML elementtiming attribute, a web platform feature designed to measure the precise render and paint times of specific DOM elements. By annotating key visual elements directly in the HTML and querying them with the Performance Timeline API, developers can track component-level performance in real user monitoring (RUM) setups, moving beyond broad, page-level performance metrics.

What is the elementtiming Attribute?

The elementtiming attribute is an HTML attribute that allows developers to flag specific elements for performance measurement. When added to an element, the browser records timing metrics—such as when the element was requested, when it loaded, and when it was first rendered on the screen—and exposes these metrics via the Performance Timeline API.

Traditionally, web performance focused on aggregate, page-level milestones such as First Contentful Paint (FCP) and Largest Contentful Paint (LCP). While useful, these metrics do not identify when a critical business component—such as a hero carousel, checkout button, or search results widget—actually renders. The elementtiming attribute bridges this gap by enabling granular, element-specific performance telemetry.

Supported Elements

The elementtiming attribute can be applied to several types of HTML elements:

  • Image elements: <img>
  • Image elements inside an SVG: <image>
  • Poster images of video elements: <video poster="...">
  • Elements with a background-image styled via CSS
  • Text-containing elements: block-level or inline elements containing direct text nodes (e.g., <h1>, <p>, <div>)

How to Use the Attribute

To track an element, assign the elementtiming attribute with an identifier string of your choice:

<img src="hero.jpg" alt="Featured Product" elementtiming="hero-banner" />
<h1 elementtiming="main-heading">Product Details</h1>

The string value assigned to the attribute acts as an identifier in the performance data, allowing scripts to map timing entries back to specific components.

Accessing the Metrics in JavaScript

Browsers expose element timing records through the PerformanceObserver API using the element entry type. When observed, the browser dispatches PerformanceElementTiming objects containing performance metrics.

const observer = new PerformanceObserver((entryList) => {
  for (const entry of entryList.getEntries()) {
    console.log('Element ID:', entry.identifier);
    console.log('Render Time:', entry.renderTime);
    console.log('Load Time:', entry.loadTime);
    console.log('Element Node:', entry.element);
  }
});

observer.observe({ type: 'element', buffered: true });

The resulting PerformanceElementTiming interface provides several key properties:

  • identifier: The string value provided in the elementtiming attribute.
  • renderTime: The exact timestamp when the element was painted to the screen. If an image is hosted on an external origin without a Timing-Allow-Origin header, this value defaults to 0 for security reasons.
  • loadTime: The timestamp when the resource finished loading (relevant for images and external assets).
  • intersectionRect: The visible coordinates and dimensions of the element within the viewport at the time of rendering.
  • naturalWidth and naturalHeight: The intrinsic dimensions of an image asset before CSS scaling.

Key Use Cases

  1. Component-Level Observability: Track the render speeds of isolated UI components, design system elements, or micro-frontends across different client devices.
  2. A/B Testing Impact: Measure whether code changes, layout shifts, or asset optimizations directly alter the display time of call-to-action buttons or hero media.
  3. Single-Page Application (SPA) Updates: Identify the exact moment dynamically injected DOM elements appear following client-side routing and asynchronous data fetching.
