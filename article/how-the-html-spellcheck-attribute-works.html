How the HTML spellcheck Attribute Works

The spellcheck attribute is a global HTML attribute that controls whether the browser checks an editable element for spelling and grammar errors. This guide covers how the attribute functions on editable text elements, the values it accepts, default browser behaviors, and practical use cases for enabling or disabling native spellchecking.

What the spellcheck Attribute Does

When applied to editable text, spellcheck instructs the web browser whether to run its native spellchecking engine on the content. If enabled, the browser flags misspelled words and grammar issues—typically by rendering a red wavy underline beneath the flagged text—and provides correction suggestions via the context menu (right-click).

Affected Elements

The spellcheck attribute only takes effect on elements that users can edit. These include:

  • <textarea> elements: Multi-line text inputs.
  • <input> elements: Text-based input types, such as type="text", type="search", and type="url".
  • Elements with contenteditable="true": Any HTML element transformed into a rich-text or editable container.

If spellcheck is placed on a non-editable element (such as a standard <p> or <div> without contenteditable), or on an <input> marked as readonly or disabled, the attribute has no visible effect.

Accepted Values

The spellcheck attribute is an enumerated attribute, not a boolean attribute. It accepts two explicit string values:

  • "true": Enables spellchecking and grammar checking for the element.
  • "false": Disables spellchecking and grammar checking for the element.

If the attribute is present without a value (e.g., <textarea spellcheck>), it resolves to true. If the attribute is omitted entirely, the element uses its default state.

Default and Inherited Behavior

When the spellcheck attribute is not explicitly declared:

  1. Inheritance: Elements generally inherit their spellcheck state from their closest ancestor element that has a defined spellcheck value.
  2. Element Defaults: If no ancestor defines the attribute, the browser falls back on its default rules:
    • <textarea> elements typically have spellchecking enabled by default.
    • Single-line <input> elements (such as type="text") typically have spellchecking disabled by default.
    • contenteditable containers usually inherit the setting or default to enabled.

Common Use Cases

  • Disabling Spellcheck (spellcheck="false"): Recommended for fields containing non-standard vocabulary where red underlines cause distraction. Common examples include code editors, terminal emulators, username fields, email address inputs, serial numbers, and cryptographic keys.
  • Enabling Spellcheck (spellcheck="true"): Recommended for fields where standard written language is expected, such as comment sections, blog post editors, messaging interfaces, and feedback forms.

Limitations

The spellcheck attribute requests browser-level checking, but it does not control the underlying dictionary, language detection, or correction algorithm. Those aspects remain entirely dependent on the user's browser version, operating system settings, and installed language packs.
