CSS content-visibility: auto for Performance

The CSS content-visibility: auto property is a modern performance feature that optimizes page load times by allowing the browser to skip rendering work for elements currently outside the user's viewport. By deferring the layout and painting processes of off-screen content until it is needed, browsers significantly reduce initial DOM rendering costs, speed up Total Blocking Time (TBT), and improve First Contentful Paint (FCP).

Skipping Layout and Painting

When content-visibility: auto is applied to an element, the browser treats it similarly to an element with heavy rendering isolation. If the element is not currently visible on the screen, the browser bypasses:

  • Layout calculations: The browser does not calculate the geometric positions or dimensions of child elements.
  • Painting: The browser does not rasterize or draw the element's visual details.
  • Style recalculations: Certain style calculations for child nodes are delayed until the element approaches the viewport.

As a result, a massive page with thousands of off-screen nodes can achieve the rendering speed of a much smaller, lightweight page.

Viewport Proximity Detection

The browser automatically monitors when an element with content-visibility: auto is approaching the viewport. As the user scrolls toward the element, the browser preemptively runs the layout and paint operations so the content is fully rendered just before it enters the visual frame, ensuring a smooth scrolling experience without visual flickering.

Preventing Layout Shifts with contain-intrinsic-size

Because the browser skips rendering off-screen elements, it initially assigns them a height and width of 0px. Without intervention, this causes severe layout shifts and erratic scrollbar behavior as items suddenly expand upon entering the viewport.

To fix this, developers pair content-visibility: auto with the contain-intrinsic-size property. This defines placeholder dimensions for the unrendered element:

.card {
  content-visibility: auto;
  contain-intrinsic-size: 0 450px; /* estimated width and height */
}

Modern browsers also support contain-intrinsic-size: auto 450px, which remembers the element's real rendered size once it has been rendered once, preventing shifts if the user scrolls back up.

Difference from display: none

Unlike display: none, which completely removes an element from the rendering tree and breaks accessibility, content-visibility: auto preserves the element's state:

  • The content remains fully searchable using the browser’s "Find on page" feature (Ctrl+F / Cmd+F).
  • Assistive technologies can still access the DOM tree, and focusing on an element inside the hidden container will cause it to render automatically.
  • Form controls and selection states inside the container remain intact.

Ideal Use Cases

The property is best applied to long, content-heavy documents such as:

  • Long articles or documentation pages split into sections.
  • Social media feeds or infinite-scroll layouts.
  • E-commerce search results and product listings.

Placing content-visibility: auto on high-level container sections allows browsers to process complex web pages with minimal rendering overhead.
