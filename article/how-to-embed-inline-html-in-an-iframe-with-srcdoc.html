How to Embed Inline HTML in an iframe with srcdoc

The srcdoc attribute in HTML5 allows developers to specify the exact HTML markup to be rendered inside an <iframe> directly as a string, eliminating the need to load an external file or host a separate document. This article explains how the srcdoc attribute works, its syntax, how it interacts with the standard src attribute as a fallback, and important security considerations like sandboxing.

What is the srcdoc Attribute?

Traditionally, the <iframe> tag requires a src attribute pointing to a URL (such as an external webpage or a local file) to render content. The srcdoc attribute provides an alternative by accepting inline HTML code directly within the element definition.

When the browser parses an <iframe> with srcdoc, it takes the string value and builds an entirely separate HTML document object model (DOM) inside the frame context, without triggering a network request for an external resource.

Basic Syntax

<iframe srcdoc="<h1>Embedded Content</h1><p>This is rendered via inline HTML.</p>"></iframe>

Because the value is passed inside an HTML attribute, any quotation marks and special characters must be properly escaped. For example, use single quotes for the attribute value if your HTML snippet uses double quotes, or encode double quotes as &quot;.

<iframe srcdoc='<p class="highlight">Inline HTML with attributes</p>'></iframe>

Interaction with the src Attribute

The srcdoc attribute is designed to override the src attribute in browsers that support it. If an <iframe> includes both attributes:

<iframe 
  src="fallback.html" 
  srcdoc="<p>Modern browsers display this content.</p>">
</iframe>
  1. Modern Browsers: The browser prioritizes srcdoc and displays the inline markup, ignoring the resource specified in src.
  2. Older Browsers: If a browser does not recognize the srcdoc attribute, it falls back to loading the file specified in the src attribute.

Document Origin and Execution Context

An iframe populated by srcdoc inherits the origin of its parent document. This means:

  • Scripts running inside the srcdoc frame have the same origin privileges as the embedding page, allowing them to access the parent's DOM unless restricted.
  • Relative URLs inside the srcdoc (such as <a href="/page"> or <img src="image.png">) are resolved against the base URL of the parent document.

Security with the sandbox Attribute

Because srcdoc content inherits the parent's origin, rendering untrusted user-generated content directly inside srcdoc can introduce Cross-Site Scripting (XSS) risks.

To mitigate this, pair srcdoc with the sandbox attribute:

<iframe 
  sandbox="allow-scripts" 
  srcdoc="<script>console.log('Sandboxed script execution');</script>">
</iframe>

Applying sandbox places the inline document into a unique, restricted origin. A completely empty sandbox attribute disables JavaScript, form submissions, and access to the parent document's cookies and local storage.

Primary Use Cases

  • Email and Template Previews: Displaying HTML email previews or user-generated design templates in an isolated container without writing files to disk.
  • Rich Text Editors: Rendering live previews of user-supplied HTML content securely using sandboxed frames.
  • Performance Optimization: Creating independent document trees for widgets or components without making additional HTTP round-trips.
