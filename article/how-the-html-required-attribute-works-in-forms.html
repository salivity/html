How the HTML Required Attribute Works in Forms

The HTML required attribute is a boolean attribute that enforces native client-side form validation directly within modern web browsers without relying on JavaScript. This article explains how browsers handle required inputs during form submission, how the underlying Constraint Validation API tracks validity states, how to style these elements using CSS pseudo-classes, and why server-side validation remains necessary.

When the required attribute is added to an element—such as <input>, <textarea>, or <select>—it marks that specific control as mandatory before the parent <form> can be submitted. If a user tries to submit the form while a required field is empty, the browser intervenes automatically: it halts the submission event, shifts focus directly to the first invalid field, and displays a localized, browser-specific warning prompt (such as "Please fill out this field").

Under the hood, the browser manages this behavior through the Constraint Validation API. Every DOM form element exposes a validity property returning a ValidityState object. When a field with the required attribute lacks an acceptable value, the validity.valueMissing property evaluates to true. This causes methods like element.checkValidity() to return false, triggering an invalid event on the element and blocking the form's native submit action.

Different input types interpret completion differently under the required attribute:

  • Text, Email, Password, and Textarea: The field must contain at least one non-whitespace character or non-empty string.
  • Select Menus: The selected <option> must have a non-empty value attribute. A placeholder option with value="" forces the user to choose another item.
  • Checkboxes: A required checkbox must be explicitly checked.
  • Radio Groups: If any single radio button in a named group contains the required attribute, the entire group requires at least one option to be selected.

Browsers also provide CSS pseudo-classes to style these fields based on their state:

  • :required targets any input with the attribute present, allowing developers to visually denote mandatory inputs (such as adding an asterisk).
  • :valid and :invalid dynamically apply styles depending on whether the current input satisfies its constraints, including completion.

While the required attribute effectively guides users and streamlines the user experience on the client side, it can be bypassed by end-users disabling HTML validation, adding the novalidate attribute to the form, or sending direct HTTP requests to the backend. Consequently, native HTML validation should always be paired with robust server-side validation.
