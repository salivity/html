Native HTML Accordions with Details and Summary

This article explains how the native HTML <details> and <summary> elements create collapsible content areas and accordions without requiring JavaScript. It covers basic syntax, state management with attributes, creating exclusive multi-panel accordions, styling the default appearance, and the inherent accessibility benefits of using native browser features.

The Basic Structure

The <details> tag acts as a disclosure widget wrapper that can toggle between an open and closed state. The <summary> tag sits inside <details> as its first child, functioning as the visible, clickable label.

<details>
  <summary>What is HTML?</summary>
  <p>HTML stands for HyperText Markup Language and structures web content.</p>
</details>

When a user clicks on the text within <summary>, the browser automatically toggles the visibility of the remaining content nested within <details>. By default, the browser provides a small disclosure triangle icon next to the summary text.

Controlling the State with the open Attribute

The visibility of the <details> element is controlled by the boolean open attribute:

  • Closed (default): When the open attribute is omitted, only the <summary> is visible.
  • Open: When the open attribute is present (e.g., <details open>), the element expands automatically upon page load.

JavaScript can read or modify this state directly via the DOM property:

const details = document.querySelector('details');
console.log(details.open); // returns true or false

The element also emits a native toggle event whenever its state changes:

details.addEventListener('toggle', (event) => {
  if (details.open) {
    // Panel was opened
  } else {
    // Panel was closed
  }
});

Creating Mutually Exclusive Accordions

Traditional accordions automatically close other panels when a new panel is opened. Modern HTML supports this natively through the name attribute. When multiple <details> elements share the same name value, only one element within that group can be open at a time.

<details name="faq">
  <summary>Question 1</summary>
  <p>Answer to question 1.</p>
</details>

<details name="faq">
  <summary>Question 2</summary>
  <p>Answer to question 2.</p>
</details>

<details name="faq">
  <summary>Question 3</summary>
  <p>Answer to question 3.</p>
</details>

Opening "Question 2" automatically collapses "Question 1" without requiring custom scripts.

Customizing and Styling

Browsers allow standard CSS properties to be applied directly to <details> and <summary>:

Removing the Default Marker

The default triangle indicator can be hidden using standard CSS:

summary {
  list-style: none; /* Standard */
  cursor: pointer;
}

summary::-webkit-details-marker {
  display: none; /* Safari/older Chrome support */
}

Adding Custom Indicators

Custom icons can be implemented using the ::after or ::before pseudo-elements alongside the [open] attribute selector:

summary::after {
  content: '+';
  float: right;
}

details[open] summary::after {
  content: '−';
}

Accessibility Advantages

Using native <details> and <summary> elements provides built-in accessibility without extra ARIA configuration:

  • Keyboard Navigation: Users can navigate to the <summary> using the Tab key and toggle visibility using the Enter or Space key.
  • Screen Readers: Assistive technologies automatically announce the element as an expandable button or disclosure widget, along with its current expanded or collapsed state.
  • SEO and Search: Text inside a closed <details> element remains part of the DOM, allowing search engine crawlers and browser "find-in-page" tools (Ctrl+F / Cmd+F) to index and locate content within collapsed sections.
