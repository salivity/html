How MSE Feeds Fragmented Buffers into HTML Video

The Media Source Extensions (MSE) API bridges JavaScript and the HTML5 <video> element, allowing client-side code to build and manage media streams dynamically. Instead of pointing a video element directly to a static media file, MSE allows developers to fetch fragmented media segments—such as fragmented MP4 (fMP4) or WebM chunks—via standard network requests and feed them directly into the browser's decoding pipeline. This architecture forms the backbone of modern web streaming protocols like DASH and HLS.

Attaching the MediaSource to the Video Element

The process begins by decoupling the video element from a direct file URL. A MediaSource object is created in JavaScript and bound to the <video> element's src attribute using a temporary object URL created with URL.createObjectURL(mediaSource).

Once the browser initializes the binding, the MediaSource instance fires a sourceopen event. This event signals that the underlying media engine is ready to accept media configurations and data streams.

Creating the SourceBuffer

Inside the sourceopen event handler, the application creates one or more SourceBuffer objects by calling mediaSource.addSourceBuffer(mimeType). The MIME type string must explicitly declare the container format and the exact codecs used, such as video/mp4; codecs="avc1.4d401f, mp4a.40.2".

The SourceBuffer acts as the direct staging area for raw bytes before they are passed to the hardware or software decoders. Browsers allocate specific memory constraints for these buffers to prevent memory overflow during extended playback.

Fetching and Appending Fragmented Chunks

MSE relies on fragmented media, which splits media files into an initialization segment and multiple sequential media segments:

  1. Initialization Segment: Contains metadata, codec parameters, and track configurations (such as the moov box in MP4 files) but contains no raw sample data.
  2. Media Segments: Contain timestamped audio/video frames packed into self-contained units (such as moof and mdat boxes in MP4 files).

JavaScript fetches these segments asynchronously using the Fetch API as ArrayBuffer instances. The application then passes the fetched bytes into the decoder pipeline by calling sourceBuffer.appendBuffer(chunk).

Handling Asynchronous Buffer Updates

The appendBuffer() method is asynchronous. While the browser parses and integrates the raw media data into the playback timeline, the SourceBuffer enters an updating state (sourceBuffer.updating === true).

Attempting to append another chunk while the buffer is updating throws an InvalidStateError. Therefore, the application must listen for the updateend event on the SourceBuffer before pushing the next segment. This sequential queue ensures that frames are decoded and mapped onto the timeline in proper chronological order.

Playback and Timeline Management

As segments are appended, the browser's media engine automatically assembles a continuous timeline. It resolves timestamps, parses keyframes, and handles synchronization between separate audio and video SourceBuffer instances.

The standard HTML <video> element monitors this timeline. When the playback head enters a buffered region, the player decodes and renders the frames seamlessly. If the application needs to switch video quality dynamically, it simply fetches the next media segment from a different bitrate representation and appends it to the existing SourceBuffer. When all segments have been fed, the application calls mediaSource.endOfStream() to close the stream gracefully.
