Declarative Shadow DOM: shadowrootmode Open vs Closed

Declarative Shadow DOM allows developers to render native shadow trees directly from server-side HTML using the <template> element without relying on client-side JavaScript. The primary difference between shadowrootmode="open" and shadowrootmode="closed" is whether the encapsulated DOM tree can be accessed by client-side JavaScript through the host element's shadowRoot property. Choosing between these modes dictates the level of JavaScript accessibility, affecting how the host page, testing tools, and third-party scripts interact with the component.

Understanding shadowrootmode="open"

When using shadowrootmode="open", the browser attaches a shadow root to the parent element and exposes it to the DOM API via element.shadowRoot.

<custom-card>
  <template shadowrootmode="open">
    <style>p { color: blue; }</style>
    <p>Open Shadow Content</p>
  </template>
</custom-card>

In this mode:

  • JavaScript Accessibility: Calling document.querySelector('custom-card').shadowRoot returns the ShadowRoot object.
  • Inspectability: Outside scripts can query, style, or manipulate elements inside the shadow tree by traversing into the exposed root (e.g., card.shadowRoot.querySelector('p')).
  • Tooling Support: Automation frameworks, unit tests, and accessibility inspection tools can easily traverse the internal nodes.

Understanding shadowrootmode="closed"

When using shadowrootmode="closed", the browser encapsulates the internal DOM tree without exposing a public reference on the host element.

<custom-card>
  <template shadowrootmode="closed">
    <style>p { color: green; }</style>
    <p>Closed Shadow Content</p>
  </template>
</custom-card>

In this mode:

  • JavaScript Accessibility: Calling document.querySelector('custom-card').shadowRoot returns null.
  • Restricted Direct Access: External scripts cannot directly access the shadow root through the standard element property.
  • Hydration Caveat: When created declaratively, JavaScript has no default reference to the shadow root. Unlike imperative attachShadow({ mode: 'closed' })—which returns the shadow root reference upon creation—declarative closed trees leave no reference unless deliberately captured by an internal component script.

Key Differences

Feature shadowrootmode="open" shadowrootmode="closed"
element.shadowRoot Returns the ShadowRoot Returns null
External JS Access Permitted Blocked via standard DOM property
Testing & Automation Straightforward Difficult without workarounds
Style Encapsulation Yes (scoped styles) Yes (scoped styles)
Security Boundary None None

Encapsulation vs. Security

A common misconception is that shadowrootmode="closed" functions as a security boundary. It does not.

Closed mode only deters casual DOM traversal; it does not protect against malicious scripts executing in the same execution context. An external script can patch prototypes (such as Element.prototype.attachShadow) before hydration, intercept bubbling events via event.composedPath(), or parse the raw template markup before the browser parses it into a shadow tree.

Summary

Use shadowrootmode="open" for general-purpose web components, design systems, and server-rendered templates. It provides CSS scoping and DOM encapsulation while keeping the component accessible to unit tests, DOM manipulation scripts, and browser tooling.

Reserve shadowrootmode="closed" strictly for scenarios where deliberate detachment from the host element's public API is required, keeping in mind that it adds architectural friction without offering true security benefits.
