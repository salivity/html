Why type="text/javascript" Is Obsolete in HTML5

In earlier versions of HTML, developers were required to include the type="text/javascript" attribute on every <script> tag to specify the scripting language being used. With the arrival of HTML5, this requirement was officially dropped because JavaScript became the standardized, universal default scripting language of the World Wide Web. Modern web browsers automatically interpret the contents of a <script> tag as JavaScript unless explicitly told otherwise, making the attribute redundant boilerplate.

Historical Context: The Multi-Language Web That Never Happened

During the development of HTML 4.01 and XHTML in the late 1990s, browser vendors envisioned a web that could support multiple client-side scripting languages. Internet Explorer, for instance, supported both JavaScript (via JScript) and VBScript.

Because of this architectural diversity, the HTML 4.01 specification made the type attribute mandatory. Specifying type="text/javascript" informed the browser's rendering engine precisely which interpreter to invoke before executing the code block.

The HTML5 Standardization

As the web evolved, alternative scripting languages fell out of favor, and JavaScript became the undisputed standard for client-side development. When the Web Hypertext Application Technology Working Group (WHATWG) and the W3C drafted HTML5, one of the guiding design principles was to "pave the cowpaths"—meaning the specification should reflect real-world implementation rather than theoretical ideals.

Because browsers were already defaulting to JavaScript when encountering untyped <script> tags, the HTML5 specification codified this behavior:

  • An omitted type attribute automatically defaults to JavaScript.
  • An empty type="" attribute also defaults to JavaScript.
  • Using type="text/javascript" is still permitted for backward compatibility, but it is classified as purely optional.

When Is the type Attribute Still Needed?

While type="text/javascript" is no longer necessary, the type attribute itself is still used in modern web development for specific scenarios:

  • JavaScript Modules: To utilize native ES modules, you must specify type="module". This changes how the script is executed, enabling features like top-level import/export and deferred loading by default.
  • Data Blocks: Embedding non-executable data (such as JSON configuration) within an HTML document uses <script type="application/json">.
  • Templating Engines: Frameworks and libraries sometimes use custom script types (like type="text/template") to prevent the browser from executing the script content as code.

Omitting type="text/javascript" reduces unnecessary markup, saves bandwidth, and follows modern HTML best practices.
