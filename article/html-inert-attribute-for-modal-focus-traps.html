HTML Inert Attribute for Modal Focus Traps

The inert global HTML attribute significantly streamlines modal implementation by natively disabling interaction and hiding non-modal page elements from the accessibility tree. Traditionally, keeping keyboard focus and screen readers constrained within an active modal—known as a focus trap—required intricate JavaScript logic, manual tabindex manipulation, and aria-hidden attributes. By applying inert to the background content, developers can achieve a fully accessible, robust focus trap with a single attribute toggle.

The Complexity of Traditional Focus Traps

Historically, building an accessible modal dialog required complex JavaScript to prevent users from interacting with the background page. A standard implementation required:

  • Listening for keydown events to detect the Tab and Shift + Tab keys.
  • Querying all focusable elements inside the modal to redirect focus when the user cycled past the first or last interactive element.
  • Setting aria-hidden="true" on every background container to prevent screen readers from reading background content.
  • Managing pointer-events: none in CSS to prevent background mouse clicks.

This approach was brittle, error-prone, and required cleanup scripts whenever the modal opened or closed.

How the inert Attribute Works

The inert boolean attribute tells the browser to treat a DOM subtree as non-interactive. When inert is present on an element:

  1. Focus is blocked: None of the element's children can receive focus via keyboard navigation (Tab), script navigation (element.focus()), or mouse selection.
  2. User input is ignored: Clicks, hovers, text selection, and touch gestures on the subtree are completely disabled.
  3. Accessibility tools ignore it: The entire subtree is hidden from assistive technologies, acting as an implicit aria-hidden="true".

Implementing a Focus Trap with inert

Instead of trapping focus inside the modal, inert allows you to disable everything outside the modal. By wrapping your main application layout in a container separate from your modal container, you can toggle inert on the background wrapper whenever a modal opens.

<body>
  <!-- Main content wrapper -->
  <div id="main-content">
    <header>...</header>
    <main>
      <button id="open-modal">Open Modal</button>
    </main>
  </div>

  <!-- Modal overlay container -->
  <div id="custom-modal" role="dialog" aria-modal="true" hidden>
    <h2>Modal Title</h2>
    <input type="text" placeholder="Enter details" />
    <button id="close-modal">Close</button>
  </div>
</body>

With this DOM structure, trapping focus requires only toggling the inert attribute on #main-content:

const mainContent = document.getElementById('main-content');
const modal = document.getElementById('custom-modal');
const openBtn = document.getElementById('open-modal');
const closeBtn = document.getElementById('close-modal');

openBtn.addEventListener('click', () => {
  // Show the modal
  modal.removeAttribute('hidden');
  
  // Make the background inert
  mainContent.setAttribute('inert', '');
  
  // Shift focus to the first interactive element inside the modal
  closeBtn.focus();
});

closeBtn.addEventListener('click', () => {
  // Hide the modal
  modal.setAttribute('hidden', '');
  
  // Restore interaction to the background
  mainContent.removeAttribute('inert');
  
  // Restore focus to the triggering element
  openBtn.focus();
});

Because #main-content is marked as inert, the browser automatically confines the Tab sequence to the active elements inside #custom-modal. There is no need to write keyboard event listeners to intercept focus cycling.

inert vs. Native <dialog>

The native HTML <dialog> element automatically applies inertness to the rest of the document when opened using the showModal() method. However, the inert attribute is invaluable when:

  • You are working within an existing codebase or design system utilizing custom div-based modals.
  • You are implementing side drawers, slide-out navigation panels, or cookie banners that require focus management without standard <dialog> defaults.
  • You need to temporarily disable sections of a page during asynchronous loading states or multi-step forms.

Conclusion

The inert attribute replaces fragile JavaScript workarounds with a native browser mechanism. By shifting the focus management strategy from trapping focus inside a dialog to disabling the background content, developers can create robust, accessible modals with minimal code.
