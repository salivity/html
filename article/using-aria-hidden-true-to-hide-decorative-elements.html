Using aria-hidden="true" to Hide Decorative Elements

The aria-hidden="true" attribute is a core tool in web accessibility used to remove non-essential or decorative elements from the accessibility tree without affecting their visual display. When assistive technologies such as screen readers encounter an element marked with this attribute, they bypass it entirely. This ensures that users relying on audio feedback receive a clean, focused, and coherent reading experience free from redundant or confusing visual clutter like icons, dividers, and background graphics.

What is aria-hidden="true"?

The aria-hidden attribute belongs to the WAI-ARIA (Web Accessibility Initiative – Accessible Rich Internet Applications) specification. It accepts a boolean value (true or false). Setting it to "true" explicitly tells assistive technologies that the target element—along with all of its child elements—should be ignored.

Unlike the HTML hidden attribute or the CSS display: none; rule, aria-hidden="true" does not hide elements visually. The element remains fully visible on the screen for sighted users while disappearing completely from the screen reader's virtual cursor and accessibility API mapping.

Why Decorative Elements Must Be Hidden

Decorative elements are visual enhancements that provide aesthetic value but convey no unique information. Common examples include:

  • Font icons and SVGs displayed alongside explanatory text (e.g., a magnifying glass icon next to the word "Search").
  • Decorative line dividers, borders, or background shapes.
  • Redundant visual indicators (e.g., a "new window" arrow icon where the link text already clarifies the behavior).

Without aria-hidden="true", screen readers attempt to parse these elements. An SVG without an accessible name might be announced as "unlabeled image" or read out raw path data, while an icon font might read out an obscure Unicode character code. This interrupts the flow of content, increases cognitive load, and degrades the browsing experience.

Practical Implementation

The most frequent use case is an icon placed beside text. The text provides all the necessary context, rendering the icon purely decorative:

<button type="button">
  <svg aria-hidden="true" focusable="false" viewBox="0 0 24 24">
    <!-- SVG path data -->
  </svg>
  <span>Delete Item</span>
</button>

In this example, the screen reader simply announces "Delete Item, button." It skips the SVG entirely, avoiding an unhelpful announcement like "graphic, Delete Item, button."

Best Practices and Precautions

To maintain accessible code, keep the following rules in mind:

  • Never hide focusable elements: Applying aria-hidden="true" to an interactive element (like a link, button, or form control) creates a severe usability issue. Keyboard users will still tab into the control, but screen readers will remain silent, leaving the user unaware of what element is currently focused.
  • Inheritance applies to children: Hiding a parent container hides all nested elements inside it. Ensure that no meaningful content or interactive elements are wrapped inside an element with aria-hidden="true".
  • Use native HTML where appropriate: If an element should be hidden from both sighted users and screen readers, use native CSS (display: none; or visibility: hidden;) or the HTML5 hidden attribute instead of ARIA.
