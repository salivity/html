What Are Conditional Comments in Internet Explorer?

Conditional comments were proprietary Microsoft HTML extensions used between Internet Explorer 5 and Internet Explorer 9 to deliver targeted code—such as CSS fixes and JavaScript polyfills—specifically to legacy IE versions while remaining invisible to other web browsers. This article explains how conditional comments worked, their common syntax, why web developers relied on them, and their eventual obsolescence in modern web development.

How Conditional Comments Worked

Standard HTML comments use the <!-- comment --> syntax, which browsers ignore during rendering. Microsoft extended this behavior in Internet Explorer 5 by introducing conditional logic inside comment blocks.

When a standard-compliant browser like Mozilla Firefox, Opera, or Google Chrome encountered a conditional comment, it treated the entire block as plain HTML comments and ignored the contents. However, Internet Explorer contained an internal parser that evaluated the condition. If the condition evaluated to true, IE executed or rendered the HTML, CSS, or script tags nested inside.

Basic Syntax and Types

Conditional comments primarily came in two distinct formats: downlevel-hidden and downlevel-revealed.

1. Downlevel-Hidden Comments

This was the most common format. Browsers other than IE completely hid the content because the opening and closing tags resembled standard HTML comment delimiters.

<!--[if IE 6]>
<link rel="stylesheet" type="text/css" href="ie6-fixes.css" />
<![endif]-->

In this example, only Internet Explorer 6 loaded ie6-fixes.css. All other browsers ignored the block entirely.

2. Downlevel-Revealed Comments

This format allowed developers to show content to non-IE browsers while hiding it from specific IE versions. The syntax intentionally omitted standard comment markers around the inner content for non-IE parsers:

<!--[if !IE]> -->
<p>You are using a modern browser or a non-IE browser.</p>
<!-- <![endif]-->

Supported Operators

Conditional comments supported conditional operators to target specific versions or ranges of Internet Explorer:

  • [if IE]: Targets all supported versions of Internet Explorer (IE5 through IE9).
  • [if IE 7]: Targets Internet Explorer 7 specifically.
  • [if lt IE 8]: Less than (targets versions below IE8).
  • [if lte IE 8]: Less than or equal to (targets IE8 and older).
  • [if gt IE 6]: Greater than (targets versions above IE6).
  • [if gte IE 7]: Greater than or equal to (targets IE7 and newer).
  • [if !IE]: Logical NOT (targets non-IE browsers in downlevel-revealed syntax).

Multiple conditions could also be combined using the & (AND) and | (OR) operators.

Primary Use Cases

Before standardized rendering across browsers, legacy Internet Explorer versions suffered from significant non-standard behaviors, such as the proprietary Box Model bug in IE5/6, lack of support for HTML5 elements, and incomplete CSS selector support.

Developers primarily used conditional comments to:

  • Load dedicated fallback stylesheets containing CSS hacks specifically for older IE versions without polluting standard stylesheets.
  • Load polyfills and shims, such as html5shiv.js, enabling older IE versions to recognize elements like <article>, <section>, and <nav>.
  • Apply specific CSS classes to the root <html> tag (e.g., <html class="ie8">), allowing developers to scope IE-specific CSS rules inside a single global stylesheet.

Deprecation and Modern Status

Microsoft deprecated conditional comments starting with Internet Explorer 10. When running in standard mode, IE10 and IE11 treat conditional comments as regular HTML comments and ignore them entirely. Microsoft Edge, which replaced Internet Explorer, does not support them under any circumstances.

In modern web development, conditional comments are obsolete. Cross-browser compatibility is now handled through web standards, CSS feature queries (@supports), progressive enhancement, and automated transpilation tools.
