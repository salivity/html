What Is window.opener and rel="noopener"?

When an HTML hyperlink opens a new tab using the target="_blank" attribute, the newly opened webpage gains partial control over the originating page via the JavaScript window.opener property. This connection introduces significant security vulnerabilities, notably reverse tabnabbing, as well as performance bottlenecks. Adding rel="noopener" to the link severs this connection by nullifying the window.opener reference, isolating the two pages from each other for improved security and performance.

The Purpose and Risk of window.opener

The window.opener property is an inherent part of the Browser Object Model (BOM). When a page opens another page using an anchor tag with target="_blank" or through JavaScript's window.open(), the browser automatically creates an execution bridge. The opened page can access the original page through window.opener, which references the Window object of the referring document.

While this allows legitimate multi-window applications to pass messages, it creates a major security flaw known as "reverse tabnabbing." If a website links to an external or untrusted third-party site without restriction, the destination site can execute:

if (window.opener) {
  window.opener.location = "https://phishing-site.example.com";
}

Because the user initiated the click, they trust the original tab. When they finish viewing the secondary tab and return to the first tab, they may find a convincing replica of a login screen. Unaware that the page redirected itself in the background, the user is likely to enter their credentials.

Beyond security, window.opener can degrade performance. Because the two windows share an execution context, the browser may run both tabs on the same operating system process and thread. If the newly opened page executes heavy JavaScript, the originating page can freeze or stutter.

How rel="noopener" Solves the Problem

The rel="noopener" attribute is an HTML link attribute that instructs the browser to open the target document in an isolated browsing context.

<a href="https://example.com" target="_blank" rel="noopener">Visit External Site</a>

When a user clicks a link with rel="noopener", the browser sets the value of window.opener to null inside the new window. Consequently, the opened page has no reference to the referring document, completely eliminating the possibility of reverse tabnabbing via window.opener.location.

Severing this reference also allows the browser to place the new tab in a completely separate process or thread, depending on the browser's multi-process architecture. Heavy computation on the target page will not degrade the responsiveness of the original tab.

Modern Browser Defaults and Best Practices

Most modern browsers (including Chromium-based browsers, Firefox, and Safari) automatically apply the behavior of rel="noopener" to any link that includes target="_blank". However, explicitly declaring rel="noopener" remains a web development best practice to ensure protection in legacy browsers, webviews, and non-standard browsing environments.

Additionally, developers frequently encounter rel="noreferrer". Using rel="noreferrer" accomplishes the same outcome as rel="noopener"—it sets window.opener to null—while also omitting the HTTP Referer header from the network request, preventing the destination server from identifying the URL where the request originated.
