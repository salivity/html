How the ResizeObserver API Observes Element Changes

The ResizeObserver API provides a native, highly performant mechanism for tracking dimensional changes to specific HTML elements in real time. Unlike traditional approaches that rely on window-level resize events or periodic polling, the ResizeObserver hooks directly into the browser’s layout engine to detect modifications to an element's box model, delivering precise size notifications directly before the browser paints pixels to the screen.

Core Mechanics of the ResizeObserver

The ResizeObserver works by registering target Document Object Model (DOM) elements with an observer instance. When the browser recalculates styles and executes its layout phase, it checks whether any observed element's observed box dimensions have shifted since the last layout cycle.

A standard implementation follows three basic steps:

// 1. Define the observer with a callback function
const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    console.log('Target:', entry.target);
    console.log('New width:', entry.contentRect.width);
    console.log('New height:', entry.contentRect.height);
  }
});

// 2. Target a specific element
const targetElement = document.querySelector('#resizable-box');

// 3. Begin observation
observer.observe(targetElement);

Box Models and Observation Options

By default, the ResizeObserver monitors changes to an element's content-box—the area inside padding, borders, and margins. However, modern implementations allow developers to specify which box model to track using the box option inside the observe() method:

  • content-box: Tracks the size of the content area only, excluding padding and borders.
  • border-box: Tracks the dimensions including the content, padding, and borders.
  • device-pixel-content-box: Measures the content box in physical device pixels rather than CSS pixels, which is essential for crisp rendering on <canvas> elements across varied pixel-density displays (such as Retina screens).
observer.observe(targetElement, { box: 'border-box' });

The ResizeObserverEntry Object

When a change is detected, the callback receives an array of ResizeObserverEntry objects. Each entry contains details regarding the target element's new geometry:

  • target: The DOM element currently being resized.
  • contentRect: A legacy DOMRectReadOnly snapshot of the element's content box.
  • borderBoxSize: An array of objects reporting inlineSize (width) and blockSize (height) based on the border box.
  • contentBoxSize: An array containing inlineSize and blockSize measurements for the content box.
  • devicePixelContentBoxSize: An array reporting the dimensions in actual physical pixels.

Arrays are used for size properties to support CSS multi-column layouts and fragmented elements that span across multiple break areas.

Event Timing and Loop Prevention

A critical technical feature of the ResizeObserver API is how it handles delivery timing to prevent infinite layout loops.

Traditional layout listeners often cause "layout thrashing" by querying geometry, modifying styles, and triggering re-layouts sequentially within the same frame. ResizeObserver avoids this by processing observations directly after the layout phase and immediately before the browser renders (paints) the frame.

To prevent infinite loops—such as a resize handler resizing its own observed element—the browser employs a depth-checking algorithm:

  1. The observer detects elements that changed size during layout.
  2. The browser only processes elements whose depth in the DOM tree is greater than the shallowest element modified in the current notification loop.
  3. If resizing an element causes a shallower element (closer to the root) to resize, the callback for that shallower element is deferred to the next animation frame.
  4. If cyclic dependencies occur repeatedly, the browser fires an error event: "ResizeObserver loop limit exceeded".

Stopping Observations

To prevent memory leaks and unnecessary processing, elements should be released when no longer in use:

  • observer.unobserve(targetElement): Stops tracking a specific DOM node while keeping the observer active for other elements.
  • observer.disconnect(): Immediately ceases tracking across all registered elements associated with that observer instance.
