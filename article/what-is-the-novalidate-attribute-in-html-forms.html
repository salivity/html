What Is the Novalidate Attribute in HTML Forms?

The novalidate attribute is a boolean attribute used on HTML <form> elements to disable the browser's built-in constraint validation upon form submission. This guide explains what the attribute does, why developers choose to bypass native validation, common practical use cases, and how to implement it effectively without compromising your application's security.

What Does the novalidate Attribute Do?

Modern browsers automatically validate form controls before submitting data based on HTML5 attributes such as required, type="email", pattern, min, and max. When invalid data is entered, the browser halts submission and displays a native error popup.

Adding the novalidate attribute instructs the browser to skip this process entirely. The form will submit immediately, regardless of whether the inputs meet the defined constraints.

<form action="/submit" method="post" novalidate>
  <label for="email">Email:</label>
  <input type="email" id="email" name="email" required>
  <button type="submit">Submit</button>
</form>

In the example above, even though the required and type="email" attributes are present, clicking the submit button will not trigger the browser's native error bubble if the input is left blank or contains an invalid email format.

Why Use novalidate?

Disabling native browser validation is a standard practice in modern web development for several reasons:

  1. Custom JavaScript Validation
    Native validation tooltips differ visually across browsers (Chrome, Safari, Firefox) and offer limited styling options. Developers often use novalidate to suppress these inconsistent popups so they can implement fully styled, branded, and accessible validation messages using JavaScript or UI libraries.

  2. Access to the Constraint Validation API
    Using novalidate stops the browser from blocking submission, but it does not remove the element constraints. JavaScript can still query the Constraint Validation API (using methods like checkValidity() or properties like validity.valid) to run checks manually before determining whether to allow submission.

  3. "Save Draft" Functionality
    Multi-step forms or complex documents often require users to save progress before all required fields are completed. While developers typically use the formnovalidate attribute on a specific "Save Draft" button for this purpose, novalidate can achieve a similar result at the form level.

  4. Testing Server-Side Validation
    Client-side validation should never replace server-side validation. Adding novalidate allows developers and QA testers to submit deliberately malformed data through the interface to ensure that server-side validation and error handling work as expected.

Server-Side Security Considerations

The novalidate attribute only affects client-side behavior in the browser. It does not sanitize inputs or protect endpoints against malicious requests. Any user can remove the attribute via browser developer tools or bypass the browser entirely using tools like cURL or Postman. Always enforce rigorous server-side validation regardless of whether novalidate is present.
