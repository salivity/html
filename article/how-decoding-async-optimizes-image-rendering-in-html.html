How decoding="async" Optimizes Image Rendering in HTML

The decoding="async" attribute in HTML optimizes web performance by instructing the browser to decode compressed image data off the main execution thread. By offloading this computationally heavy rasterization process to a background thread, the browser prevents UI freezes, maintains responsive frame rates, and improves Core Web Vitals such as Interaction to Next Paint (INP) and Total Blocking Time (TBT).

The Problem with Synchronous Image Decoding

Before a browser can display a downloaded image format (such as JPEG, PNG, or WebP), it must decompress the binary data into a raw pixel bitmap. By default, browsers often handle this decoding synchronously on the main thread.

Because the main thread is also responsible for running JavaScript, calculating styles, computing layouts, and responding to user interactions, synchronous decoding introduces latency. If a browser encounters a large or complex image, the decoding process can lock the main thread, causing noticeable scroll stuttering, delayed button responses, and dropped animation frames (jank).

How decoding="async" Solves the Issue

Applying decoding="async" allows the browser to decouple image decoding from the main rendering loop:

<img src="large-graphic.webp" alt="Descriptive text" decoding="async" width="800" height="600">

When this attribute is present:

  1. Background Processing: The browser downloads the image and immediately transfers the decoding task to a background thread or asynchronous worker.
  2. Unblocked Main Thread: The main thread continues executing JavaScript, processing DOM updates, and handling user input without interruption.
  3. Independent Paint: Once the background thread completes decoding the bitmap, the browser updates the display list and paints the image onto the screen during the next available frame.

Performance Benefits

  • Smoother User Interactions: By removing decode computation from the main thread, the page remains fully responsive to user input, significantly optimizing the page's INP metric.
  • Elimination of Scroll Jank: Fast scrolling through galleries or content-heavy feeds is substantially smoother because incoming images do not stall the rendering engine.
  • Faster Time to Interactive: Web applications with heavy client-side JavaScript execution can initialize and run scripts without waiting for image decoding queues to resolve.

Distinguishing decoding="async" from loading="lazy"

It is common to confuse decoding with loading, but they control different stages of the image rendering pipeline:

  • loading="lazy" delays the network request (fetching) of an image until it approaches the viewport.
  • decoding="async" alters the processing mechanism (decompression) after the image data has already been fetched.

For non-critical images located below the fold, pairing both attributes provides optimal performance by deferring both the network impact and the CPU load.

Best Practices

  • Use for Non-Critical Images: Use decoding="async" on secondary images, infinite scroll feeds, and below-the-fold content.
  • Avoid on Largest Contentful Paint (LCP) Images: For the primary hero image or critical above-the-fold content, omit decoding="async" or use decoding="sync". Asynchronous decoding can introduce a slight delay before the decoded image paints, which may negatively impact your LCP score.
  • Always Provide Explicit Dimensions: Always include width and height attributes on the <img> tag to reserve layout space and prevent Cumulative Layout Shift (CLS) when the asynchronously decoded image finally renders.
