HTML Progress Indeterminate State Without Value

The HTML <progress> element is designed to convey the completion status of a task, operating in either a determinate or indeterminate state. When the value attribute is completely omitted, the browser automatically switches the element to an indeterminate state, representing a process of unknown duration. This article explains the technical mechanics behind this state, native browser rendering behaviors, styling capabilities, and its accessibility implications.

Mechanics of the Indeterminate State

Under the HTML specification, a <progress> element calculates its completion ratio by dividing the current value attribute by the max attribute. If the value attribute is absent, this calculation cannot occur. Consequently, the browser determines that the progress cannot be quantified and places the element into the indeterminate mode. The presence or absence of the max attribute does not affect this behavior; as long as value is missing, the element remains indeterminate.

Default Browser Rendering

Instead of displaying a static fill bar proportional to a percentage, browsers render an automated, looping animation to signal ongoing activity. While visual implementations vary across rendering engines, standard default behaviors include:

  • Chromium and WebKit (Chrome, Edge, Safari): Typically render a smooth, continuous sliding pulse or gradient that sweeps back and forth across the track.
  • Gecko (Firefox): Displays an animated block or bar sliding horizontally from left to right across the container.

These built-in animations provide immediate visual feedback to the user that a task is actively processing, without conveying a false metric of completion time.

Accessibility Mapping

The indeterminate state directly alters how assistive technologies interpret the element. By default, the <progress> element maps to the ARIA role of progressbar. When a value is present, the browser automatically assigns the aria-valuenow property to match it.

When value is omitted:

  • The aria-valuenow property is removed from the accessibility tree.
  • Screen readers announce the element as a progress bar in an indeterminate or busy state, informing users that an operation is underway without reading out a numerical percentage.
  • Developers should pair the element with an accessible label using aria-label, aria-labelledby, or an associated <label> to provide context on what operation is running.

Styling with CSS

The CSS :indeterminate pseudo-class allows developers to specifically target and style progress bars that lack a value. This pseudo-class is supported across all modern browsers.

progress:indeterminate {
  /* General styles for indeterminate state */
  accent-color: #0066cc;
}

Vendors also provide pseudo-elements to customize the internal rendering. For WebKit and Blink engines, ::-webkit-progress-bar targets the container track, while Firefox provides ::-moz-progress-bar. Because an indeterminate progress bar lacks a measurable value, standard fill pseudo-elements (such as ::-webkit-progress-value) do not apply, and custom animations are typically achieved by styling the background of the element itself using keyframe animations.

Dynamic State Transitions

Web applications often start a task without knowing its duration, such as initializing a network request, and later switch to determinate progress once file sizes or total steps are calculated. Dynamically setting the value property via JavaScript immediately transitions the element from the indeterminate state to the determinate state:

const progressBar = document.querySelector('progress');

// Switches from indeterminate to determinate at 25%
progressBar.value = 25;

// Removing the attribute returns it to indeterminate
progressBar.removeAttribute('value');

This flexibility makes the <progress> element a semantic and lightweight native solution for representing unmetered wait states.
