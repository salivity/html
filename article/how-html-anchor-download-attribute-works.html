How HTML Anchor Download Attribute Works

This article explains how the download attribute on an HTML anchor (<a>) tag instructs modern web browsers to save a linked resource directly to a user's local storage instead of navigating to it. It covers the underlying browser mechanics, how to define custom filenames, the role of HTTP headers, and critical security constraints such as the same-origin policy.

When a user clicks a standard hyperlink, the browser's default behavior is to request the resource specified in the href attribute and display it directly in the viewport if it supports the file type (such as an image, text file, or PDF). Adding the download attribute alters this workflow. It acts as an instruction to the browser engine to treat the target resource as an attachment, immediately opening a "Save As" dialogue or saving the file directly to the user’s default download directory.

The attribute can be implemented in two ways: as a boolean or with a value. If used as a boolean (e.g., <a href="report.pdf" download>), the browser automatically determines the filename from the resource's URL or the server's response headers. If a value is provided (e.g., <a href="report.pdf" download="Q3-Report.pdf">), the browser uses that value as the default suggested filename when saving the file.

Behind the scenes, the download attribute mimics the behavior of the HTTP Content-Disposition: attachment header. When the browser initiates the fetch request following a click, the presence of the attribute tells the network layer to bypass typical in-tab rendering. Instead, the incoming data stream is routed directly to the browser's download manager.

There are important security and origin constraints associated with this attribute:

  • Same-Origin Policy: The download attribute only works for same-origin URLs or resources using the blob: and data: schemes. If the link points to a different origin (a different domain, protocol, or port), the browser ignores the download attribute entirely to prevent malicious sites from triggering unauthorized downloads, and it falls back to standard navigation.
  • HTTP Header Precedence: If a server serves a resource with a Content-Disposition: inline header, modern browsers generally prioritize the download attribute for same-origin requests. However, if the server specifies a specific filename via Content-Disposition: attachment; filename="...", the server-defined filename may take precedence over the filename defined in the HTML download attribute depending on the browser.
  • JavaScript Dynamic Creation: Developers frequently combine the download attribute with dynamically generated Blob objects via JavaScript. By creating an object URL using URL.createObjectURL(blob), assigning it to a temporary anchor tag with a download attribute, and programmatically calling .click(), client-side data can be exported directly to the user's machine without any backend server interaction.
