Why Custom HTML Elements Require a Hyphen

The HTML Living Standard mandates that custom HTML elements, defined via the Web Components specification, must contain at least one hyphen in their tag name. This article explains the technical reasons behind this requirement, focusing on namespace isolation, forward compatibility for standard HTML, and how the browser's parser differentiates between built-in and user-defined elements.

Namespace Separation and Forward Compatibility

The primary reason for the hyphen requirement is to guarantee forward compatibility. Standard HTML tags defined by the WHATWG and W3C are single-word names or joined words without hyphens (such as <div>, <span>, <textarea>, or newer additions like <dialog> and <search>).

By reserving all hyphenated tag names exclusively for developers, browser vendors and standards bodies ensure they can introduce new standard elements in the future without breaking existing websites. If a developer were allowed to create a custom <calendar> or <tabs> element, a future native <calendar> or <tabs> tag would cause catastrophic naming collisions and unexpected behavior in legacy code. The hyphen permanently separates the standard HTML namespace from the user-defined namespace.

HTML Parser Differentiation

When an HTML parser encounters an opening tag, it must determine whether to instantiate a built-in element or treat it as a potential custom element.

According to the specification:

  • Standard Elements: Tags without a hyphen are matched against the list of known HTML elements. If unrecognized, the browser treats them as an instance of HTMLUnknownElement.
  • Custom Elements: Tags containing a hyphen are flagged as valid potential custom elements. The browser instantiates them as HTMLElement and checks the CustomElementRegistry to see if a matching custom definition has been registered via customElements.define().

This clear syntactic distinction allows the parser to optimize memory and lifecycle handling without performing unnecessary registry lookups on standard or misspelled built-in tags.

Specification Rules for Custom Element Names

To be considered a valid custom element name, a tag must adhere to specific rules set out by the HTML specification:

  1. Must include a hyphen: The name must contain at least one hyphen-minus character (-), such as <user-profile> or <super-button-v2>.
  2. Must start with a lowercase letter: The first character must be an ASCII lower alpha character (a-z).
  3. Cannot be a reserved name: Certain hyphenated names that already exist in SVG or MathML specifications are strictly forbidden. These include:
    • annotation-xml
    • color-profile
    • font-face
    • font-face-src
    • font-face-uri
    • font-face-format
    • font-face-name
    • missing-glyph

Attempting to register a custom element that lacks a hyphen or matches a reserved name will cause the browser to throw a DOMException of type NotSupportedError.
