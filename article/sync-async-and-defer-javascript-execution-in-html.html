Sync, Async, and Defer JavaScript Execution in HTML

When loading JavaScript in an HTML document, the execution strategy dictates how the browser balances reading HTML elements and running script code. The primary difference between synchronous, asynchronous (async), and deferred (defer) execution lies in whether the HTML parser is blocked during the script download and the exact moment the script is executed. Choosing the correct loading method is critical for optimizing page load speed, ensuring responsive user interfaces, and avoiding render-blocking issues.

Synchronous Script Execution (Default)

By default, scripts included via <script src="script.js"></script> are synchronous and render-blocking.

  • Parsing and Downloading: When the browser's HTML parser encounters a synchronous <script> tag, it immediately halts parsing the document.
  • Execution: The browser downloads the script file and executes it immediately before resuming the HTML parsing process.
  • Drawback: If a script takes time to download or execute, the user is left staring at an incomplete, unrendered page. This behavior often leads to poor core web vitals and sluggish performance.
  • Best Used For: Scripts that must run before any subsequent HTML can be safely rendered, though modern best practices discourage using default synchronous scripts in the document <head>.

Asynchronous Script Execution (async)

Adding the async boolean attribute—<script async src="script.js"></script>—tells the browser to download the script without stopping the HTML parsing process.

  • Parsing and Downloading: The script is downloaded in the background asynchronously while HTML parsing continues uninterrupted.
  • Execution: The moment the download completes, HTML parsing pauses immediately so the script can execute. Once execution finishes, HTML parsing resumes.
  • Execution Order: Scripts marked with async execute in the order they finish downloading, not the order they appear in the HTML.
  • Best Used For: Independent, third-party scripts that do not depend on the DOM being fully constructed or on other scripts running first, such as analytics trackers, ad networks, and telemetry tools.

Deferred Script Execution (defer)

The defer attribute—<script defer src="script.js"></script>—also downloads the script in the background, but delays execution until HTML parsing is entirely finished.

  • Parsing and Downloading: The script downloads asynchronously in parallel with HTML parsing without blocking the browser.
  • Execution: The script will not execute until the entire HTML document has been fully parsed, right before the DOMContentLoaded event fires.
  • Execution Order: Unlike async, scripts with defer maintain their relative execution order as declared in the document markup.
  • Best Used For: Scripts that manipulate the DOM or depend on other scripts, making it the preferred approach for core application logic placed in the <head> of an HTML document.

Quick Comparison

  • Synchronous: Blocks parsing during both download and execution. Execution order is strictly sequential.
  • async: Does not block parsing during download, but blocks parsing during execution. Execution occurs as soon as the file arrives, disregarding order.
  • defer: Does not block parsing during download and waits until HTML parsing is complete before executing. Execution order is preserved.
