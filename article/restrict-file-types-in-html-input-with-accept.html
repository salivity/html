Restrict File Types in HTML Input with Accept

The accept attribute in HTML <input type="file"> elements allows developers to specify which file formats a user can select from their device's file picker. By defining specific file extensions, MIME types, or broad media categories, this attribute streamlines the user experience by filtering out unsupported files directly within the operating system's file selection dialog. While it provides an essential first layer of user interface guidance, it functions strictly on the client side and does not replace server-side file validation.

How the accept Attribute Works

When applied to an <input type="file"> tag, the accept attribute provides a hint to the user's browser and operating system. When the user clicks the upload button, the native file dialog opens with filters applied, displaying only the files that match the criteria specified in the attribute or graying out incompatible files.

<input type="file" accept=".pdf">

Accepted Values and Syntax

The accept attribute accepts a comma-separated list of one or more file specifiers:

  1. Specific File Extensions: Valid file extensions must begin with a period (.). This tells the file picker to allow files with that specific extension.

    <input type="file" accept=".doc, .docx, .pdf">

  2. Standard MIME Types: You can specify complete MIME types (Multipurpose Internet Mail Extensions) to define valid formats.

    <input type="file" accept="application/pdf, image/png">

  3. Wildcard / Broad Media Types: To accept any file within a broad media category, use standard wildcard MIME types.

    • image/*: Permits any image format (e.g., JPEG, PNG, GIF, WebP).
    • audio/*: Permits any audio file format (e.g., MP3, WAV).
    • video/*: Permits any video file format (e.g., MP4, WebM).
    <input type="file" accept="image/*">

  4. Mixed Combinations: You can combine MIME types and explicit file extensions in the same attribute.

    <input type="file" accept="image/*, .pdf, .txt">

Mobile Device Behavior

On mobile operating systems (like iOS and Android), specifying media types such as image/* or video/* often changes how the system responds. Instead of only presenting a document browser, mobile platforms frequently offer direct access to the device camera, photo gallery, or voice recorder.

Client-Side Limitations and Security

The accept attribute is not a security measure. It acts purely as a user experience enhancement:

  • User Overrides: Most desktop file dialogs allow users to change the dropdown filter from "Custom Files" to "All Files (.)", allowing them to select any file on their hard drive regardless of the accept attribute.
  • Tampering: Malicious users can edit the HTML markup using browser developer tools or bypass the frontend entirely by sending direct POST requests with arbitrary files.

To ensure application security, all uploaded files must be thoroughly validated on the server side by checking MIME types, file signatures (magic bytes), and file sizes before storage or processing.
