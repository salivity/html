HTML Form Submit Event and How to Cancel It

The HTML <form> element automatically triggers a submit event whenever a user initiates an action to send form data to a server. In client-side web development, JavaScript frequently intercepts this event to validate inputs, handle data asynchronously via APIs, and prevent the browser from reloading the page. This article explains the exact mechanisms that cause a form to emit the submit event and details how to effectively cancel it using standard JavaScript methods.

How the submit Event Is Emitted

The submit event is fired directly on the <form> element, not on the individual buttons or inputs inside it. The browser emits this event under three primary conditions:

  1. Submit Buttons: When a user clicks an element capable of submitting the form, specifically <button type="submit">, <input type="submit">, or <input type="image">. If a <button> tag does not have an explicit type attribute defined, browsers treat it as type="submit" by default.
  2. Implicit Submission (The Enter Key): When a user presses the Enter key while focused on a text-based input field within the form. If the form contains at least one submit button or a single text input, the browser automatically triggers the submission process.
  3. The requestSubmit() Method: Calling the JavaScript method formElement.requestSubmit() programmatically emits the submit event exactly as if a user clicked a submit button. It runs form validation and triggers attached event listeners.

Note: Calling the traditional formElement.submit() method bypasses the submit event entirely, skips HTML5 constraint validation, and submits the form directly to the server without firing any event handlers.

How JavaScript Cancels the submit Event

When the submit event fires, the browser's default behavior is to package the form inputs into an HTTP request and navigate to the URL specified in the form's action attribute.

To prevent this navigation and handle the submission with JavaScript (such as via fetch or XMLHttpRequest), you must attach an event listener to the form and invoke the event.preventDefault() method.

Using addEventListener and preventDefault()

The standard and modern approach is to attach an event listener using addEventListener to the form element:

const form = document.querySelector('#myForm');

form.addEventListener('submit', function(event) {
  // Cancel the default browser submission
  event.preventDefault();

  // Custom logic: validation, AJAX/fetch requests, etc.
  console.log('Form submission intercepted.');
});

When event.preventDefault() is called:

  • The event's defaultPrevented attribute is set to true.
  • The browser halts its native submission process.
  • The current page does not reload, keeping the application state intact.

Conditional Cancellation

You can cancel the event conditionally, which is common in client-side validation workflows. If the data passes validation, the event is allowed to proceed; otherwise, it is cancelled:

const form = document.querySelector('#myForm');

form.addEventListener('submit', function(event) {
  const usernameInput = document.querySelector('#username');

  if (usernameInput.value.trim() === '') {
    // Stop form submission if validation fails
    event.preventDefault();
    alert('Username cannot be empty.');
  }
  // If the condition is not met, the form submits normally to the server
});

Legacy Inline Cancellation

In legacy codebases, inline event handlers in HTML cancel the submission by returning false:

<form onsubmit="return validateForm()">
  <!-- form controls -->
</form>

<script>
function validateForm() {
  if (/* validation fails */) {
    return false; // Cancels submission
  }
  return true; // Allows submission
}
</script>

While returning false works for inline handlers and properties like form.onsubmit = function() { return false; };, it does not work inside modern addEventListener() callbacks. For all modern applications, event.preventDefault() is the standard and reliable method for cancelling the submit event.
