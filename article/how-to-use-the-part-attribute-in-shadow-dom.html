How to Use the Part Attribute in Shadow DOM

The part attribute bridges the gap between style encapsulation and theme customization in Web Components. While the Shadow DOM inherently blocks external CSS to protect internal component structure, the part attribute allows component authors to selectively expose specific internal elements to the outer HTML document. By pairing this attribute with the CSS ::part() pseudo-element, external stylesheets can safely customize component visuals without piercing or breaking component encapsulation.

The Style Boundary Problem

Web Components use Shadow DOM to keep markup and styles self-contained. While this prevents global styles from inadvertently breaking the component, it also prevents developers from easily applying custom styles—such as adjusting background colors, borders, or typography to fit a broader site design. Previously, developers had to rely on CSS custom properties (variables), which are limited to property-by-property inheritance, or disable Shadow DOM entirely.

How the part Attribute Works

The part attribute is added directly to elements inside a component's shadow tree. It assigns a public identifier to an internal node, designating it as an intentionally customizable "part" of the component.

For example, inside a custom <user-profile> component's shadow tree, you might expose the avatar image and username text:

<div class="card">
  <img part="avatar" src="user.jpg" alt="User avatar" />
  <span part="username">Jane Doe</span>
</div>

Elements can also feature multiple part names separated by spaces, similar to CSS classes:

<button part="button primary">Submit</button>

Styling Exposed Elements via ::part()

Once an element has a part attribute, the outer document targets it using the ::part() pseudo-element appended to the custom element selector.

user-profile::part(avatar) {
  border-radius: 50%;
  border: 2px solid #007acc;
}

user-profile::part(username) {
  font-weight: bold;
  color: #333333;
}

The outer stylesheet can style the matched part using standard CSS properties, pseudo-classes (such as :hover or :focus), and state variations.

Key Benefits

  • Preserved Encapsulation: The component author controls the styling contract. Only elements explicitly marked with part are exposed, keeping the rest of the implementation details private.
  • Full Styling Flexibility: Unlike CSS custom properties, which require predefining a variable for every single styleable property, ::part() grants full CSS property access (e.g., margins, borders, animations, and typography) on the targeted element.
  • Structural Freedom: Internal DOM structure can change over time without breaking external themes, as long as the part attribute remains on the appropriate logical element.

Limitations

The ::part() selector cannot penetrate deeper into the shadow tree beyond the exposed element itself. Outer selectors cannot use child or sibling combinators with ::part() (for example, custom-element::part(button) > span is invalid). Additionally, styles applied via ::part() have lower specificity than inline styles defined within the shadow DOM, though they will override default component stylesheet rules.
