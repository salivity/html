HTML Referrerpolicy Attribute Explained

The referrerpolicy attribute in HTML controls how much referrer information—the URL of the originating page—is sent in the HTTP Referer header when a user navigates via a link or when a browser requests external assets like images and iframes. By setting this attribute, web developers can protect user privacy, prevent the leakage of sensitive URL paths or tokens, and selectively manage tracking data across origins.

Purpose and Context of the Referer Header

When a browser navigates to another page or loads external resources, it typically passes the URL of the current page to the destination server in an HTTP request header called Referer. While this header is useful for analytics, logging, and security verification, it can inadvertently expose sensitive data embedded in URLs, such as user session IDs, search queries, or internal site structures. The referrerpolicy attribute provides fine-grained control over this behavior directly within HTML markup.

Application to Elements

The referrerpolicy attribute can be applied to several HTML elements:

  • Anchor Links (<a> and <area>): Governs the referrer header sent to the target destination when a user clicks a link.
  • Images (<img>): Controls the referrer information sent to the image host when the browser fetches the image source (src).
  • Inline Frames (<iframe>): Determines what referrer details are provided to the embedded external site loaded inside the frame.
  • Other Elements: It also functions similarly on <link>, <script>, and <audio> or <video> tags.

Available Policy Values

The attribute accepts specific values that determine how strictly referrer data is withheld or exposed:

  • no-referrer: Completely omits the Referer header from all outgoing requests.
  • no-referrer-when-downgrade: Sends the full URL when navigating from HTTPS to HTTPS, but sends no referrer when navigating from HTTPS to HTTP. This was the traditional browser default.
  • origin: Only sends the scheme, host, and port (e.g., https://example.com/) instead of the full URL path, regardless of security level.
  • origin-when-cross-origin: Sends the full URL for same-origin requests, but truncates the referrer to only the origin for cross-origin requests.
  • same-origin: Sends the full URL for requests on the same origin, but sends no referrer header for cross-origin requests.
  • strict-origin: Sends the origin only when the security level remains the same or improves (HTTPS to HTTPS), but sends nothing over insecure connections (HTTPS to HTTP).
  • strict-origin-when-cross-origin: Sends the full URL for same-origin requests, sends only the origin for cross-origin requests over HTTPS, and sends no referrer to insecure destinations. This is the modern default behavior in most browsers.
  • unsafe-url: Always sends the full URL with all requests, regardless of security or origin. This value is strongly discouraged due to privacy and security risks.

Syntax Example

Applying the attribute is straightforward across elements:

<!-- For a link -->
<a href="https://external-site.com" referrerpolicy="strict-origin-when-cross-origin">External Site</a>

<!-- For an image -->
<img src="https://third-party.com/image.png" referrerpolicy="no-referrer" alt="External Image">

<!-- For an iframe -->
<iframe src="https://partner-portal.com" referrerpolicy="origin"></iframe>

Why Use referrerpolicy?

Using referrerpolicy is a critical web security and privacy practice. For external links, it prevents proprietary parameters in your URLs from leaking to third parties. For embedded media and iframes, applying no-referrer or origin stops third-party hosting providers from gathering detailed analytics on the exact pages your users are visiting, thereby minimizing tracking across the web.
