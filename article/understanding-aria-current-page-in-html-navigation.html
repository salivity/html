Understanding aria-current="page" in HTML Navigation

The aria-current="page" attribute is a WAI-ARIA specification used to inform assistive technologies, such as screen readers, that a specific link represents the current active page within a navigation menu. While sighted users rely on visual cues like background colors, borders, or bold text to identify where they are on a website, assistive technology requires programmatic markup to convey this context. This article explains how aria-current="page" works, why it is critical for web accessibility, and how to implement it correctly in both HTML and CSS.

The Purpose of aria-current="page"

When navigating a website, standard HTML markup provides no native way to indicate that a specific anchor (<a>) tag points to the document currently being viewed. Historically, developers relied solely on custom class names like .active or .current paired with visual styling.

While CSS classes create visual distinction, screen readers cannot interpret their semantic meaning. Without programmatic identification, a visually impaired user must deduce their location based on the page's heading rather than the navigation list itself. Adding aria-current="page" explicitly communicates state, prompting screen readers to announce words like "current page" alongside the link’s label.

Values of the aria-current Attribute

The aria-current attribute accepts several token values depending on the context of the container:

  • page: Indicates the current page within a set of pages (used on primary site navigation).
  • step: Indicates the current step within a multi-step flow or process indicator.
  • location: Indicates the current item within a visual flow or map.
  • date: Indicates the current date within a calendar or schedule.
  • time: Indicates the current time within a timetable.
  • true: A generic fallback indicating an active item in any generic set.
  • false: The default state, indicating the item is not active.

For website navigation menus, page is the most accurate and descriptive value.

Implementation Example

In a standard navigation bar, apply aria-current="page" only to the link corresponding to the current URL.

<nav aria-label="Main Navigation">
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about" aria-current="page">About Us</a></li>
    <li><a href="/services">Services</a></li>
    <li><a href="/contact">Contact</a></li>
  </ul>
</nav>

When a screen reader encounters the "About Us" link, it will announce it as "About Us, current page, link," immediately orienting the user.

Styling with CSS Using Attribute Selectors

Using aria-current="page" also simplifies CSS architecture by eliminating the need for duplicate visual class names like .active. You can target the attribute directly in your stylesheet:

/* Base navigation link styles */
nav a {
  color: #333333;
  text-decoration: none;
}

/* Style for the current page */
nav a[aria-current="page"] {
  color: #0056b3;
  font-weight: bold;
  border-bottom: 2px solid #0056b3;
}

This ensures that the visual style and the accessibility state are tied to the exact same source of truth in the DOM.

Best Practices

  • Single Current Item: Only one item within a specific navigation set should have aria-current="page" at any given time.
  • Single-Page Applications (SPAs): When client-side routing changes the view without a full page reload, ensure your JavaScript router moves the aria-current="page" attribute to the newly active link.
  • Contrast Requirements: When applying visual styles to the active link, ensure that the active state meets WCAG color contrast requirements (at least 3:1 against adjacent colors or a distinct non-color indicator like an underline).
