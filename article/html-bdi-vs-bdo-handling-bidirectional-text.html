HTML bdi vs bdo: Handling Bidirectional Text

The <bdi> and <bdo> HTML elements are specialized tools designed to manage bidirectional text when mixing left-to-right (LTR) scripts, like English or Spanish, with right-to-left (RTL) scripts, like Arabic or Hebrew. While web browsers typically rely on the Unicode Bidirectional Algorithm to determine text layout automatically, mixed-language content can often cause layout glitches, scrambled punctuation, and distorted reading orders. This article explains the distinct purposes of the <bdi> (Bi-Directional Isolation) and <bdo> (Bi-Directional Override) elements, detailing how and when to use each to maintain correct text presentation.

The Problem with Mixed Directional Text

Browsers handle text direction using the Unicode Bidirectional Algorithm. However, when user-generated or dynamic content is inserted into a page, the algorithm can become confused by surrounding text, punctuation, or numbers. For example, rendering an Arabic username next to an English sentence might cause trailing punctuation or surrounding text to jump to the wrong side of the phrase, breaking the visual flow. HTML provides <bdi> and <bdo> to resolve these structural issues.

The <bdi> Element: Bi-Directional Isolation

The <bdi> tag stands for Bi-Directional Isolation. Its primary purpose is to isolate a span of text from its surroundings so that its internal directionality does not affect, and is not affected by, the neighboring text.

Primary Use Cases

  • User-Generated Content: Displaying user names, comments, or profile information where the language direction is unpredictable.
  • Dynamic Data Feeds: Rendering content from databases or APIs where the text language may change dynamically.

How It Works

When you wrap text in <bdi>, the browser treats the contained text as an independent formatting context. The browser evaluates the direction of the text inside the <bdi> element on its own, preventing any RTL characters from corrupting the LTR flow of the surrounding sentence (or vice versa).

Example

<ul>
  <li>User <bdi>إيان</bdi>: 1st place</li>
  <li>User <bdi>John</bdi>: 2nd place</li>
</ul>

Without <bdi>, the Arabic name could cause the colon and rank indicator (: 1st place) to render improperly to the left of the name rather than to the right.

The <bdo> Element: Bi-Directional Override

The <bdo> tag stands for Bi-Directional Override. Its primary purpose is to explicitly override the Unicode Bidirectional Algorithm and force the enclosed text to render in a strictly defined direction, regardless of the characters it contains.

Primary Use Cases

  • Enforcing Specific Flow: Displaying text such as product codes, part numbers, or hexadecimal strings that require a strict visual order.
  • Specialized Visual Effects: Reversing the natural reading order of text deliberately.

How It Works

Unlike <bdi>, the <bdo> element requires the dir attribute to be explicitly set to either ltr (left-to-right) or rtl (right-to-left). The browser disregards the natural directionality of the internal characters and renders them sequentially according to the specified dir attribute.

Example

<!-- Forces English text to render from right to left -->
<p><bdo dir="rtl">This text will be displayed from right to left.</bdo></p>

<!-- Forces mixed content to render strictly left to right -->
<p><bdo dir="ltr">CODE-123-عربي</bdo></p>

Key Differences Between <bdi> and <bdo>

Feature <bdi> (Isolation) <bdo> (Override)
Purpose Isolates text to prevent layout corruption. Overrides character direction completely.
Direction Detection Automatically determines direction based on content. Requires manual direction via the dir attribute.
Best Used For Dynamic, user-submitted, or unknown text. Text requiring a forced, predictable reading order.
Required Attributes None. dir (ltr or rtl) is required.

Summary

Use <bdi> when you do not know the language or direction of the text beforehand and want to protect your surrounding layout from bidirectional layout bugs. Use <bdo> when you need absolute control to force text to render in a specific direction, bypassing the standard rules of the Unicode Bidirectional Algorithm.
