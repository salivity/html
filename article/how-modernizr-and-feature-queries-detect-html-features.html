How Modernizr and Feature Queries Detect HTML Features

This article provides an overview of how web developers historically and natively detect browser capabilities instead of relying on unreliable user-agent sniffing. It examines the JavaScript-driven techniques popularized by Modernizr—such as element creation, attribute reflection, and method verification—and explains how native CSS feature queries (@supports) fit into the feature-detection ecosystem to create resilient, progressively enhanced web applications.

The Need for Feature Detection

Historically, web browsers implemented HTML5 and CSS3 specifications at vastly different paces. Developers initially relied on browser sniffing via the navigator.userAgent string to guess compatibility. This practice frequently failed because user-agent strings were easily spoofed, altered by proxies, or updated without reflecting actual feature parity. Feature detection emerged as the standard alternative, focusing on testing whether a specific browser engine actually supports an API, element, or property before attempting to use it.

How Modernizr Detects HTML Features

Modernizr is a JavaScript utility library that runs tests on page load to determine browser capabilities. Because the browser does not natively expose a universal checklist of supported HTML elements, Modernizr employs several programmatic techniques to infer support.

1. In-Memory Element Creation and Property Checking

To test whether a new HTML5 element exists natively or is treated merely as an unrecognized generic element (an HTMLUnknownElement), Modernizr creates the element in memory without adding it to the live DOM:

var canvas = document.createElement('canvas');
var supportsCanvas = !!(canvas.getContext && canvas.getContext('2d'));

If the browser supports the element natively, the created element will have specific properties and prototype methods associated with its corresponding DOM interface (e.g., HTMLCanvasElement). If unsupported, the element falls back to a generic interface lacking these specialized properties.

2. Attribute and Method Reflection

Modernizr verifies new HTML attributes—such as placeholder, autofocus, or required on form controls—by instantiating the element and inspecting whether the attribute is exposed as a property on the object:

var input = document.createElement('input');
var supportsPlaceholder = 'placeholder' in input;

If the browser recognizes the HTML attribute, it reflects that attribute as a standard property on the DOM node.

3. HTML5 Input Type Validation

Browsers handle unknown type attributes on <input> elements by falling back to type="text". Modernizr exploits this behavior to verify support for specialized input types like color, date, or email:

  1. An <input> element is generated in JavaScript.
  2. The type attribute is set to the target value (e.g., input.setAttribute('type', 'date')).
  3. Modernizr sets a value that does not match standard text.
  4. It reads back the type property. If the browser does not support date, it automatically sanitizes or reverts input.type to 'text'.

4. Media Format Support and Execution

For media elements like <audio> and <video>, simply detecting the element is insufficient because format support (such as MP3, AAC, WebM, or H.264) varies by platform. Modernizr invokes native evaluation methods like canPlayType():

var audio = document.createElement('audio');
var supportsMp3 = !!(audio.canPlayType && audio.canPlayType('audio/mpeg;').replace(/^no$/, ''));

The method returns strings—"probably", "maybe", or "" (empty string for no support)—which Modernizr converts into boolean flags.

5. Exposing Results via Classes and Objects

Once tests complete, Modernizr attaches the results to a global Modernizr JavaScript object and appends corresponding utility classes to the root <html> element (e.g., .canvas or .no-canvas). This allows developers to conditionally branch JavaScript logic or apply fallback styling in CSS.

The Role of Feature Queries (@supports)

While Modernizr primarily relies on JavaScript to test both HTML and CSS, the CSS standard introduced native feature queries via the @supports rule and its JavaScript counterpart, CSS.supports().

Feature queries are natively parsed by the browser's CSS engine:

@supports (display: grid) {
  .container {
    display: grid;
  }
}

Technically, @supports detects CSS property-value pairs rather than HTML elements. However, it plays a complementary historical role:

  • Eliminating JavaScript Overhead: For styles tied to newer HTML elements (such as styling <dialog> or custom elements), native feature queries allow developers to apply rules without waiting for external libraries to execute and apply DOM classes.
  • JavaScript CSS Detection: Developers can use CSS.supports('selector(:has(*))') or CSS.supports('display', 'flex') within scripts, reducing reliance on libraries like Modernizr for layout and style-based capabilities.

Together, Modernizr's DOM-probing strategies and the standardization of native feature queries established modern progressive enhancement, allowing developers to safely deploy newer web standards while maintaining fallbacks for older browsers.
