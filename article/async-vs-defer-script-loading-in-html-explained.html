Async vs Defer: Script Loading in HTML Explained

When loading external JavaScript files in HTML, the async and defer attributes are boolean attributes used to prevent script loading from blocking the browser from parsing the HTML document. While both attributes allow the browser to download scripts in the background without halting the parsing process, they differ fundamentally in when the downloaded scripts are executed and whether execution order is preserved. Understanding this distinction is essential for optimizing web page performance and avoiding script dependency errors.

Default Script Loading (Without Attributes)

By default, when a browser encounters a standard <script src="..."> tag:

  1. HTML parsing immediately pauses.
  2. The browser fetches the script from the network.
  3. The browser executes the script immediately upon download.
  4. HTML parsing resumes only after the script finishes executing.

This default behavior causes render-blocking, which can significantly delay page load times and degrade user experience.

The async Attribute

The async attribute instructs the browser to download the script asynchronously in the background while continuing to parse the HTML document.

  • Execution Timing: The script executes the exact moment it finishes downloading. This means HTML parsing is paused during execution, whenever that happens to occur.
  • Execution Order: Independent and non-deterministic. If you load multiple async scripts, they will execute in whichever order they finish downloading, not the order they appear in the HTML.
  • Event Relationship: May execute before or after the DOMContentLoaded event, depending on file size and network speed.

Best Used For: Independent, third-party scripts that do not rely on the DOM or other scripts, such as Google Analytics, tracking pixels, and advertising tags.

The defer Attribute

The defer attribute also downloads the script asynchronously in the background while HTML parsing continues uninterrupted.

  • Execution Timing: The script does not execute immediately after downloading. Instead, execution is deferred until the HTML parsing is completely finished.
  • Execution Order: Deterministic. Scripts marked with defer are guaranteed to execute in the exact order they appear in the HTML source code.
  • Event Relationship: All defer scripts execute right after the DOM is fully built, immediately before the DOMContentLoaded event fires.

Best Used For: Scripts that depend on the full DOM tree to be available, or scripts that depend on one another (such as a library and its dependent plugins).

Summary of Differences

  • HTML Parsing Interruption: defer never interrupts parsing; async interrupts parsing only while executing.
  • Order Guarantee: defer maintains the order of execution; async executes on a "first to finish downloading" basis.
  • DOM Readiness: defer guarantees the DOM is fully parsed before running; async does not.
