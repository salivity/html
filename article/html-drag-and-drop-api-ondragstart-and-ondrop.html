HTML Drag and Drop API: ondragstart and ondrop

The HTML Drag and Drop API allows web applications to implement native, intuitive drag-and-drop interfaces using standard DOM event listeners and the DataTransfer object. This article examines how the lifecycle of a drag-and-drop operation functions, focusing specifically on how ondragstart initializes the operation and defines data, how intermediate events like ondragover permit drop targets, and how ondrop completes the interaction by extracting data and updating the application state.

The Drag and Drop Lifecycle

A drag-and-drop interaction consists of a source element, a dragged payload, and a target element. The browser orchestrates this interaction by firing sequential events as the user clicks, moves, and releases an element:

  1. Initiation: The user clicks and drags a source element (ondragstart).
  2. Traversal: The dragged element moves across potential targets (ondragenter, ondragover, ondragleave).
  3. Completion: The user releases the mouse over a valid target (ondrop), followed by cleanup on the source (ondragend).

Initiating the Drag with ondragstart

To make an HTML element draggable, it must have the attribute draggable="true". When a user begins dragging this element, the browser fires the dragstart event, handled by the ondragstart property or an event listener.

The primary responsibility of ondragstart is to populate the event.dataTransfer object. The dataTransfer object holds the data being dragged from the source to the drop zone.

Key actions inside ondragstart:

  • Set Payload: Call event.dataTransfer.setData(format, data) to specify the data format (e.g., 'text/plain', 'application/json') and the content.
  • Set Permitted Effects: Configure event.dataTransfer.effectAllowed (e.g., 'copy', 'move', 'link') to govern the visual feedback and allowed actions.
const item = document.getElementById('drag-item');

item.addEventListener('dragstart', (event) => {
  event.dataTransfer.setData('text/plain', event.target.id);
  event.dataTransfer.effectAllowed = 'move';
});

The Intermediary Step: ondragover

A drop target cannot trigger an ondrop event unless the browser default behavior is explicitly overridden. By default, browsers reject drop operations on most DOM elements.

To mark an element as a valid drop zone, you must attach an ondragover listener and invoke event.preventDefault():

const dropZone = document.getElementById('drop-zone');

dropZone.addEventListener('dragover', (event) => {
  event.preventDefault(); // Required to allow a drop
  event.dataTransfer.dropEffect = 'move';
});

Receiving Data with ondrop

When a user releases the dragged item over a valid drop target that has handled ondragover, the drop event fires on that target, captured via ondrop.

Key actions inside ondrop:

  • Prevent Default Handling: Call event.preventDefault() to stop the browser's default behavior, such as navigating to a URL if text or a link was dropped.
  • Retrieve Data: Access the data set during dragstart using event.dataTransfer.getData(format).
  • Mutate the DOM: Use the extracted data to manipulate the DOM, update component state, or trigger application logic.
dropZone.addEventListener('drop', (event) => {
  event.preventDefault();
  const draggedElementId = event.dataTransfer.getData('text/plain');
  const draggedElement = document.getElementById(draggedElementId);
  
  if (draggedElement) {
    dropZone.appendChild(draggedElement);
  }
});

Interaction Summary

The coordination between ondragstart and ondrop hinges on the shared dataTransfer context. ondragstart writes the necessary identifiers or values into the payload, the target's ondragover signals to the browser that an incoming drop is permitted, and ondrop reads the payload to finalize the interaction. Without ondragstart, no data is packaged; without ondragover preventing defaults, ondrop will never execute.
