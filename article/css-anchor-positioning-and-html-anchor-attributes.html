CSS Anchor Positioning and HTML Anchor Attributes

CSS Anchor Positioning allows developers to tether positioned elements to target anchors across a webpage without complex JavaScript calculations. When combined with the HTML anchor attribute, this specification creates an implicit binding directly in the markup, bypassing the need for manual CSS anchor naming and offering tighter semantic integration. This article examines how the HTML anchor attribute interacts with CSS Anchor Positioning, detailing implicit anchoring mechanics, precedence rules, and accessibility benefits.

The Mechanism of the HTML Anchor Attribute

The HTML anchor attribute allows an element to declaratively reference another element by referencing its id. For example:

<button id="menu-btn">Actions</button>
<div popover anchor="menu-btn">Menu Options</div>

When an element includes the anchor="menu-btn" attribute, the browser establishes an implicit anchor reference. In the CSS Anchor Positioning specification, an implicit anchor serves as the default target for anchor-based positioning properties without needing an explicit anchor-name declared on the target.

Implicit Anchor Resolution in CSS

Ordinarily, CSS Anchor Positioning requires two explicit CSS declarations:

  1. anchor-name: --my-anchor; on the anchor element.
  2. position-anchor: --my-anchor; on the positioned element.

When an element is bound via the HTML anchor attribute, the second declaration becomes unnecessary. The browser automatically assigns the referenced DOM element as the anchored element's default anchor reference.

Properties such as position-area or functions like anchor() resolve against this implicit anchor automatically:

[popover] {
  position: fixed;
  position-area: bottom span-right;
  margin: 0;
}

Because the implicit anchor is already set in the HTML markup, position-area: bottom span-right evaluates directly against #menu-btn. Similarly, positional functions resolve without parameters specifying an anchor name:

[popover] {
  position: fixed;
  top: anchor(bottom);
  left: anchor(left);
}

Cascade and Precedence Rules

CSS retains full control over positioning overrides. If both the HTML anchor attribute and CSS anchor properties are present, standard CSS precedence applies:

  • Default State: If position-anchor is set to auto (the default value), the element uses the implicit anchor defined by the HTML anchor attribute.
  • CSS Override: If a developer explicitly declares position-anchor: --custom-anchor; in the stylesheet, the CSS declaration overrides the HTML attribute for styling purposes. The element will physically align with --custom-anchor while maintaining its DOM-level association via HTML.
  • Explicit Function Targets: Supplying an explicit anchor name inside the anchor() function (e.g., top: anchor(--other-anchor bottom)) overrides both the HTML attribute and the position-anchor property for that specific property.

Semantic and Accessibility Implications

Pure CSS anchor positioning (anchor-name and position-anchor) only creates visual associations. Screen readers and assistive technologies do not infer a structural relationship between two elements solely based on CSS anchor properties.

The HTML anchor attribute bridges this gap. It creates a relationship within the DOM tree, particularly when paired with the Popover API or focus management routines. By pairing layout anchoring with HTML-level relationships, assistive technologies can identify that the positioned element is conceptually anchored to its invoker or target.

Scoping and DOM Boundaries

For an HTML anchor attribute to resolve properly:

  • The target element must exist within the same tree scope (i.e., inside the same document or the same Shadow DOM tree).
  • If the ID referenced in the anchor attribute cannot be found or is removed from the DOM, the implicit anchor evaluates to null.
  • When the implicit anchor fails to resolve, CSS fallback rules take over, typically causing the positioned element to position relative to its standard containing block.
