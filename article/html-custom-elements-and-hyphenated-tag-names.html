HTML Custom Elements and Hyphenated Tag Names

This article explains how HTML custom elements use hyphens in their tag names to define valid Web Components, the technical necessity behind this naming convention, and how the browser parses and registers these elements. By understanding the requirement for kebab-case syntax, developers can properly declare custom HTML elements, avoid naming collisions with future web standards, and successfully register custom DOM elements using the Web Components API.

Why Custom Element Names Require a Hyphen

The HTML specification explicitly requires that all autonomous custom element names contain at least one hyphen (-). This rule serves as a forward-compatible namespace boundary between standard HTML elements and developer-defined elements.

Because standard HTML tags (such as <div>, <article>, or <dialog>) are always single words without hyphens, the World Wide Web Consortium (W3C) and the WHATWG can safely introduce new native elements in future HTML specifications without breaking existing websites. If a tag contains a hyphen, the browser's HTML parser instantly recognizes it as a potential custom element rather than an unknown or standard HTML tag.

Naming Rules for Custom Elements

A valid custom element name must adhere to the following rules:

  1. Must contain a hyphen: The name must include at least one hyphen (e.g., user-profile, main-nav-bar).
  2. Must start with a lowercase ASCII letter: Characters prior to the first hyphen must begin with a-z.
  3. No uppercase letters: Custom element names are ASCII case-insensitive in HTML, but the custom elements specification requires lowercase characters when registering them.
  4. Reserved names: Certain names containing hyphens are explicitly reserved for internal or legacy reasons and cannot be used, such as annotation-xml, color-profile, font-face, missing-glyph, and all-caps.

How to Define and Register a Hyphenated Tag

Custom elements are defined using JavaScript and registered through the CustomElementRegistry interface using window.customElements.define().

1. Create the Class

Define a class that extends HTMLElement:

class UserCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
    this.shadowRoot.innerHTML = `<p>User Card Content</p>`;
  }
}

2. Register the Tag Name

Pass the hyphenated tag name and the class to customElements.define():

customElements.define('user-card', UserCard);

If you attempt to register a tag name without a hyphen (for example, customElements.define('usercard', UserCard)), the browser will throw a DOMException indicating that the name is not a valid custom element name.

3. Use the Tag in HTML

Once registered, the element can be used directly in HTML markup or created programmatically:

<user-card></user-card>
const element = document.createElement('user-card');
document.body.appendChild(element);

How Browsers Parse Hyphenated Tags

When the HTML parser encounters a hyphenated tag:

  • Before Registration: The browser instantiates it as an HTMLUnknownElement or an un-upgraded HTMLElement. It renders inline by default and preserves its children.
  • After Registration: When customElements.define() executes, the browser "upgrades" the element. It assigns the custom prototype, invokes the constructor, and triggers lifecycle callbacks such as connectedCallback().
