Guide to the HTML virtualkeyboardpolicy Attribute

The virtualkeyboardpolicy attribute in HTML controls how touch-screen devices display their on-screen virtual keyboards when an editable element receives focus. By allowing developers to switch between automatic display and manual control via JavaScript, this attribute prevents intrusive layout shifts and enables seamless integration for custom input interfaces.

Understanding the Attribute Values

The virtualkeyboardpolicy attribute can be applied to form controls like <input> and <textarea>, or any element using the contenteditable attribute. It accepts two distinct values:

  • auto (default): The browser automatically displays the on-screen keyboard as soon as the element gains focus, and hides it when the element loses focus. This is standard behavior across mobile browsers.
  • manual: The browser decouples element focus from the virtual keyboard. Tapping or focusing on the element will not automatically trigger the keyboard, leaving visibility control entirely to JavaScript.

Using virtualkeyboardpolicy="manual"

When set to manual, the element gains focus, but the device's native keyboard remains hidden until explicitly invoked. This is configured directly in the HTML:

<input type="text" virtualkeyboardpolicy="manual" id="custom-input" />

To display or hide the keyboard programmatically, developers use the VirtualKeyboard API through the navigator.virtualKeyboard interface:

const input =.getElementById('custom-input');

input.addEventListener('click', () => {
  if ('virtualKeyboard' in navigator) {
    navigator.virtualKeyboard.show();
  }
});

To dismiss the keyboard, call navigator.virtualKeyboard.hide().

Primary Use Cases

The virtualkeyboardpolicy attribute solves specific UI challenges where default mobile browser behavior degrades the user experience:

  1. Custom Keyboards and Keypads: Web applications providing on-screen numpads, custom math symbols, or specialized character pickers can prevent the native system keyboard from popping up and covering the custom UI.
  2. Canvas and WebGL Applications: In browser-based games or interactive canvases, text entry points can gain focus without triggering sudden viewport resizes or layout shifts.
  3. Complex Rich Text Editors: WYSIWYG editors can maintain user focus inside an editable area while displaying formatting toolbars or modal menus before deciding whether the native keyboard is required.

By shifting keyboard visibility from an automatic browser event to an intentional developer-driven action, the virtualkeyboardpolicy attribute provides fine-grained control over touch interactions in modern web forms.
