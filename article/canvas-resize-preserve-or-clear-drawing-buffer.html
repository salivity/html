Canvas Resize: Preserve or Clear Drawing Buffer

Resizing an HTML <canvas> element fundamentally alters how its visual contents are handled depending on whether you modify its internal dimensions or its CSS styling. Modifying the canvas's intrinsic width and height attributes clears the drawing buffer and resets the rendering context to its default state. Conversely, altering the dimensions using CSS preserves the buffer's contents but scales the existing bitmap, which often introduces blurriness or visual distortion.

Intrinsic Dimensions vs. CSS Styling

An HTML <canvas> element has two distinct sizing mechanisms:

  1. Drawing Buffer Dimensions (Intrinsic Size): Controlled by the width and height attributes directly on the HTML element or through DOM properties (e.g., canvas.width = 800). This defines the actual pixel resolution of the canvas's internal bitmap.
  2. Display Dimensions (CSS Size): Controlled via CSS rules or inline styles (e.g., canvas.style.width = '800px'). This defines the size of the element on the screen.

If you resize a canvas using only CSS, the browser preserves the drawing buffer completely. However, it scales the internal bitmap to fit the new CSS layout box, behaving identically to an <img> tag. This operation does not wipe the canvas, but expanding the CSS size causes pixelation or blurring.

Why Changing Intrinsic Dimensions Clears the Buffer

According to the HTML specification, setting either the width or height attribute on a <canvas> element—even to its current value—instantly resets the element's bitmap to transparent black (rgba(0, 0, 0, 0)).

In addition to clearing all drawn pixels, mutating the intrinsic dimensions resets the entire 2D rendering context state. This means:

  • Transformations (such as scale, rotate, or translate) revert to the identity matrix.
  • Clipping regions are removed.
  • Styling properties (like fillStyle, strokeStyle, lineWidth, and font) return to their initial default values.

How to Preserve the Drawing Buffer on Intrinsic Resize

Because the browser does not natively retain pixels when the intrinsic dimensions change, you must manually preserve and restore the content if dynamic resizing is required.

Method 1: Offscreen Canvas / In-Memory Copy

The most robust approach is copying the current canvas to an in-memory canvas before resizing, then redrawing it back onto the original canvas:

function resizeCanvas(canvas, newWidth, newHeight) {
  // Create an in-memory canvas to hold the current image
  const tempCanvas = document.createElement('canvas');
  tempCanvas.width = canvas.width;
  tempCanvas.height = canvas.height;
  
  const tempCtx = tempCanvas.getContext('2d');
  tempCtx.drawImage(canvas, 0, 0);

  // Resize the original canvas (this clears its contents and resets state)
  canvas.width = newWidth;
  canvas.height = newHeight;

  // Restore the previous content onto the resized canvas
  const ctx = canvas.getContext('2d');
  ctx.drawImage(tempCanvas, 0, 0);
}

Method 2: ImageData Snapshot

Alternatively, you can extract the raw pixel array using getImageData() and restore it with putImageData():

const ctx = canvas.getContext('2d');
const data = ctx.getImageData(0, 0, canvas.width, canvas.height);

canvas.width = newWidth;
canvas.height = newHeight;

ctx.putImageData(data, 0, 0);

While functional, this method ignores canvas transformations and is generally slower than drawImage() for larger resolutions because it operates on raw pixel data in JavaScript memory.

WebGL Considerations

For WebGL contexts (getContext('webgl') or getContext('webgl2')), changing the width or height attributes similarly destroys the underlying drawing buffer and recreates it to match the new dimensions.

Additionally, the WebGL context creation attribute preserveDrawingBuffer dictates whether the frame buffer is preserved between display compositing passes, but it does not prevent the buffer from being destroyed and reallocated when the intrinsic canvas dimensions are altered. When resizing in WebGL, you must update the viewport using gl.viewport(0, 0, newWidth, newHeight) and re-render the scene.
