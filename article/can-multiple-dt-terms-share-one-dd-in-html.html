Can Multiple dt Terms Share One dd in HTML?

This article explains whether multiple <dt> (description term) elements can share a single <dd> (description details) element within an HTML description list (<dl>). It covers the official HTML specification rules, provides valid code examples, highlights common practical use cases such as defining synonyms, and addresses accessibility considerations to ensure your markup is both standards-compliant and user-friendly.

According to the official HTML Living Standard maintained by WHATWG and the W3C specifications, multiple <dt> elements can share a single <dd> element. The specification defines a <dl> element as consisting of groups of one or more <dt> elements followed by one or more <dd> elements.

Basic Syntax and Example

When multiple terms share the exact same definition, you can place multiple <dt> elements consecutively before the corresponding <dd> element:

<dl>
  <dt>Soda</dt>
  <dt>Pop</dt>
  <dt>Carbonated soft drink</dt>
  <dd>A non-alcoholic, flavored beverage charged with carbon dioxide.</dd>

  <dt>Colour</dt>
  <dt>Color</dt>
  <dd>The visual perception based on the electromagnetic spectrum.</dd>
</dl>

In this example, "Soda", "Pop", and "Carbonated soft drink" are distinct terms tied to the same single description.

Common Use Cases

  • Synonyms and Regional Variations: When words with the same meaning vary by region, such as "lift" and "elevator."
  • Spelling Differences: Handling variations like American and British English (e.g., "organize" and "organise").
  • Aliases and Abbreviations: Defining a person, concept, or technical acronym alongside its full name.

Flexibility of the Description List

The relationship between <dt> and <dd> is not strictly one-to-one. The specification supports several combinations:

  • Many-to-One: Multiple <dt> terms followed by a single <dd> description.
  • One-to-Many: A single <dt> term followed by multiple <dd> elements (useful for terms with multiple distinct definitions).
  • Many-to-Many: Multiple <dt> terms followed by multiple <dd> descriptions.

Accessibility and Styling

Modern web browsers and screen readers natively handle multiple <dt> elements per <dd>. Assistive technologies correctly communicate that each term relates to the following description.

From a styling perspective, default browser styles will render <dt> elements as block-level elements on separate lines, with the <dd> indented beneath them. If you need to group terms and descriptions with custom wrappers for responsive CSS layouts or flexbox/grid styling, the HTML specification allows wrapping each term-description group in a <div> element:

<dl>
  <div class="term-group">
    <dt>Author</dt>
    <dt>Writer</dt>
    <dd>The creator of an original written work.</dd>
  </div>
</dl>

Using multiple <dt> elements with a single <dd> is fully valid, semantically correct, and supported across all standard web environments.
