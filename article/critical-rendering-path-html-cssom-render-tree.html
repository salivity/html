Critical Rendering Path: HTML, CSSOM, Render Tree

The Critical Rendering Path (CRP) is the sequence of browser operations that converts raw code into visible pixels on a screen. This article explains how the browser processes the Document Object Model (DOM) from HTML, generates the CSS Object Model (CSSOM) from stylesheets, and combines them into the Render Tree to prepare a webpage for the layout and painting stages.

1. Processing the Document Object Model (DOM)

The rendering process begins when the browser requests an HTML document and receives a stream of raw bytes over the network. The browser converts these bytes into the DOM tree through four sequential steps:

  1. Conversion: The browser reads the raw bytes from the disk or network and translates them into individual characters based on the specified file encoding (such as UTF-8).
  2. Tokenization: The browser parses the characters into distinct tokens defined by the HTML5 standard, such as <html>, <body>, <p>, and other tag identifiers.
  3. Lexing (Node Creation): The tokens are converted into "objects" or "nodes," which contain their properties and rules.
  4. DOM Construction: Because HTML tags can be nested inside other tags, the browser links the created nodes into a tree data structure that captures the parent-child and sibling relationships defined in the original markup.

The DOM construction is incremental. The browser can process chunks of HTML as they arrive from the network without waiting for the entire document to download.

2. Processing the CSS Object Model (CSSOM)

While parsing HTML, the browser encounters external stylesheets (<link rel="stylesheet">) or embedded styles (<style>). When it finds CSS resources, it must parse them to determine how to style the DOM elements.

Like HTML, CSS goes through conversion, tokenization, lexing, and tree construction:

  • Raw bytes are decoded into characters.
  • Characters are parsed into tokens representing selectors, properties, and values.
  • Tokens are turned into node objects containing styling rules.
  • The nodes are assembled into the CSSOM tree.

The CSSOM has a hierarchical structure because CSS styles cascade. A child element inherits computed styles from its parent unless a more specific rule overrides them.

Unlike DOM construction, CSSOM construction is not incremental. The browser cannot use a partial CSSOM because styles defined later in a stylesheet can override previously parsed rules. Therefore, CSS is considered render-blocking: the browser pauses the rendering pipeline until the entire CSSOM is fully constructed.

3. Assembling the Render Tree

Once the browser has built both the DOM and the CSSOM, it merges them into the Render Tree.

The Render Tree captures both the content and the computed visual styles for every visible element on the page. The process works as follows:

  1. Traversing the DOM: The browser starts at the root of the DOM tree and inspects every node.
  2. Filtering Non-Visual Elements: Non-visible elements are excluded from the Render Tree. This includes elements that are inherently non-visual (such as <head>, <script>, and <meta>) as well as elements hidden via CSS using display: none.
  3. Matching CSSOM Rules: For every visible DOM node, the browser finds the corresponding rules in the CSSOM and applies them to calculate the final computed styles.
  4. Emitting Render Nodes: Each visible node with its computed styles is added to the Render Tree.

Elements styled with visibility: hidden or opacity: 0 are still included in the Render Tree because they occupy physical space in the layout, unlike elements set to display: none.

Next Steps: Layout and Paint

The completion of the Render Tree marks the transition from parsing code to calculating geography and pixels:

  • Layout (Reflow): The browser uses the Render Tree to calculate the exact size and position of every visible element relative to the viewport.
  • Paint: The browser converts the calculated boxes into actual pixels on the screen, drawing text, colors, borders, and shadows across multiple layers before compositing them for the final display.
