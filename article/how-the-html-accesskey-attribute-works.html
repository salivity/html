How the HTML accesskey Attribute Works

This article provides an overview of the HTML accesskey global attribute, explaining how it designates keyboard shortcuts to web elements, how different operating systems and browsers interpret these shortcuts, and the practical considerations surrounding user experience and accessibility.

What is the accesskey Attribute?

The accesskey attribute is a global attribute in HTML that allows developers to assign a specific keyboard shortcut to a focusable or clickable element. When a user presses the assigned key combination on their keyboard, the browser either focuses the specified element (such as an <input> field) or activates it directly (such as clicking a <button> or <a> link).

Syntax and Basic Implementation

To assign a shortcut key, add the accesskey attribute directly to an HTML tag and set its value to the character you wish to designate:

<a href="/search" accesskey="s">Search</a>
<button type="submit" accesskey="x">Submit</button>
<input type="text" id="username" accesskey="u" />

You can also specify a space-separated list of characters. Browsers will search through the list from left to right and use the first key supported by the system:

<button accesskey="s a">Save</button>

In this example, if the shortcut for "s" is already reserved or unavailable on the user's system, the browser will attempt to use "a" instead.

How Browsers Activate the Shortcut

The user does not simply press the single letter assigned by the accesskey attribute. To prevent accidental triggers while typing in text areas, web browsers require a combination of modifier keys alongside the defined character.

The required modifier keys vary depending on the operating system and the specific browser:

  • Windows:
    • Chrome / Edge: Alt + [key]
    • Firefox: Alt + Shift + [key]
  • macOS:
    • Chrome / Safari / Firefox: Ctrl + Option + [key]
  • Linux:
    • Firefox: Alt + Shift + [key]
    • Chrome: Alt + [key]

When the full combination is pressed, the browser executes the default action for that element:

  • Links (<a>): Navigates to the URL or triggers attached click listeners.
  • Buttons (<button> or <input type="button">): Triggers the click action or form submission.
  • Form Fields (<input>, <textarea>): Places focus into the field, enabling immediate data entry.

Important Considerations and Limitations

While accesskey offers a native way to implement shortcuts, it comes with notable usability and accessibility challenges:

  1. Shortcut Conflicts: The assigned character may conflict with existing browser shortcuts, operating system hotkeys, or screen reader commands (such as those in NVDA or JAWS).
  2. Lack of Native Discovery: Browsers do not inherently display assigned accesskey values to the end user. Developers must manually document or visually indicate shortcuts (such as underlining the corresponding letter in the label).
  3. International Keyboards: Certain characters may not be easily accessible on non-standard or localized keyboard layouts, leading to inconsistencies across different user regions.
