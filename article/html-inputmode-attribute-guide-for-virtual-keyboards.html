HTML inputmode Attribute Guide for Virtual Keyboards

The inputmode attribute in HTML allows developers to specify which virtual keyboard layout to display on touch-enabled devices when a user focuses on an input field or textarea. By matching the keyboard layout to the expected data format, inputmode streamlines data entry, reduces user errors, and creates a smoother mobile user experience without altering the underlying data validation rules.

How inputmode Works

When a user taps an input element on a mobile device or tablet, the operating system summons an on-screen virtual keyboard. By default, the browser guesses which keyboard to display based on the type attribute (such as type="text", type="number", or type="email").

The inputmode attribute provides direct control over this behavior. Unlike the type attribute, inputmode does not affect how the browser parses, validates, or submits form data; it exclusively governs the visual layout of the soft keyboard.

Why Use inputmode Instead of the type Attribute?

Using type="number" has well-documented usability issues for data like credit card numbers, ZIP codes, and two-factor authentication (2FA) PINs:

  • It often displays unnecessary stepper arrows (up/down buttons).
  • It allows mouse wheel scrolling to inadvertently increment or decrement values.
  • It strips leading zeros (e.g., changing 0123 to 123).

By pairing type="text" with inputmode="numeric", you can trigger a 0–9 keypad on mobile devices while retaining the text input's ability to preserve leading zeros, disable stepper controls, and prevent numerical alteration.

Available inputmode Values

The inputmode attribute accepts the following standard values:

  • numeric: Displays a number keypad containing digits 0 through 9. This is ideal for PINs, credit card numbers, postal codes, and phone extension codes.
  • decimal: Displays a numeric keyboard that includes the user's localized decimal separator (either a period or a comma). This is best suited for monetary amounts, measurements, and percentages.
  • tel: Displays a standard telephone keypad containing numbers 0–9, the asterisk (*), and the hash symbol (#). Useful for phone numbers when full phone validation behavior from type="tel" is not desired.
  • email: Displays an alphanumeric keyboard optimized for email addresses, typically offering prominent @ and period (.) keys.
  • url: Displays an alphanumeric keyboard optimized for web addresses, typically highlighting the forward slash (/) and common domain suffixes like .com.
  • search: Displays a standard text keyboard with the "Enter" or "Return" key replaced or styled as a "Search" button.
  • text: Displays the standard, default text input keyboard for the user’s current locale.
  • none: Prevents the operating system's virtual keyboard from appearing altogether. This is useful for web applications that implement their own custom on-screen keypad or interactive canvas-based inputs.

Example Implementation

<!-- One-Time Passcode (OTP) input -->
<label for="otp">Enter 6-Digit Code:</label>
<input 
  id="otp" 
  type="text" 
  inputmode="numeric" 
  pattern="[0-9]{6}" 
  autocomplete="one-time-code" 
/>

<!-- Price or invoice amount input -->
<label for="amount">Payment Amount:</label>
<input 
  id="amount" 
  type="text" 
  inputmode="decimal" 
  placeholder="0.00" 
/>

Browser Support and Fallbacks

The inputmode attribute is supported across all modern mobile browsers on iOS and Android. If a browser does not recognize the attribute, it simply ignores it and falls back to the default keyboard specified by the input's type attribute, making it a safe, progressive enhancement for any web form.
