How Void Elements Work in HTML

This article provides an overview of void and self-closing elements in HTML, detailing what they are, how browsers interpret them, and the rules governing their syntax. You will learn the mechanical differences between standard elements and void elements, review common examples, and understand how HTML5 treats self-closing slashes.

What Are Void Elements?

In HTML, a void element is an element that cannot contain any child nodes, such as nested HTML tags or plain text. Because they cannot have content, they never require a closing tag (such as </img> or </br>).

The standard HTML specification explicitly defines which elements are void. When an HTML parser encounters a void element, it immediately knows that the element has finished its declaration and moves directly to parsing the next node in the document tree.

Common Void Elements

The HTML specification designates a specific set of tags as void. The most frequently used include:

  • <meta>: Sets document metadata.
  • <link>: Connects external resources like stylesheets or icons.
  • <img>: Embeds image assets.
  • <input>: Creates interactive controls in web forms.
  • <br>: Produces a line break in text.
  • <hr>: Represents a thematic break between paragraphs.
  • <source>: Specifies media resources for <picture>, <audio>, or <video>.

Any attempt to place text or other tags inside these elements is invalid HTML.

The Self-Closing Slash in HTML5

In XHTML (an older, XML-based variation of HTML), every tag without content required a trailing slash to close itself, formatted as <br /> or <img />.

In modern HTML5, the trailing slash is entirely optional on void elements. The browser’s parser recognizes void elements strictly by their tag name, not by the presence of a slash. As a result, both of the following examples are parsed identically:

<input type="text" name="username">
<input type="text" name="username" />

The slash is preserved in the HTML5 specification primarily to support backward compatibility with XHTML codebases and modern JSX or XML preprocessors.

Non-Void Elements Cannot Be Self-Closed

A critical rule in HTML parsing is that non-void elements cannot be turned into self-closing tags using a trailing slash. If an element is capable of holding content (such as <div>, <span>, <script>, or <textarea>), writing <div /> will not close the element.

The HTML5 parser ignores the slash on non-void elements and treats the opening tag as remaining open. This causes subsequent elements to become unintentionally nested inside it, leading to unexpected layout and rendering errors. Non-void elements must always use explicit closing tags, such as <div></div> or <script></script>, even when left empty.
