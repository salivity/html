Understanding the crossorigin Attribute in HTML

The crossorigin attribute in HTML tells the browser how to handle Cross-Origin Resource Sharing (CORS) when fetching external assets like images, scripts, fonts, and media. By default, browsers load cross-origin resources without CORS validation, which restricts programmatic access to their content for security reasons. Applying the crossorigin attribute forces the browser to make a formal CORS request, allowing web applications to safely access and manipulate external data—such as reading pixel data from a canvas or capturing detailed script error logs—provided the remote server grants the proper permissions.

What is the crossorigin Attribute?

When an HTML element loads a resource from a different origin (domain, protocol, or port), the browser typically treats that resource as opaque. The crossorigin attribute changes this behavior by instructing the browser to include CORS headers in the HTTP request.

This attribute is supported on several HTML elements:

  • <img>
  • <audio>
  • <video>
  • <script>
  • <link> (particularly for stylesheets, fonts, and preloaded assets)

Attribute Values

The crossorigin attribute accepts two primary keyword values:

1. anonymous

Setting crossorigin="anonymous" (or simply writing crossorigin as a boolean attribute) sends a CORS request without transmitting user credentials such as HTTP cookies, TLS client certificates, or HTTP authentication.

  • Request Behavior: The browser sends an Origin HTTP header with the request.
  • Server Requirement: The server must respond with an Access-Control-Allow-Origin header that matches the requesting origin or uses the wildcard *.
  • Credential Handling: Even if the user has an active session or cookies for the external domain, the browser will not send them.

2. use-credentials

Setting crossorigin="use-credentials" tells the browser to include user credentials (cookies, certificates, and authentication headers) along with the cross-origin request.

  • Request Behavior: The browser sends the Origin header and passes all associated credentials.
  • Server Requirement: The server must explicitly allow credentials by responding with Access-Control-Allow-Credentials: true and an Access-Control-Allow-Origin header that explicitly specifies the requesting origin. A wildcard * is not permitted when credentials are used.

How the Request Flow Works

  1. The Request: When the browser encounters an element with crossorigin, it attaches the Origin header containing the domain of the current page.
  2. Server Evaluation: The target server inspects the Origin header and determines whether to allow the request based on its CORS configuration.
  3. The Response:
    • If allowed, the server returns the requested resource alongside the appropriate Access-Control-Allow-* headers. The browser exposes the resource fully to client-side APIs.
    • If the server fails to include the appropriate CORS headers, the browser blocks access to the resource and logs a CORS policy error in the developer console.

Primary Use Cases

Unlocking <canvas> Pixel Access

When an external image is drawn onto an HTML <canvas>, the canvas becomes "tainted" by default, preventing methods like toDataURL(), toBlob(), or getImageData() from functioning. Adding crossorigin="anonymous" to the <img> tag lets the canvas read the raw pixel data, provided the image host sends correct CORS headers.

Detailed JavaScript Error Reporting

Scripts loaded from a third-party CDN hide their internal errors, logging generic messages like "Script error." in window.onerror to prevent cross-site data leakage. Adding crossorigin="anonymous" to the <script> tag allows the browser to capture full stack traces and line numbers for remote scripts.

Preloading Web Fonts

Web fonts fetched via <link rel="preload" as="font" ...> must always use the crossorigin attribute (even if the font is on the same domain). Font fetching specifications mandate that fonts be fetched using anonymous CORS mode; omitting the attribute causes the browser to fetch the resource twice.
