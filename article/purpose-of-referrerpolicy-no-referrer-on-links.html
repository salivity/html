Purpose of referrerpolicy="no-referrer" on Links

The referrerpolicy="no-referrer" attribute on sensitive HTML outbound links instructs the browser to completely omit the HTTP Referer header when a user navigates to an external destination. By stripping this header, website owners prevent external servers from discovering the URL of the origin page. This measure is essential for safeguarding user privacy, preventing the accidental leakage of sensitive query parameters or session data, and shielding internal system structures from third-party observation.

How the Referer Header Works

By default, web browsers send an HTTP Referer header whenever a user clicks a hyperlink. This header tells the destination server the exact address of the page where the user clicked the link.

While this mechanism helps analytics tools track traffic sources, it creates significant security and privacy vulnerabilities when the originating page contains sensitive information.

Preventing Credential and Token Leaks

Many web applications include sensitive information within URLs, particularly in query strings. Examples include:

  • Password reset tokens (e.g., https://example.com/reset-password?token=xyz123)
  • Email verification links
  • Session identifiers
  • Personally Identifiable Information (PII), such as email addresses or usernames

If a user clicks an outbound link on any of these pages without restrictions, the external website receives the full URL in its server logs. Third parties can potentially capture these tokens to hijack accounts or extract private user details. Setting referrerpolicy="no-referrer" ensures that the destination server receives no information about the originating URL.

Protecting Internal URL Structures

Internal applications, such as intranets, admin dashboards, or staging environments, often use URL paths that reveal the company's internal network architecture or software stack (e.g., https://corp-internal.net/admin/users/edit/492).

If an administrator clicks an external link within that dashboard, the destination site can log that URL. Applying referrerpolicy="no-referrer" prevents the exposure of internal domains, directory structures, and private corporate systems to external parties.

Implementation

To apply the policy to an individual link, add the attribute directly to the anchor tag:

<a href="https://external-example.com" referrerpolicy="no-referrer">Visit External Site</a>

When clicked, the browser sends the HTTP request to external-example.com with an empty or absent Referer header, treating the visit as direct traffic.

Differences Between referrerpolicy and rel="noreferrer"

Both referrerpolicy="no-referrer" and rel="noreferrer" accomplish the same primary goal of suppressing the Referer header. However, referrerpolicy is part of the newer W3C Referrer Policy specification, allowing consistent referrer handling across multiple HTML elements—such as <a>, <area>, <img>, <iframe>, and <link>.

For maximum backward compatibility with older browsers, developers often combine them:

<a href="https://external-example.com" rel="noreferrer" referrerpolicy="no-referrer">Visit External Site</a>
