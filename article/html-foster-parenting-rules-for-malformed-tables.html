HTML Foster Parenting Rules for Malformed Tables

Foster parenting is a browser error-recovery mechanism defined in the HTML specification to handle invalid content placed directly inside table elements. When an HTML parser encounters non-table markup—such as bare text or generic block elements—inside a table structure, it does not discard the content or leave it inside the invalid context. Instead, it activates foster parenting to move the misplaced nodes to a valid location in the Document Object Model (DOM), typically directly before the table element itself.

Triggers for Foster Parenting

The HTML parser operates as a state machine using insertion modes. Foster parenting is triggered primarily when the parser is in the following insertion modes:

  • "in table"
  • "in table body"
  • "in row"
  • "in select in table"

While in these modes, the parser strictly expects table-related tags such as <caption>, <colgroup>, <thead>, <tbody>, <tfoot>, <tr>, <td>, and <th>. Foster parenting is initiated when the parser encounters:

  1. Character Tokens: Any non-whitespace character that appears directly inside <table>, <tbody>, <thead>, <tfoot>, or <tr>. (Pure whitespace characters are processed differently depending on context).
  2. Disallowed Start Tags: Any start tag other than valid table elements (for instance, <div>, <p>, <span>, <h1>, or form controls).
  3. Disallowed End Tags: Stray or mismatched closing tags that do not belong to the current table context.

When any of these tokens appear, the parser sets its internal foster parenting flag to true and runs the appropriate insertion algorithm.

The Foster Parent Location Algorithm

Under the WHATWG specification, the parser determines the target insertion location for foster-parented nodes using the following sequence:

  1. Locate the Table: The parser inspects the stack of open elements and identifies the last element that is a table element.
  2. Identify the Template Exception: If there is a template element on the stack of open elements that is more recent than the last table element (or if there is no table element), the foster parent is the template element's template contents (a DocumentFragment), and the node is appended there.
  3. Determine Parent Node: If no template takes precedence, the parser examines the parent node of the identified table element:
    • Table Has a Parent: If the table has a parent node in the DOM tree, the foster parent target is that parent node, and the insertion point is set immediately before the table element.
    • Table Has No Parent: If the table has no parent node (such as when dynamically constructed or in an incomplete parse tree), the foster parent target is the element immediately preceding the table element in the stack of open elements. The node is appended to the end of that element.

Once the insertion position is calculated, the node is constructed and inserted into that position, and the parser resets the foster parenting flag to false.

Parsing Example

Consider this malformed HTML fragment:

<table>
  <div>Content</div>
  <tr>
    <td>Cell</td>
  </tr>
</table>

During execution:

  1. The parser creates the <table> element and switches to the "in table" mode.
  2. It encounters the <div> start tag, which is invalid inside a table.
  3. The parser enables foster parenting and locates the <table> element's parent (for example, the <body>).
  4. The <div>Content</div> node is inserted into the <body>, immediately before the <table>.
  5. The parser resumes normal processing for the subsequent <tr> and <td> elements within the table structure.

The resulting DOM representation mirrors the following structure:

<div>Content</div>
<table>
  <tbody>
    <tr>
      <td>Cell</td>
    </tr>
  </tbody>
</table>

Special Cases

Whitespace Characters

Inter-element whitespace inside a table does not trigger foster parenting. Instead, leading whitespace is either ignored or collected and inserted into the table’s current insertion point once valid content is processed. Only non-whitespace text triggers foster parent insertion before the table.

Active Formatting Elements

If foster-parented content includes formatting tags (such as <b> or <i>) that remain open across table boundaries, the Adoption Agency Algorithm interacts with the foster parenting rules. Formatting tags opened prior to an invalid table element will reconstruct their formatting wrappers inside the foster-parented location to ensure styling consistency without producing an invalid DOM hierarchy.
