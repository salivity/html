HTML Meter Attributes: Value, Low, High, Optimum

The HTML <meter> element represents a scalar measurement within a known range or a fractional value, such as disk usage, battery level, or test scores. To properly contextualize these measurements, the element relies on key attributes: value, low, high, and optimum. Understanding these attributes allows you to divide a meter into distinct performance ranges—such as low, medium, and high—and automatically style the meter based on whether the current measurement represents a favorable or unfavorable state.

The value Attribute

The value attribute defines the current numerical reading of the meter.

  • It must be a valid floating-point number.
  • If a min and max are set, value should logically fall between them (if omitted, the range defaults to 0 to 1).
  • If the value attribute is missing or invalid, the browser defaults to 0.

The low Attribute

The low attribute establishes the upper bound of the "low" range of the gauge.

  • Any reading between min and low is treated as falling within the low segment.
  • The value must be greater than or equal to min, and less than or equal to both high and max.

The high Attribute

The high attribute defines the lower bound of the "high" range of the gauge.

  • Any reading between high and max is treated as falling within the high segment.
  • The value must be greater than or equal to low, and less than or equal to max.

Together, the low and high attributes divide the meter into three distinct segments:

  1. Low segment: From min to low
  2. Medium segment: From low to high
  3. High segment: From high to max

The optimum Attribute

The optimum attribute designates the ideal numeric value within the overall range. Its primary role is to tell the browser which of the three segments is considered the best state.

Browsers use this information to determine the meter's color (typically green for optimal, yellow/orange for sub-optimal, and red for critical):

  • High is best: If optimum is set higher than high (e.g., battery life), the high segment is optimal (green), the middle segment is acceptable (yellow), and the low segment is critical (red).
  • Low is best: If optimum is set lower than low (e.g., CPU temperature or disk usage), the low segment is optimal (green), the middle segment is acceptable (yellow), and the high segment is critical (red).
  • Middle is best: If optimum is set between low and high, the middle segment is optimal, and moving toward either extreme triggers warning or critical states.

Example Usage

<!-- High value is best: Battery percentage -->
<meter min="0" max="100" low="20" high="80" optimum="90" value="15"></meter>

<!-- Low value is best: Server load percentage -->
<meter min="0" max="100" low="30" high="70" optimum="10" value="85"></meter>

In the first example, the value 15 is below the low threshold (20), resulting in a critical (red) visual state because the optimum is set high. In the second example, the value 85 exceeds the high threshold (70), triggering a critical state because the optimum is low.
