How to Avoid Tainted Canvas with Crossorigin

When loading images from external domains onto an HTML canvas, browsers enforce strict security boundaries to protect sensitive user data. Without proper permissions, drawing an external image marks the canvas as "tainted," which permanently blocks any attempt to export or read back its pixel data. This article explains what causes a tainted canvas, how the crossorigin attribute resolves this issue through Cross-Origin Resource Sharing (CORS), and how to implement it correctly.

What Is a Tainted Canvas?

A canvas becomes tainted the moment it renders an image, SVG, or video hosted on a different origin (domain, protocol, or port) without explicit CORS authorization. The browser allows the visual rendering of the media, but it treats the data as potentially untrusted.

Once a canvas is tainted, calling data-extraction methods will fail immediately by throwing a SecurityError. The affected methods include:

  • canvas.toDataURL()
  • canvas.toBlob()
  • context.getImageData()

This restriction prevents malicious scripts from loading third-party images (such as private user content from an authenticated session on another site) and reading raw pixel data to steal information.

The Function of the crossorigin Attribute

The crossorigin attribute tells the browser to request the external resource using standard CORS mechanisms rather than a standard, unauthenticated GET request.

When you attach crossorigin to an <img> element or set the crossOrigin property in JavaScript, the browser adds an Origin header to the outgoing HTTP request. If the server hosting the image allows access, it replies with an Access-Control-Allow-Origin response header. Upon verifying this header, the browser considers the image clean and allows the canvas to remain untainted after drawing it.

Attribute Values

The crossorigin attribute accepts two values:

  • anonymous: The browser sends a CORS request without credentials. Cookies, HTTP authentication, and client-side SSL certificates are not transmitted to the cross-origin server. If the attribute is defined without a value (e.g., <img crossorigin src="...">), it defaults to anonymous.
  • use-credentials: The browser sends a CORS request that includes credentials (such as cookies or authorization headers). The remote server must respond with Access-Control-Allow-Credentials: true and specify your exact origin in Access-Control-Allow-Origin rather than using a wildcard (*).

Implementation in JavaScript

To load an external image into a canvas dynamically without tainting it, set the crossOrigin property before assigning the src attribute:

const canvas = document.getElementById('myCanvas');
const ctx = canvas.getContext('2d');

const img = new Image();
img.crossOrigin = 'anonymous'; // Request CORS access

img.onload = () => {
  ctx.drawImage(img, 0, 0);
  
  // This will now execute safely without throwing a SecurityError
  const dataURL = canvas.toDataURL('image/png');
};

img.src = 'https://example.com/image.png';

Setting crossOrigin before src ensures the browser initiates the network request with the appropriate CORS headers from the start.

Server Requirements

The crossorigin attribute cannot bypass security restrictions on its own. For the canvas to remain untainted, the remote image server must be configured to return valid CORS headers:

Access-Control-Allow-Origin: *

If the server does not return this header, or if it rejects the origin, the image will fail to load entirely, resulting in a CORS network error. The image must either be served with valid CORS headers or hosted on the same origin as the application to allow pixel manipulation on a canvas.
