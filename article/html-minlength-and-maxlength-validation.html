HTML minlength and maxlength Validation

The minlength and maxlength attributes in HTML provide built-in client-side validation to constrain the number of characters a user can enter into text-based input fields. Working together, this attribute pair defines an acceptable character length range for form data, enforcing lower and upper boundaries without requiring custom JavaScript. This article explains how these attributes function individually, how they interact, and how browsers handle their validation constraints.

The Function of maxlength

The maxlength attribute sets the upper limit on the number of characters permitted in an input element or <textarea>.

Unlike standard validation warnings, browsers typically enforce maxlength proactively by preventing the user from typing or pasting characters beyond the defined limit. If a field specifies maxlength="10", the browser simply truncates pasted text at 10 characters and stops accepting new keystrokes once 10 characters are reached. Because of this behavior, a field rarely triggers a standard "too long" submission error under normal user interaction.

The Function of minlength

The minlength attribute sets the lower boundary for the number of characters required.

Unlike maxlength, the browser does not block keystrokes when enforcing minlength. Instead, it allows users to freely type and edit their input. The constraint is checked when the user attempts to submit the form or when JavaScript queries the element's validity. If the input contains text but fails to meet the specified minimum character count, the browser marks the input as invalid, prevents submission, and displays a localized validation message.

Interaction Between the Two Attributes

When used together, minlength and maxlength establish a strict length window:

<label for="username">Username (5 to 15 characters):</label>
<input type="text" id="username" name="username" minlength="5" maxlength="15" required>

In this scenario:

  • A user cannot type more than 15 characters.
  • A user cannot submit fewer than 5 characters.
  • Valid submissions must fall between 5 and 15 characters, inclusive.

Key Behavioral Rules and Nuances

  1. Empty Fields: If an input field is empty, minlength is not violated unless the required attribute is also present. This allows optional fields to remain empty while still enforcing a minimum length if the user chooses to fill them out.
  2. Character Counting: Length is measured in UTF-16 code units. Most standard alphanumeric characters count as one character, but certain multi-byte characters, such as some emojis or complex symbols, count as two units.
  3. The Constraint Validation API: The browser reflects the status of these attributes in JavaScript through the validity property. Failing minlength sets validity.tooShort to true, while exceeding maxlength programmatically sets validity.tooLong to true. Both conditions set validity.valid to false.
