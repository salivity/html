How og:image Configures Thumbnail Previews

The Open Graph og:image meta tag is an HTML element that specifies the graphic asset social networks, messaging platforms, and search engines display when a webpage URL is shared. By declaring this tag within an HTML document's <head> section, developers instruct web crawlers to fetch and render a dedicated preview card, directly controlling how the page visually appears across external platforms like Facebook, LinkedIn, Slack, and Discord.

The Basic Syntax and Placement

The og:image tag resides in the <head> of an HTML document. It uses the property and content attributes:

<head>
  <meta property="og:image" content="https://example.com/assets/preview.jpg" />
</head>

Web scrapers require the content attribute to contain a fully qualified, absolute URL (including https://). Relative paths often fail to resolve properly on third-party platforms, leading to broken or missing previews.

How Platforms Process the Tag

When a user pastes a URL into a platform that supports the Open Graph protocol:

  1. Scraping: The platform sends an automated user agent (bot) to fetch the HTML source of the target page.
  2. Parsing: The bot scans the <head> section for Open Graph protocol metadata.
  3. Fetching Asset: Upon finding og:image, the bot requests the image file from the specified URL.
  4. Caching: The platform downloads and stores the image on its own content delivery network (CDN) to optimize loading times for subsequent shares.
  5. Rendering: The platform constructs a visual preview card combining the image with other metadata, such as og:title and og:description.

Supplementary Image Tags

To optimize how platforms load and render thumbnail previews, the Open Graph standard includes complementary sub-properties:

  • og:image:width and og:image:height: Declares dimensions in pixels. Specifying these dimensions enables crawlers to reserve the layout and render the preview card immediately on the first share without having to download and measure the image file first.
  • og:image:type: Defines the MIME type of the image (e.g., image/jpeg, image/png, or image/webp).
  • og:image:alt: Provides descriptive alt text for visually impaired users and screen readers.

Example implementation with sub-properties:

<meta property="og:image" content="https://example.com/assets/preview.jpg" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:type" content="image/jpeg" />
<meta property="og:image:alt" content="Article summary card with title and graphic" />

Technical Standards and Best Practices

To ensure consistent display across different platforms, adhere to these technical specifications:

  • Dimensions and Aspect Ratio: The industry standard for high-resolution feed previews is 1200 x 630 pixels, representing a 1.91:1 aspect ratio. This size ensures the card renders cleanly across both desktop and mobile viewports without cropping.
  • File Formats: Standard image formats such as JPEG, PNG, and WebP are widely supported. SVG files are not universally supported by social media scrapers and should be avoided.
  • File Size: Keep image files under 8MB (ideally under 1MB) to ensure fast fetching times. Heavy files may cause crawlers to time out, resulting in a default placeholder or a text-only link preview.
  • Fallback Behavior: If an HTML document lacks an og:image tag, crawlers will attempt to guess an image by parsing the <img> tags within the document body, often resulting in unintended, low-quality, or oddly cropped thumbnails.
