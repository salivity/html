Using the HTML translate="no" Attribute

The translate="no" attribute is an official HTML5 global attribute designed to prevent automated translation tools and web browsers from translating specific elements on a webpage. By appending this attribute to an HTML tag, developers can preserve the original language of brand names, code snippets, trademarks, or technical terminology that must remain unchanged. This article explores the purpose, implementation, inheritance rules, and practical use cases of the translate="no" attribute in modern web development.

What Is the translate Attribute?

The translate attribute is a standardized W3C global attribute that accepts two values: yes and no. When set to no, it signals to automated translation engines—such as Google Translate, Microsoft Translator, and native browser translation features—that the text inside the targeted element must not be altered.

<p>Welcome to <span translate="no">OpenAI</span> services.</p>

In this example, while the rest of the sentence translates into the user's preferred language, the word "OpenAI" remains intact.

Why Use translate="no"?

Machine translation algorithms attempt to translate every word on a page based on context. However, translating certain types of content leads to broken functionality, confusion, or compromised branding. Key use cases include:

  • Brand Names and Trademarks: Prevent company names like "Apple" or "Target" from being literally translated into foreign equivalents.
  • Code and Technical Syntax: Maintain code blocks, API keys, file paths, and terminal commands in their original form.
  • Proper Nouns and Personal Names: Preserve the correct spelling of individual names, addresses, or identifiers.
  • Email Addresses and URLs: Prevent automated tools from altering hyperlinks or contact details, which would break their functionality.

Inheritance and Scope

The translate attribute is inherited by child elements. When an element is marked with translate="no", all nested HTML tags inside it will also be excluded from translation unless explicitly overridden.

<div translate="no">
  <p>This entire block will not be translated.</p>
  <p translate="yes">Except this specific sentence, which will be translated.</p>
</div>

This hierarchical behavior makes it efficient to protect large sections of content, such as a code documentation block, while allowing specific inline explanations to remain translatable.

translate="no" vs. class="notranslate"

Before the translate attribute became a standard in HTML5, third-party translation tools like Google Translate relied on proprietary class names, most notably class="notranslate".

While many translation engines still support class="notranslate" for backward compatibility, the translate="no" attribute is the vendor-neutral, standards-compliant approach. Using the standard attribute ensures that your site complies with W3C specifications and works reliably across different translation engines, screen readers, and automated processing tools.

Best Practices

  • Apply Granularly: Only apply translate="no" to elements that truly require it, rather than broad structural containers, so users can still read most of the page in their native language.
  • Use with the lang Attribute: Pair translation controls with the correct lang attribute at the document or element level to provide search engines and assistive technologies with accurate language context.
  • Combine with <pre> and <code> Tags: While some translation tools automatically ignore code tags, adding translate="no" to <pre> or <code> elements guarantees that code remains unchanged across all platforms.
