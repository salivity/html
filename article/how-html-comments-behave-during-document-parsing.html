How HTML Comments Behave During Document Parsing

This article explains how web browsers process the HTML comment syntax <!-- comment --> during document parsing. When a browser ingests an HTML stream, comments are not simply discarded; they undergo strict tokenization according to the HTML5 specification, are inserted into the Document Object Model (DOM) as distinct Comment nodes, and interact directly with the parser's state machine. Understanding this behavior clarifies how comments affect DOM construction, script access, and browser memory.

The Tokenization Phase

The HTML parser consists of two main stages: tokenization and tree construction. During tokenization, the parser reads the raw character stream character by character.

  1. Detection: When the parser encounters the sequence <!--, it shifts from the standard Data state through several intermediate transition states into the Comment state.
  2. Character Consumption: Inside the Comment state, characters are consumed as text data until the closing delimiter is identified.
  3. Closing Sequence: The parser looks for the sequence --> to transition back to the Data state. Modern HTML5 parsing rules also recognize --!> as a valid comment end sequence for historical compatibility reasons.
  4. Token Emission: Once closed, the tokenizer emits a single Comment token containing all text found between the delimiters.

Tree Construction and DOM Integration

Unlike comments in compiled languages, HTML comments do not vanish after the document is parsed. Instead, the tree constructor processes the emitted Comment token and inserts it into the DOM tree.

  • DOM Node Creation: The parser creates an instance of the Comment interface (which inherits from CharacterData and ultimately Node).
  • Node Placement: The comment node is appended to the current open element in the stack. Depending on where the comment appears in the source markup, it can become a child of the document root, the <head>, the <body>, or any other element. For example, comments placed before the <!DOCTYPE html> or after </html> become direct children of the document object.
  • NodeType: In JavaScript, these nodes have a nodeType property value of 8 (Node.COMMENT_NODE).

Parser Quirks and Special States

The parser’s handling of comment syntax includes specific rules to handle malformed markup and legacy edge cases:

  • Nested Hyphens: In older specifications (like HTML4/SGML), double hyphens (--) inside a comment were strictly forbidden because they acted as sub-delimiters. Under HTML5, modern parsers allow double hyphens inside the comment body, only terminating the comment when encountering --> or --!>.
  • Abrupt Closing: An empty comment <!----> or <---> is parsed cleanly into a comment node with an empty or single-dash string value.
  • Unclosed Comments: If an HTML document ends before a closing --> sequence is found, the parser transitions to an EOF (End of File) state, automatically closes the comment, and appends whatever content was captured up to that point as the comment node value.

Runtime Implications

  • Rendering: Comment nodes are completely ignored by the layout engine and CSS styling mechanisms; they generate no visual boxes in the render tree.
  • DOM Traversal: Because comments exist as nodes, properties like Node.childNodes will include comment nodes, potentially affecting index-based DOM traversal if scripts assume only element nodes are present. Element.children, by contrast, ignores comment nodes.
  • Memory and Execution: Comments consume memory in the DOM tree. While negligible in small quantities, massive quantities of comments or serialized data hidden inside comments will increase memory overhead and the time required for initial tree construction.
