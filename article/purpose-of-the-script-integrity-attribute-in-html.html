Purpose of the Script Integrity Attribute in HTML

This article explains the purpose and functionality of the integrity attribute in HTML, focusing on how Subresource Integrity (SRI) protects websites that load scripts from Content Delivery Networks (CDNs). You will learn the security risks associated with third-party hosting, the cryptographic mechanism behind hash validation, and how to properly implement the attribute alongside cross-origin settings to prevent unauthorized code execution.

The primary purpose of the integrity attribute is to enable Subresource Integrity (SRI), a security feature that allows modern web browsers to verify that externally hosted files—such as JavaScript libraries and CSS stylesheets—have not been unexpectedly altered or maliciously manipulated before execution.

When using a CDN to deliver libraries like jQuery, Bootstrap, or React, your application relies on a third-party server. If that CDN is compromised, misconfigured, or targeted in a supply chain attack (such as a Magecart attack), an attacker could inject malicious JavaScript into the hosted file. Without validation, any website referencing that script would automatically download and execute the infected code, exposing users to data theft, session hijacking, or defacement.

The integrity attribute mitigates this risk through cryptographic hashing. Here is how the process works:

  1. Hash Generation: The developer hashes the verified, legitimate version of the file using a secure algorithm—typically SHA-256, SHA-384, or SHA-512.
  2. HTML Definition: The resulting base64-encoded hash is included directly within the <script> tag using the integrity attribute (e.g., integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC").
  3. Browser Verification: When the browser downloads the script from the CDN, it independently computes the cryptographic hash of the received content.
  4. Validation Check: The browser compares its computed hash to the value defined in the integrity attribute:
    • Match: The file is unmodified and safe; the browser parses and executes the script.
    • Mismatch: The browser immediately rejects the file, blocks its execution, and logs a network security error in the developer console.

To successfully use the integrity attribute with resources hosted on a different domain, you must also include the crossorigin="anonymous" attribute on the element. This instructs the browser to request the resource using Cross-Origin Resource Sharing (CORS) without sending user credentials, which is required for the browser to read the response data and calculate the hash.

By implementing the integrity attribute, developers enforce an immutable guarantee that the code running in their users' browsers matches the exact code intended, eliminating the threat of untrusted modifications from third-party hosting providers.
