Using aria-expanded on Disclosure Buttons

The aria-expanded attribute is an essential accessibility feature used on interactive disclosure widgets, such as accordions, mobile navigation toggles, and dropdown menus. This article explains the technical purpose of aria-expanded, how assistive technologies interpret it, its valid values, and how to properly implement it alongside JavaScript to ensure inclusive digital experiences.

The Primary Purpose of aria-expanded

The primary purpose of the aria-expanded attribute is to convey the open or closed state of a collapsible container to assistive technologies, such as screen readers. When content is visually hidden or revealed upon user interaction, sighted users receive immediate visual confirmation. However, users relying on screen readers cannot detect these visual changes unless the interactive trigger programmatically communicates its state.

Applying aria-expanded directly to the trigger element (typically a <button>) informs the screen reader whether the associated content panel is currently open or closed.

How Screen Readers Announce the Attribute

When a user navigates to a button equipped with aria-expanded, the screen reader announces the accessible name of the button followed by its current state.

  • If aria-expanded="false" is set, the screen reader typically announces the control as "collapsed."
  • If aria-expanded="true" is set, the screen reader announces the control as "expanded."

This notification provides vital context, allowing users to understand that activating the control will toggle the visibility of additional content directly below or associated with that button.

Valid Values and Syntax

The aria-expanded attribute accepts a boolean state:

  • "false": Indicates that the controlled grouping or region is closed/hidden.
  • "true": Indicates that the controlled grouping or region is open/visible.
  • undefined (or omitted): The default state. If the attribute is absent, assistive technology assumes the element is not a disclosure control and does not support expansion.

Do not use empty strings or other values.

Implementation Pattern

To build an accessible disclosure widget, pair aria-expanded with the aria-controls attribute. The aria-controls attribute takes the id of the content panel that the button controls.

<!-- Closed State -->
<button 
  type="button" 
  aria-expanded="false" 
  aria-controls="faq-answer-1" 
  id="faq-question-1">
  What is your return policy?
</button>

<div id="faq-answer-1" hidden>
  <p>You can return items within 30 days of purchase.</p>
</div>

When the button is clicked, JavaScript must toggle two items:

  1. The aria-expanded value on the button (between "true" and "false").
  2. The visibility of the target content (for example, by toggling the hidden attribute or relevant CSS display properties).
const toggleButton = document.getElementById('faq-question-1');
const contentPanel = document.getElementById('faq-answer-1');

toggleButton.addEventListener('click', () => {
  const isExpanded = toggleButton.getAttribute('aria-expanded') === 'true';
  
  toggleButton.setAttribute('aria-expanded', !isExpanded);
  contentPanel.hidden = isExpanded;
});

Important Usage Considerations

  • Only use on interactive elements: Apply aria-expanded directly to focusable elements like native <button> tags. Do not place it on static elements like <div> or <span> unless they are properly retrofitted with a focusable tabindex and an appropriate ARIA role.
  • Avoid redundant usage with native HTML: Native HTML elements like <details> and <summary> handle disclosure behavior and accessibility states out of the box. Do not manually add aria-expanded to a <summary> element, as doing so can create conflicting announcements across different browser and screen reader combinations.
  • Must update dynamically: Setting aria-expanded="false" in the static HTML without updating it via JavaScript upon user interaction is an anti-pattern. An out-of-sync attribute misinforms users about the actual state of the interface.
