Difference Between innerHTML, outerHTML, and textContent

When manipulating the Document Object Model (DOM) with JavaScript, developers frequently need to update the contents of an element. This article provides a clear comparison of innerHTML, outerHTML, and textContent, explaining how each property behaves, how it handles HTML tags, whether it alters the element itself, and the security and performance implications of using each approach.

textContent

The textContent property represents the text content of a node and all of its descendants.

  • Behavior: When setting textContent, any text provided is inserted literally. If the string contains HTML tags (such as <b> or <span>), the browser does not parse them; instead, it renders them as plain, visible text.
  • Security & Performance: Because it does not invoke the browser's HTML parser, textContent is significantly faster than innerHTML and outerHTML. It is also inherently safe from Cross-Site Scripting (XSS) attacks because malicious scripts cannot be executed through plain text.

Example: Given <div id="target">Hello <em>World</em></div>:

const el = document.getElementById("target");
el.textContent = "<strong>New Text</strong>";

Result in DOM:

<div id="target">&lt;strong&gt;New Text&lt;/strong&gt;</div>

The browser displays: <strong>New Text</strong>

innerHTML

The innerHTML property gets or sets the HTML markup contained strictly inside the element.

  • Behavior: When setting innerHTML, the browser parses the provided string into DOM nodes and replaces all existing child nodes of the target element. The target element itself (its tags, classes, and attributes) remains unchanged.
  • Security & Performance: Parsing HTML strings requires extra computational overhead. Additionally, inserting untrusted user input via innerHTML creates a major XSS vulnerability, as it allows arbitrary code execution.

Example: Given <div id="target">Hello <em>World</em></div>:

const el = document.getElementById("target");
el.innerHTML = "<strong>New Text</strong>";

Result in DOM:

<div id="target"><strong>New Text</strong></div>

The browser displays: New Text

outerHTML

The outerHTML property gets or sets the serialization of the element itself, including its opening and closing tags and all child content.

  • Behavior: When reading outerHTML, it returns the element's own markup plus everything inside it. When writing to outerHTML, the target element is completely removed from the DOM and replaced by the newly parsed HTML string.
  • Important Caveat: Replacing outerHTML does not update the variable holding the original element. The variable still references the old, detached element in memory, not the newly inserted element.

Example: Given <div id="target">Hello <em>World</em></div>:

const el = document.getElementById("target");
el.outerHTML = "<p class='new-elem'>New Paragraph</p>";

Result in DOM:

<p class="new-elem">New Paragraph</p>

The original <div> with id="target" is completely replaced.

Summary of Key Differences

Property Parses HTML Tags? Affects Target Element Wrapper? Risk of XSS? Best Used For
textContent No No (updates children only) None Safe text display, reading raw text, high performance
innerHTML Yes No (updates children only) High (with untrusted data) Inserting structured HTML inside an existing container
outerHTML Yes Yes (replaces the element entirely) High (with untrusted data) Replacing an element and its tag completely
