How exportparts Propagates Nested Shadow Parts

The exportparts attribute allows modular Web Components to expose internally encapsulated CSS shadow parts across nested Shadow DOM boundaries to ancestor scopes. While the standard ::part() pseudo-element can only access elements one shadow root deep, exportparts acts as an explicit forwarding mechanism. By mapping or aliasing inner part attributes upward through container components, developers can maintain encapsulation boundaries while still granting top-level documents style control over deeply nested UI primitives.

The Single-Boundary Limitation of Shadow Parts

When creating a Web Component with Shadow DOM, you can designate specific internal elements for external styling using the part attribute:

<!-- Inside <custom-button> shadow DOM -->
<button part="native-button">Click Me</button>

An outer document containing <custom-button> can style this element directly:

custom-button::part(native-button) {
  background-color: royalblue;
}

However, if <custom-button> is encapsulated inside a parent component, such as <nav-bar>, the outer document can no longer reach native-button. Shadow encapsulation intentionally prevents the ::part() selector from piercing through multiple nested shadow roots. By default, <nav-bar> hides the internal structure of <custom-button>.

The Role of the exportparts Attribute

The exportparts attribute solves this containment problem. Placed on a custom element within a shadow tree, it explicitly exposes that element's internal parts to the containing host's own shadow boundary.

The attribute takes a comma-separated list of part mappings and supports two formats:

  1. Direct Forwarding: Exposing the inner part under its existing name.
  2. Aliased Forwarding: Renaming the inner part using a source: alias syntax to avoid namespace collisions and create clearer component APIs.

How Propagation Works in Practice

Consider a deeply nested structure with three levels: a root document, a parent <user-card> component, and a nested <user-avatar> component.

1. The Leaf Component (<user-avatar>)

Inside <user-avatar>'s shadow root, an image is tagged with a standard part attribute:

<!-- <user-avatar> shadow root -->
<img part="avatar-image" src="profile.jpg" alt="User Avatar" />

2. The Intermediate Component (<user-card>)

Inside <user-card>'s shadow root, <user-avatar> is instantiated. To propagate avatar-image outward so it is visible to <user-card>'s consumer, use exportparts:

<!-- <user-card> shadow root -->
<div class="card-container">
  <user-avatar exportparts="avatar-image: profile-pic"></user-avatar>
</div>

In this step, the internal avatar-image part is exposed to the outer scope under the alias profile-pic.

3. The Outer Document Styling

The top-level document can now target the element through <user-card> using the exported alias:

/* Document-level CSS */
user-card::part(profile-pic) {
  border-radius: 50%;
  border: 2px solid #333;
}

The browser traces profile-pic from the <user-card> shadow host down to the <user-avatar> shadow boundary, maps it back to avatar-image, and applies the styles directly to the target <img> element.

Multi-Level Chaining

Propagation is not limited to a single intermediate component. exportparts can be chained across any number of nested shadow layers:

  1. Component C (Leaf): Defines <span part="label">.
  2. Component B (Intermediate): Embeds Component C and declares <component-c exportparts="label: inner-label">.
  3. Component A (Outer Wrapper): Embeds Component B and declares <component-b exportparts="inner-label: public-label">.
  4. Global CSS: Styles the target via component-a::part(public-label).

At each boundary, the hosting component must explicitly declare what it forwards. If any component in the chain omits the part from its exportparts list, the chain breaks, and styling from higher scopes is blocked.

Key Rules for Implementation

  • Selective Exposure: Unlisted parts remain fully encapsulated; only parts listed in exportparts can penetrate outward.
  • Namespace Isolation: Aliasing (inner: outer) allows wrapper components to prevent naming collisions when combining multiple child components that use generic part names like button, icon, or text.
  • Dynamic Updates: Modifying the exportparts attribute via JavaScript dynamically updates which styles apply without requiring component re-renders.
